# TRIBE — Telegram Mini App

Лёгкая low-poly 3D-стратегия о племени позднего средневековья: посёлок стоит с первой секунды,
а игра — про дружину, карту и бой. Полное видение — в [docs/concept.md](docs/concept.md).
Заход 3–5 минут: поставить людей, сковать снаряжение, нанять отряд, отправить разведку или
поход, принять решение в событии, улучшить здание.

## Стек

- Vite + TypeScript + React 18 (2D-интерфейс поверх сцены)
- three.js (low-poly диорама; камерой правит сама сцена от общего разбора жеста)
- zustand (единый стор), vitest (тесты симуляции)
- Telegram WebApp API через `window.Telegram.WebApp` (скрипт в index.html); сохранение — localStorage плюс наш сервер

## Команды

```bash

npm run build      # РЕЛИЗ: значки + типы + бандл + приёмка dist → dist/

npm test           # vitest

npm run lair:report  # логова: рост и его потолок, срок пепелища, добыча, что с картой за часы
npm run sack:report  # тайник и добыча: таблица вместимости, час грабежа, потолок мести
npm run order:report # невольники и порядок: выработка, надзор, цена, война против хозяйства, срок до мятежа
npm run scene:report # ожидание: запуск, генерация мира, вход на карту, память
npm run revive:report # возвращается ли диорама сама: потеря контекста, фон, чужой размер
npm run tap:report # след пальца по постройкам: попадает ли тап туда, куда целились
npm run prologue:report # предыстория: числа круга, кадр, память, проходится ли она пальцем — и финал целиком

npm run splash:build # арты перехода из assets-src/splash в src/ui/art (WebP)
```

## Работа с ветками

Обязательные правила проекта, а не пожелания.

1. **Коммит — часть задачи, а не её хвост.** Работа, не попавшая в коммит, считается
   несделанной. Коммить и пушить после каждого законченного шага, а не в конце задачи.
   В финальном отчёте обязательно печатать три вещи: имя ветки, вывод `git status` и
   вывод `git log --oneline -3`. Без них отчёт неполон.
2. **Ветка живёт часы, а не дни.** Закончил задачу — сразу предложи слить её в `master`
   и удалить ветку. Не копи несколько незакрытых веток: чем дольше они расходятся, тем
   дороже слияние.
3. **Начинай от свежего `master`.** Перед началом работы подтяни `master` и отведись от
   него. Никогда не начинай от устаревшего состояния.
4. **Ядро — одна сессия за раз, без исключений.** Список ядра лежит ниже, в разделе
   «Зоны: ядро и периферия». Он есть затем, чтобы «ядро это или нет» не решалось
   интуицией: «стараться не запускать параллельно» через неделю забудут все. Два
   представления о формате сохранения сойдутся в одном файле, git не покажет конфликта,
   и не заметит этого никто — до первой потерянной партии.
5. **Тематические заметки — в свой файл.** Длинные разделы по темам — карта, фигуры,
   бой, здания — заводи как `docs/<тема>.md` и оставляй в `CLAUDE.md` одну строку-ссылку:
   их дописывают разные задачи, и в общем файле они конфликтуют при каждом слиянии.
   Правила захода в работу — этот раздел — остаются в `CLAUDE.md`: их пишут редко,
   конфликтовать им не с чем, а прочитаны они должны быть раньше, чем начнётся правка.
6. **Что проверять после слияния.** git не показывает конфликты там, где обе стороны
   меняли разные строки одного смысла. Приёмка — не «git не ругался», а чистый
   `tsc --noEmit`, зелёные тесты и проходимое обучение. Отдельно ищи: удалённые
   компоненты, которые кто-то ещё импортирует; идентификаторы, переименованные с одной
   стороны и оставшиеся с другой; панели интерфейса, которые считают то же, что и
   симуляция, но своим кодом.
7. **Документы, выведенные из кода, после слияния пересобираются, а не сводятся.**
   `docs/BUILDINGS.md` и подобные справочники описывают код, а не мнение. При слиянии их
   текст сводится как текст и расходится с кодом именно там, где встретились две ветки.
   После каждого слияния, затронувшего данные или формулы, справочник перечитывается из
   кода заново, а не мержится построчно.
8. **Одна рабочая копия, несколько сессий — ветки не переключаются.** Пока в папке
   работает больше одной сессии, `checkout` и `checkout -b` запрещены: HEAD общий, и
   переключение уводит на новую ветку чужой следующий коммит. Это сильнее правила 3 —
   отведение от свежего `master` ждёт, пока копия не освободится. Каждая сессия коммитит
   в текущую ветку и **только свои файлы явными путями**: ни `git add -A`, ни `git add .`,
   ни `git commit -a`. Перед коммитом — `git status`, и в индексе не должно быть ничего
   чужого.
9. **Кто пушит из общей копии, пушит всё.** Коммит свой, а ветка общая: `push` уносит и
   чужие коммиты, легшие вперемешку, и разделить их нечем. Поэтому приёмка перед пушем —
   по **всему дереву**, а не по своей задаче: `npm test`, `npm run typecheck`,
   `npm run build` — и **все отчёты целиком**, а не только тот, который правил:

   ```bash
   for r in battle pop world settle raid siege notify lair sack order log figure tap prologue scene revive map; do npm run $r:report || break; done
   ```

   Стоит это около тринадцати с половиной минут, и четыре с половиной из них — `tap:report`: он гоняет
   настоящий Chrome настоящим касанием и настоящими часами, быстрее не бывает. Ещё столько же —
   `prologue:report` (перезагрузки на выбранные минуты суток, драка со стаей, ремесло, род и
   финал настоящим касанием), минута — `map:report` и без малого минута — `siege:report`.
   `map:report` и `scene:report` требуют собранного `dist` — гони их после `npm run build`,
   иначе они мерят вчерашнюю сборку.
   `battle:sweep` в список не входит — это не отчёт, а перебор по `GRID=`. `map:shots`
   тоже не входит и по той же причине: он ничего не меряет и ничем не падает — он
   снимает картинки, которые смотрят глазами.

   **Граница у отчётов есть, и проводит её команда, а не рассуждение.** Правило обязано
   быть дешёвым там, где оно ничего не ловит: иначе его начнут пропускать там, где ловит,
   а обойдённое правило хуже отсутствующего.

   ```bash
   git diff --name-only origin/master..HEAD | grep -qvE '^(docs/|CLAUDE\.md|README)' \
     && echo 'есть код — гнать все семнадцать отчётов' || echo 'только документы — отчёты не нужны'
   ```

   - в пуше изменился **хоть один файл не из списка документов** (`src/`, `netlify/`,
     `scripts/`, настройки сборки, `public/`, `assets-src/` — что угодно) — приёмка
     целиком, все семнадцать отчётов;
   - изменились **только** `docs/`, `CLAUDE.md`, `README.md` — отчёты не гоняются. Тесты,
     типы и сборка гоняются **по-прежнему**: втроём они стоят около минуты (22 + 12 + 23
     секунды), и это тот пол, ниже которого приёмки не бывает.

   Смотреть надо **весь диапазон пуша** (`origin/master..HEAD`), а не свой коммит: `push`
   уносит и чужие коммиты, легшие вперемешку, — и если среди них есть код, отчёты нужны,
   даже когда своей рукой правил один документ. Команда это делает сама.

   Список документов — **белый**, и это не мелочь: файл, о котором никто не подумал,
   попадает в «код» и тянет полную приёмку. Ошибиться в эту сторону стоит семь минут, в
   обратную — стоит регрессии в `master`.

   Других исключений нет и заводить их нельзя. «Мелкая правка» и «я уверен, что не задел» —
   не критерий, а ровно тот случай, ради которого правило и написано: у обоих на месте
   критерия стоит самооценка, а решает `git diff --name-only`.

   **Почему отчёты, а не только тесты.** Отчёты гоняют настоящий мир целиком и ловят то,
   на что тесты слишком аккуратны. Случай, из которого правило и выросло: слепок деревни
   перестал возить поле `resources` и стал возить `stock`, а `stepLetters` читал
   `save.profile.stock` без `?? {}`. Слепок при этом **лежит в сохранении мира**
   (`WorldSave.profile`), и из партии, начатой до правки, он приезжает без нового поля —
   `Object.values(undefined)` роняет весь пульс мира. Тысяча тридцать три теста этого не
   увидели, и не по недосмотру: и в игре, и в тестах `sync` кладёт свежий слепок раньше
   `advance`, так что до чтения старый просто не доживает. Тест подаёт то, что задумано;
   отчёт подаёт то, что бывает, — и упал на первом же пульсе.

   Отсюда следствие: **отчёт, переставший запускаться, — это находка, а не помеха.** Он
   споткнулся раньше игрока. Чинить надо причину, а не обходить отчёт; а если отчёт правда
   устарел — переписать его тем же коммитом, а не отложить.
10. **Непрочитанный код в коммит не идёт — чей бы он ни был.** Ни одна строка не уезжает
   в репозиторий, пока её не прочитали глазами: своя, подагента, чужой сессии, выведенная
   скриптом. Следствий четыре, и все обязательные.
   - **Перед коммитом смотрится, что именно уходит** — `git diff --staged` целиком, а не
     только «тесты зелёные». Зелёные тесты говорят, что код работает; они ничего не
     говорят о том, что он тут делает и не вторая ли он копия уже написанного.
   - **Файлы вне своей задачи в коммит не берутся никогда**, даже если они изменились
     сами: общие настройки, конфигурация окружения, чужие `launch.json` и `settings.json`.
     Изменился — верни его или оставь в рабочем дереве, но не в индексе; коммитить только
     своими явными путями (правило 8).
   - **Подагент, которого просили проектировать, писать в репозиторий не имеет права.**
     Написал — написанное разбирается руками, файл за файлом, и берётся по частям, а не
     принимается целиком: замысел и его исполнение проверяются по-разному, и «раз уж
     написано» — не довод.
   - **Взял чужое — отвечаешь за него как за своё.** «Это написал подагент» не объяснение
     ни в отчёте, ни в разборе.

   **Откуда правило.** Подагенты, которых просили только спроектировать детальный режим
   карты мира, записали в дерево 1192 строки кода и заодно переписали общий
   `.claude/launch.json` — файл, который делят обе рабочие копии. Поймалось это чтением
   диффа перед коммитом, и то по случайности: два файла из написанного оказались нужны,
   остальное было вторыми копиями уже существующих модулей. Уйди коммит на одних зелёных
   тестах — в `master` уехали бы дубли и чужая настройка порта, и разошлись бы они молча,
   как расходится всё, чего git не показывает конфликтом (правило 6). Цена чтения —
   минуты; цена непрочитанного — вторая правда об одном и том же, найденная через месяц
   и неизвестно кем.
11. **Тест-свойство падает на мутации по той причине, ради которой написан, — и его точки
   лежат внутри области, где правило вообще действует.** Точка за границей области даёт
   зелёный даром: правило там не спрашивается, и тест проходит при любом коде. Мутация
   поэтому проверяется не счётом «упал / не упал», а сообщением: упал тот тест и на том
   утверждении, которое держит мутированное правило, а не соседний и не на побочном
   эффекте.

   Повадка узнаётся по трём случаям подряд, и все три выглядели зелёными тестами:
   - тест «у частокола дружины нет» проверял побочный эффект, а не само правило обороны;
   - обвязка теста сдвигала время и тем самым досрочно завершала сбор дружины — проверялось
     не то состояние, про которое тест назван;
   - кривая «шанс вылазки не растёт по мере того, как строятся рогатки» доходила до 32-й
     минуты при окне голода 31.6: на последней точке лагеря уже не было, «ноль побед»
     получался без лагеря, и мутация «укрепление не растёт» проходила зелёной.

   Отсюда два действия, обязательные для нового теста-свойства: назвать границу области
   (окно, срок, фазу) и проверить каждую точку на то, что она внутри, — утверждением в
   самом тесте, а не расчётом в голове; и прогнать мутацию, читая, **какое** утверждение
   упало.

## Зоны: ядро и периферия

Мы работаем несколькими сессиями в **одной рабочей копии** (поэтому `checkout` запрещён —
HEAD один на всех, см. правило 8). Значит развести задачи по веткам нельзя, и разводить их
приходится по файлам. Зон две.

**Признак, по которому файл попадает в ядро, — цена молчаливого расхождения.** Вопрос
такой: если две сессии правят этот файл врозь и обе правы по отдельности, кто заметит
первым? Ответ «игрок, потерявший партию» или «никто» — это ядро. Ответ «первый же кадр на
экране» — периферия.

Признак измерен, а не взят на глаз, и мерка «много кто импортирует» **не подошла**:
у `game/save.ts` три импортёра, у `netlify/lib/initdata.ts` — один, а дороже них в проекте
нет ничего; у `render/palette.ts` их семнадцать, и расхождение в ней видно на первом кадре.
Популярность файла и цена ошибки в нём — разные вещи.

### Ядро — одна сессия за раз

Формат и версия того, что переживает сессию (расхождение = потерянная партия):

- `src/game/state.ts`, `src/game/save.ts`, `src/game/types.ts` — состояние, `SAVE_VERSION`,
  сериализация и миграции;
- `src/profile/types.ts` — профиль игрока лежит в сохранении племени целиком: имя, лицо и
  имя города (`ProfileState.city`) — его поля;
- `src/world/local/state.ts` — `WORLD_SAVE_VERSION` и миграции мира;
- `src/world/siege.ts` — окно осады лежит в сохранении мира целиком, и отметка прохода
  через рогатки (`gateAt`) — его поле;
- `netlify/lib/contract.ts` — договор между игрой и сервером, один файл на две стороны.

Личность, время и встреча двух копий (расхождение = затёртая чужая партия):

- `src/net/` целиком — `sync.ts`, `session.ts`, `snapshot.ts`, `api.ts`, `clock.ts`,
  `roster.ts`;
- `netlify/lib/initdata.ts`, `netlify/lib/http.ts`, `netlify/lib/roster.ts`,
  `netlify/functions/*.mts`;
- `netlify/lib/notify.ts`, `netlify/lib/deliver.ts` — правила исходящих и проход доставки:
  расхождение здесь — сообщение, ушедшее дважды, чужому времени или не ушедшее вовсе;
- `src/world/notice.ts`, `src/world/local/NotifyingWorld.ts` — черновики уведомлений и разрывы:
  расхождение здесь молча шлёт игроку неправду о его осаде (docs/NOTIFY.md);
- `src/telegram/cloud-rescue.ts` — последняя дверь к чужим данным.

Общий словарь симуляции (расхождение = две правды об одном числе):

- `src/game/constants.ts`, `src/game/derived.ts`, `src/game/store.ts`;
- `src/game/data/` целиком;
- `src/world/faith.ts` — вера клетки. Земля одна на всех, значит и вера её одна: разойдись
  разметка у двоих — у соседей под одними координатами оказались бы разные веры, и
  заметил бы это только тот, кто сравнил свою карту с чужой;
- `src/game/sim/tick.ts` (единственный шаг), `src/game/sim/random.ts` (сид).

Детерминированный расчёт, который обязан повторяться (расхождение = мир или бой перестают
воспроизводиться, и это увидят только на сервере):

- `src/battle/` целиком — ядро боя и его конфиг;
- `src/game/battle/kinds.ts`, `src/game/battle/formation.ts` — перевод племени в бой;
- `src/world/api.ts`, `src/world/types.ts`, `src/world/geography.ts`, `src/world/geo.ts`,
  `src/world/gen.ts`, `src/world/data/tuning.ts`;
- `src/world/land.ts` и `src/world/settle.ts` — земля и расселение, **одни на игру и на
  серверную функцию**. Расхождение здесь не сбой, а два разных ответа на вопрос «где может
  стоять замок» у клиента и у сервера: игрок увидел бы свой замок не там, где его видят
  соседи. Отсюда и запрет на `@/`-импорты в них, и тест по исходникам (`land.test.ts`);
- `src/world/atlas/` целиком — земля, одна на всех. Расхождение здесь означает не сбой, а
  **другой мир под теми же координатами**: замок игрока переезжает в море, и заметит это
  только он. `data.ts` руками не правят вовсе — его пересобирает `npm run world:build`.

Один палец — один судья: `src/gestures.ts`. Разбор жеста уже был написан дважды и копии
успели разойтись — второй раз этого допускать нельзя.

`src/cheats.ts` в ядро не входит, и это стоит сказать вслух: коды — инструмент проверки, у них нет
ни формата, ни версии, а расхождение в них видно первым же нажатием. Ядро тут другое — **поле
метки** (`GameState.cheated`), и оно лежит там, где ему и положено: в `game/types.ts`.

Плюс сам `CLAUDE.md`.

**Список — начало, а не забор.** Правило сильнее списка: **любая правка, добавляющая поле в
сохранение или трогающая его версию, — ядро, в каком бы файле она ни лежала.** Файл, который
пришлось добавить сюда по этому правилу, дописывается в список тем же коммитом.

### Периферия — параллелить можно свободно

Арт и значки (`assets-src/`, `src/ui/icons/`, `src/ui/art/`), модели зданий и вся
`src/render/` кроме перечисленного, фигуры и раскадровка ролика, отдельные панели интерфейса,
музыка, документы в `docs/`, отчёты в `scripts/`.

`src/prologue/` — тоже периферия, и это стоит сказать вслух, потому что по букве правила «поле
в сохранении — это ядро» он на ядро похож: у него есть и формат, и версия. Мерка, однако, не в
том, есть ли версия, а в цене молчаливого расхождения — и здесь она равна трём минутам чужой
пробы, а не партии. Сохранение у него своё (`tribe.prologue.v1`), с сохранением племени и с
сервером оно не встречается нигде, и `SAVE_VERSION` от него не зависит. Расхождение здесь видно глазом на первом
кадре или падает громким тестом — оно дорого стоит в минутах и ничего не стоит в партиях.

### Два механических правила

1. **Сессия, начинающая работу в ядре, говорит об этом первой строкой отчёта.** Следующая
   смотрит `git log` перед стартом. Без этого «одна сессия за раз» проверить нечем.
2. **Вторую сессию не запускают, пока первая не сказала «запушено».** Причина не в git:
   незакоммиченные правки в общей рабочей копии видны всем сессиям **сразу**, и вторая
   прочитает полуготовый код как готовый — а потом достроит на нём своё.

  `dist`, её же командой собирает Netlify, ею же собирается то, что переносят руками.

  1. **Половинчатая сборка не должна быть возможна по невнимательности.** Прежняя строка на

### Стенд в проде

Стенд открывается по тому же адресу — он собирается в продакшен нарочно (см. «Графика»).
Замер частоты кадров на телефоне теперь делается без туннеля:

```
https://celebrated-yeot-73e410.netlify.app/?showcase=village&levels=10&perf=8
```

Экран не гасить и вкладку не сворачивать: в фоне `requestAnimationFrame` стоит, и замер выйдет
нулевым. Прогрев полторы секунды, потом камера крутится восемь секунд. Итог остаётся в подписи,
а тап по ней кладёт отчёт целиком (устройство, dpr, вызовы, треугольники) в буфер обмена —
класть его в `snaps/perf.jsonl` некому, `/__perf` есть только у dev-сервера. Снимки (`?snap=имя`)
в проде тоже не сохраняются: за ними — на `npm run dev`.

**Абзац выше — про настоящий телефон, следующий — про наш инструмент, и выводы у них разные.**
«Экран не гасить» сказано игроку и нам с телефоном в руках: там страница действительно уходит в
фон, кадры действительно останавливаются, и лечится это тем, что экран не гасят. Ниже речь о
другом — о **панели предпросмотра инструмента разработки** (браузер внутри рабочей среды сессии,
тот, в котором игру открываем мы сами). Ни к вкладке Chrome у игрока, ни к вебвью Telegram, ни к
чему-либо в самой игре это не относится: в игру панель не входит, у игрока её нет, и судить по
ней о поведении настоящего браузера нельзя — как и наоборот.

**Видимость панели предпросмотра не равна кадрам, и «кадров нет» в ней ничего не доказывает.**
`document.hidden === false` и `visibilityState === 'visible'` **не** означают, что кадры идут:
панель отвечает «видима», а `requestAnimationFrame` при этом не срабатывает ни разу за полсекунды —
кадры идут только те доли секунды, пока панель действительно рисуют. Проверено замером. Поэтому
«кадров нет» никогда не доказывает, что сцена сломана, а проверка видимости не доказывает, что
измерение состоялось. Мерить кадры можно только в окне, где панель заведомо рисуется, — например
сбросив счётчики, сняв снимок и прочитав их сразу после. Написано это потому, что на прежней
формулировке мы уже трижды принимали здоровую игру за сломанную.

## Личность игрока и хранение прогресса

Первый шаг к серверу: игрок узнаётся по Telegram, партия складывается на сервер, время берётся
серверное. Разбор целиком, с шагами выкладки и числами, — [docs/sync.md](docs/sync.md).
Здесь только то, что нельзя нарушить:

- **Сервер хранит и раздаёт, а не судит.** Он не разбирает сохранение, не считает ресурсы, не
  ловит читерство и ничего не начисляет. Алмазов у него нет ни в каком виде — ни поля, ни имени,
  и это тест по исходникам (`netlify/lib/server.test.ts`). Правило «клиент не умеет начислять
  себе алмазы» не ослабляется тем, что рядом появился сервер, который умеет: появится настоящая
  оплата — начисление будет писаться заново и целиком, вместе с проверкой платежа.
- **Личность — только из подписи.** `initData` проверяется HMAC по токену бота
  (`netlify/lib/initdata.ts`), ключ хранилища собирается из проверенного числа, и чужого ключа
  не из чего собрать. **Идентификатор из тела запроса не принимается никогда, ни в каком виде,
  ни «для отладки».** Токен бота живёт только в переменных окружения Netlify: ни в репозитории,
  ни в логах — журналов у функций нет вовсе.
- **Игра работает, когда сервера нет.** Локальное сохранение — рабочая копия, сервер — место
  синхронизации, а не условие запуска. Синхронизация начинается после того, как игра уже пошла,
  и ничего не ждёт; у каждого запроса свой срок, неудача возвращается значением, а не исключением.
  Отсутствие функций на хостинге отличается от ошибки по типу содержимого: `/api/*` без функций
  отдаёт страницу игры **с кодом 200**, и `res.ok` сказал бы «всё хорошо».
- **Сервер — единственная правда, местная копия — его продолжение.** Правило встречи двух копий —
  одна чистая функция `decide` (`src/net/sync.ts`), четыре ветки: пусто на сервере (кладём свою),
  нет своей (берём серверную), серверная наша же (`continue` — местная копия её продолжает и
  уезжает наверх), серверная чужая (`yield` — берём серверную). Разница между двумя последними и
  есть всё правило: **игра без сети расхождением не считается** — копия выросла из той же записи и
  просто ушла дальше, и вечер офлайна уезжает на сервер сам и молча. Расхождение — это когда обе
  копии выросли из одной базы врозь (играли с двух устройств), и решается оно в пользу серверной,
  тоже молча. **Окна выбора нет ни в каком виде, и заводить его заново нельзя:** вопрос при входе —
  плохая первая минута, а сравнивать две партии по описи игрок всё равно не умеет.
  «Не знаю, чему наследую» — это **не** «наследую этому»: пустая отметка читается как расхождение,
  иначе устройство, ни разу не синхронизировавшееся, затирало бы чужую партию своей.
- **Отвергнутая копия не пропадает, и на этом всё держится.** Она ложится рядом на устройство
  (`spare`), и вернуть её можно в «Заданиях» → «Служебное». Возврат оставляет отметку наследования
  на месте — иначе правило «сервер главнее» тут же отправило бы возвращённую партию обратно в
  отвергнутые, и кнопка не делала бы ничего. Убрать возврат — значит превратить «молча» в
  «навсегда»; проверяется весь путь прогоном в `sync.test.ts`, а не на слово.
- **Две вкладки договариваются о ведении партии** (`src/net/session.ts`). Вторая не перехватывает
  ведение сама: она показывает окно и до решения игрока не пишет ничего — ни на диск, ни на сервер,
  ни на выходе. Настоящей блокировки тут нет и быть не может, и городить её не надо.
- **Время спрашивают в одну дверь** — `src/net/clock.ts`. `Date.now()` и `new Date()` без доводов
  запрещены в `src/game`, `src/world`, `src/ui`, `src/profile` и `src/battle`; держит это
  `clock.test.ts` чтением исходников. Серверное «сейчас» приезжает с любым ответом, включая отказ,
  и становится поправкой, а не разовым значением. Сторожем это никого не делает: игрок с
  переведёнными часами и без сети получит своё устройство — больше взять неоткуда.
- **Мест хранения два, и роли у них разные.** Устройство — **рабочая копия**: игра запускается
  с неё и играется целиком без сети. Сервер — **правда**: он переживает телефон, чистку данных
  браузера и переустановку клиента. Третьего места нет и заводить его нельзя: пока рядом стояло
  облако Telegram, это была не тройная надёжность, а третий шанс разойтись — у каждого места
  своя отметка времени, свои условия записи и свои отказы.
- **Облако Telegram (CloudStorage) убрано как хранилище: игра туда больше не пишет.** Осталось
  одно чтение и то **разовым подъёмом** — `src/telegram/cloud-rescue.ts`: у кого-то партия может
  лежать только там (играли до появления сервера, потом потеряли локальную копию), и сделать её
  недостижимой молча нельзя. Облако спрашивают ровно тогда, когда своей копии на устройстве нет
  вовсе; поднятое сразу ложится на диск; игрок узнаёт об этом строкой в летописи; если серверная
  партия тоже есть — живых копий две, и разбирает их обычное правило расхождения. **Записи быть не
  может структурно:** `setItem` убран из типа облака в `telegram/webapp.ts`, и `cloudSet` не
  возвращается правкой одной строки — это ошибка компиляции. Держит это `telegram/cloud.test.ts`
  **с двух сторон**: со стороны кода от облака не осталось ни вызова, ни спящей ветки, кроме
  одной двери; со стороны двери — она не мёртвый код, её зовут ровно из `loadGame`. Одной
  половины мало: замок, который никто не открывает, от замка, который никто не проверял, по
  исходнику не отличить.
- **Писателей сохранения на диск ровно один — `saveGame` в `game/save.ts`, и он синхронный.**
  Их было два (быстрый на выход из вкладки и медленный с облаком), и второй потерял смысл вместе
  с облаком: два способа записать одно и то же расходятся ровно в тот день, когда формат меняют.
  Заодно «попытка ежедневки ложится на диск сразу» стало правдой без оговорок.
- **Запись разделилась, и разделилась она с замков.** Мир и племя по-прежнему едут одной
  непрозрачной строкой — это личное: туман, снимки соседей, агенты, приказы, походы, письма.
  Общим стало то, что держит вторая запись, реестр замков (`/api/castles`): где стоит замок,
  как зовут вождя, мощь, население и когда он был в игре. Из четырёх вещей, которые должны
  были стать общими — чужие замки, чужие армии, осады, дипломатия, — общей стала первая.
  Границу переносить нельзя: своё знание о чужом замке остаётся личным, общим остаётся сам
  факт замка и то, что владелец о себе написал (docs/sync.md, раздел 4).
- **Сервер читает то, что хранит, ровно в двух местах: реестр замков и исходящие
  уведомления,** и третьего быть не должно. Правило расширено вслух решением владельца
  (docs/NOTIFY.md, раздел 3) и держится тестом «сервер разбирает ровно две записи»
  (`netlify/lib/server.test.ts`): третий читатель хранимого упирается в него. Судьёй сервер
  от этого не стал. В реестре имя, мощь и население он принимает как есть и делает одну вещь,
  которую клиенту доверить нельзя, — **выбирает клетку**: клиент, выбирающий себе место,
  выбирает себе соседей. Поля координат в теле запроса нет вовсе. В исходящих он читает
  поручение, а не партию — «в такую-то минуту скажи вот это, если игрока нет», — и о мире не
  знает ничего.
- **Уведомления — [docs/NOTIFY.md](docs/NOTIFY.md).** Сделана пачка 1: черновики из сохранения
  мира (`world/notice.ts`), приём `/api/notify`, индекс по минутам и проход доставки по
  расписанию (`functions/deliver.mts`) — первая фоновая работа сервера. **Отправки нет, и
  заперта она двумя замками:** на клиенте `NOTIFY_ON = false` (`net/notify.ts`; ни запроса, и
  сборщик выбрасывает весь код — тест по исходникам), на сервере адаптеров нет ни одного (тест
  «доставка ничего не отправляет»). Видов три, поимённо: `raid`, `siege-works`, `siege-bread` —
  вида «вернись в игру» быть не может, и это тест. **Полнота держится на инварианте** «набег на
  деревню рождается только на пульсе» (`world/notice.test.ts`): мир, начавший жить без игрока,
  сделает уведомления неполными молча.
- **Правило расселения одно на обе стороны** — `src/world/settle.ts`, и его же зовёт игра без
  сервера. Земля под него уехала в `src/world/land.ts`: без `@/`, без DOM, без типов мира, —
  иначе серверный проект её не соберёт. Держит это тест по исходникам (`land.test.ts`), и
  нарушение видно только на второй ступени `npm run typecheck`.
- **Имя своего города называет игрок** (профиль, `ProfileState.city`), и очищает его одна дверь
  на обе стороны — `contract.cityName`: до сорока знаков, без разметки, без управляющих и
  невидимых знаков; пустое — не имя, тогда «Безымянный город». Имя едет слепком в мир (карта,
  отчёты, письма) и строкой в реестр замков — его увидят соседи. Сырым оно не читается нигде —
  тест по исходникам (`ui/cityname.test.ts`). Ругательства не фильтруются: решать отдельно.
  Версия сохранения племени не выросла — поле необязательное (docs/sync.md, раздел 4).
- **Чужие замки идут через ту же разведку, что и всё остальное.** Нет разведанной клетки — нет
  и точки; есть клетка, но живьём никто не смотрел — нет ни имени, ни мощи; смотрели — снимок
  с датой, стареющий обычными ступенями. Мощь при этом идёт по правилу **чужого отряда**, а не
  чужого двора: её даёт живой обзор, потому что разведать замок нечем.
- **Между игроками не происходит ничего,** и держится это устройством, а не проверками: замки
  живых игроков лежат отдельным списком и в `gen.settlements` не попадают. По сгенерированным
  поселениям ходит вся фоновая жизнь мира — набеги соседей, войны дворов, письма, приказы
  агентов, — и приписать это живому человеку нельзя ни в каком виде.
- **Формат сохранения племени не менялся** (`SAVE_VERSION` прежний). Сохранение мира —
  менялось: `WORLD_SAVE_VERSION` — 8, нижняя граница равна ей. Дом ставит теперь реестр, а у
  старого сохранения он найден поиском по сиду, и весь разведанный вокруг него туман относится
  к чужой округе.
- **Чего в этом шаге нет и что не надо доделывать по дороге:** авторитетный сервер, ловля
  читерства, платежи и Telegram Stars, общее состояние мира (чужие армии, осады, дипломатия,
  письма между игроками), серверная летопись.

## Экран загрузки

Экран загрузки **живёт в `index.html` целиком** — разметка, стили, картинка и код, без
единого внешнего запроса. Собранный тем же JavaScript, что и игра, он появился бы только
после загрузки этого JavaScript, то есть ровно после ожидания, которое должен закрыть.
Переносить его в `src/` нельзя ни целиком, ни частями, и второй копии его правил быть не
должно: тест читает `index.html` и выполняет тот самый код. Единственная дверь из игры —
`src/boot/stage.ts`, и через неё идут только имена стадий. Подробно, с числами и
порогами, — [docs/loading.md](docs/loading.md).

**После загрузки игра не входит сама — между ней и экраном загрузки стоит стартовый
экран** (`src/ui/StartScreen.tsx`). Он не второй экран загрузки, а его продолжение: тот
же арт, та же присказка (читается у него же — `bootSaying`), то же кадрирование и то же
затемнение. Экран загрузки лежит слоем 100 и снимается по первому кадру диорамы;
стартовый к этому времени уже стоит под ним слоем 70 — игрок видит не смену экранов, а
исчезновение полоски и появление кнопки. Правила, которые нельзя нарушить:

- **Ждать он не заставляет никого, и заставить не может.** Ни `await`, ни `fetch`, ни
  `requestAnimationFrame`, ни таймера — это тест по исходнику (`ui/start.test.ts`), а не
  обещание. Правило экрана загрузки «ни одного внешнего запроса и ни одного ожидания
  кадра» им не тронуто: в скрытом вебвью кадров не дают вовсе, и просить их некому.
- **Сервера ему не нужно.** Кнопка выводится из своего сохранения, синхронизация идёт
  позади. Сети нет — экран работает и в игру пускает.
- **Кнопка одна, и та, которая правдива:** нет партии — «Начать игру», есть —
  «Продолжить». Пары «Регистрация»/«Вход» здесь нет и заводить её нельзя: игрок
  опознаётся подписью Telegram сам, учётная запись заводится первым же заходом, и обе
  кнопки вели бы в одно место. Правило живёт чистой функцией (`ui/start.ts`), и
  настоящий выбор встанет на это же место вместе с настоящим входом по почте и паролю.
  Знание «есть ли что продолжать» приходит из `loadGame` (`fresh`) через поле стора
  `fresh`; серверную партию сюда не подмешивают — она приезжает позже запуска.
- **Настройки на нём — тот же компонент, что в профиле** (см. «Музыка»), а не вторая
  панель с теми же строками.
- **Ничего про алмазы и покупки** — тоже тест.
- Диораму под собой он **не останавливает**: сторож `GameCanvas` знает ровно две
  законные остановки (карта и скрытая страница) и объявил бы третью поломкой.

Разбор целиком, вместе с ценой лишнего нажатия и тем, чем за неё можно заплатить
меньше, — [docs/loading.md](docs/loading.md), раздел 1а.

**Переход между посёлком и картой мгновенный в обе стороны.** Диорама на время карты
не выгружается — встаёт только её рендер-луп. **Выгружать её пробовали, замерили и
откатили:** три мегабайта памяти против четверти секунды на каждом возврате домой —
память не чувствуется никогда, задержка чувствуется всегда. Числа и разбор — в
[docs/loading.md](docs/loading.md), раздел 3; предлагать заново — только с новыми
числами.

Из той попытки осталось и **откату не подлежит починка утечки диорамы**: `GameCanvas`
держит сцену в `useLayoutEffect`, потому что уборка обычного `useEffect` идёт уже после
удаления канвы, а сцена обязана прибираться при канве, ещё лежащей в разметке. Поймали
это на `OrbitControls`: его `dispose()` снимал слушатель с `domElement.getRootNode()`,
и на вынутой канве корнем оказывалась она сама — слушатель оставался на документе, и
документ держал всю сцену, четыре с лишним мегабайта на каждый уход с экрана игры.
Самого `OrbitControls` в сцене больше нет (он ушёл вместе с поворотом камеры), а
порядок уборки остался и держится тестом. Утечка была в игре всё время и нашлась
снимком кучи. Занавес с артом (`ui/SceneCurtain.tsx`) остался ровно
на одном случае — первый вход на карту за партию, и то за порогом мелькания в 240 мс.
Замер целиком — `npm run scene:report`: запуск, генерация мира (19 мс), первый вход на
карту (72 мс) и последующие (27 мс).

## Предыстория: человек у костра

Режим от первого лица, с которого позже будут начинать все игроки, прежде чем получить
деревню, — `src/prologue/`, отдельный чанк по кнопке со стартового экрана. В дереве семь кусков
замысла: поляна с костром (играется ли это пальцем), жизнь с охотой (зачем всё это) — голод,
холод, смерть, лук, олень и мясо, — мир с опасностью: день и ночь, дождь и снег, волки и вой, —
ремесло: дом, одежда, стрелы, — род: спутница, любовь, родословная и имя сына, — зима с телом и
вещами: здоровье, тепло и сытость, одна смерть на три беды, окно вещей, — и финал: семья у огня,
дом сыну и те, кто пришёл из леса. Разбор целиком —
управление, граница времени, сутки и погода, волки, ремесло, род, вой, числа круга, вес, кадры,
финал и честная оценка — в [docs/prologue.md](docs/prologue.md). Здесь только то, что нельзя нарушить:

- **Третьего свода правил о пальце в игре нет.** `Press` и все пороги тапа приезжают из
  `src/gestures.ts` как есть; своё в `prologue/controls.ts` ровно одно — «в какой половине
  экрана лёг палец», и такого вопроса ни у деревни, ни у карты не бывает. Сам `Gesture` взять
  было нельзя: у него правило «второй палец — щипок, тапа больше нет», а здесь два пальца —
  основа режима. Расширять его под оба смысла тем более нельзя: судья деревни и карты стал бы
  зависеть от того, кто его позвал. Держит это тест по исходнику.
- **Тап не целится, выстрел целится, и смешивать их нельзя ни в какую сторону.** Тап бьёт по
  ближайшему в досягаемости (2.1 м), стрела летит туда, куда смотрят. **Оленя в списке
  досягаемого нет вовсе**: он срывается с 7.5 м, то есть вчетверо дальше руки, — и достать его
  можно ровно одним способом. Заведи «выстрел по ближайшему» — лук станет второй кнопкой
  действия, а охота исчезнет. Перекрестье поэтому появляется только с натянутым луком: ровно
  тогда середина экрана впервые что-то значит. **Волк в списке досягаемого есть**, и это то же
  правило: он подходит сам, и удар топором по нему — «сделай с тем, к чему подошёл». Он же
  единственная цель тапа, которой нет в сохранении: его положение приезжает от сцены.
- **Мер времени три, и ни одна величина не движется в двух.** Кадровое (`performance.now()`)
  живёт только в `prologue/scene.ts` — шаг, взгляд, замах, пламя, полёт стрелы, бег зверя,
  кружение волков, капли, вой; в сохранение из него не попадает ничего. Всё, что переживает
  выход, считается **на чтении** из `serverNow()`: пара «сколько было и когда» плюс формула —
  костёр, сытость, тепло, здоровье, пни, зверь. Третья мера — **те же часы, но свой масштаб**: круг
  суток длится четыре минуты, а не сутки, погода идёт спеллами по две. Срок на полосах
  называется настоящими часами, небо — своим кругом, и разводить их надо ровно так. Тика,
  таймера и догона нет ни у одной. Захочется, чтобы огонь разгорался на глазах, — разгораться
  будет картинка, а число останется формулой. `src/prologue` дописан в список зон
  `net/clock.test.ts`.
- **Круг суток — четыре минуты, и число выведено, а не подобрано:** трёхминутный заход обязан
  застать и день, и ночь с любой секунды, отсюда круг не длиннее 4 мин 50 с при доле дня 0.62.
  Проверяется прогоном с каждой секунды круга (`sky.test.ts`).
- **Погода — кольцо данными, а не хеш:** четырнадцать спеллов, двадцать восемь минут, семь
  кругов суток. Хеш от номера спелла означал бы обход тысяч спеллов на каждое чтение, то есть
  догон офлайна; кольцо даёт закрытую форму для обоих интегралов — горения
  (`burnedMs`/`burnUntil`) и холода (`chilledMs`/`chillUntil`). Плата названа вслух: погода
  повторяется раз в двадцать восемь минут.
- **Дождь не гасит костёр, а жжёт втрое быстрее, и полоса считает это вперёд** (`burnLeftMs`
  идёт через прогноз). Гашение отобрало бы обещанное задним числом; ускорение входит в обещание.
  «Двое суток на полном очаге» остались правдой про **погожее** время. Ночь и снег студят
  быстрее (×1.8 и ×1.6), отогрев у огня — одной скоростью в любую погоду. Небо хмурится за
  двадцать пять секунд до непогоды — это тоже тест.
- **Кадр касается записи ровно четырежды, и каждый раз событием, а не величиной:** человек
  пересёк круг — у костра или под крышей достроенного дома (от этого зависит, уходит тепло или
  возвращается и с какой скоростью), стрела долетела (записью становится точка, куда она воткнулась),
  волк укусил (урон растёт ровно на укус) и ночь застала человека дома, пока в доме жена (засчитан
  день общей жизни, не чаще раза в сутки поляны). Отрезок при этом закрывается формулой, и
  пересчёт по частям даёт то же число, что целиком, — это тест.
- **Уходя, человек возвращается к костру.** Отметка «грелся» ложится на диск всегда поднятой:
  промежуток между заходами человек проводит на стоянке, а не там, где его застало закрытие
  вкладки. Иначе игра убивала бы за разряженный у дерева телефон — а это не решение игрока.
  Достроен дом — стоянка под крышей: отметка `roof` ложится на диск тем же правилом.
- **Смерть — чтение, а не событие**, поля «мёртв» в сохранении нет. Она забирает **только запас
  мяса, дрова и шкуру в руках**: топор, лук, все стрелы, одежда и дом остаются, очаг разжигается
  заново. Еда — единственное, что игрок вправду копит, ею он покупает право уйти на сутки;
  отобрать сверх неё значило бы замкнуть петлю смертей, а человек, потерявший всё на пятой минуте,
  второй раз не придёт. По той же причине **новое утро тихое**: волки уходят на три часа, иначе
  загрызенный открывал бы глаза у тех же зубов. Раньше сорокового часа от новой поляны смерть
  невозможна (было четырнадцать) — проверено прогоном по всем фазам кольца, а полоса здоровья
  обещает ровно тот срок, который и случится, — это тест вместо записанного числа.
- **Граница детерминизма у зверя:** есть ли олень на поляне, где он вышел и когда придёт
  следующий — на чтении, из одной отметки времени; как он ходит прямо сейчас — кадры, и в
  сохранение из этого не попадает ничего. `Math.random` нет ни одного во всей папке, и хеш на
  папку один (`glade.hash`) — это тесты.
- **Стрела не размножается и не пропадает сама:** четыре чистые операции в `hunt.ts`; выстрел,
  приземление и подбор не меняют суммы «в колчане плюс на земле плюс одна в полёте» никогда, а
  строгание прибавляет ровно две из полена — и больше суммы не меняет ничто.
- **Волки — не подлость, а опасность, и держится это тремя правилами** (`wolves.ts`). У горящего
  костра их нет вовсе: в круг 6.5 м они не входят и человека в нём не кусают, а все деревья
  стоят снаружи. Их видно раньше, чем они дотянутся: стая выходит на опушку, воет через 0.9 с и
  кружит семь секунд с минуты, в которую человек вышел из круга. Отбиться можно: топор кладёт
  одним ударом, стрела — одной. Есть ли стая этой ночью — на чтении (хеш от круга суток), как
  они ходят — кадр.
- **Стая бросается по одному, и отсчёт у неё один.** Пока отсчёт был у каждого волка свой, пара
  кусала разом на седьмой секунде и добивала на десятой — поймано тестом, переигрывающим само
  правило сцены. Теперь укусил один — отскакивает вся стая, и смерть от волков не раньше
  двадцать второй секунды для стаи любого размера. Укус снимает шестую часть здоровья, и здоровье
  считается в укусах, а не в долях: шесть шестых в числах с плавающей точкой — 0.9999999999999999, и
  шестой укус не убивал бы (та же ловушка однажды поймана с тремя ранами).
- **Вой — синтез через единственный контекст и общий переключатель.** Выключенный звук не
  открывает контекста вовсе, второго рычага нет, а тест «рычаг один» читает целиком `src/ui`,
  `src/prologue` и `src/sound`. Код воя едет чанком предыстории (`sound/howl.ts`, импортирует
  его только она — тест): у `sound/web.ts` он берёт только выход, `openBus`. Похож ли вой на
  вой, ухом не проверено; честное место под файл — интерфейс `HowlHost`.
- **Мясо жарится только на горящем костре и стоит полполена за кусок** — олень целиком ровно
  одно дерево. Сырое есть можно, но втрое хуже — и в сытости, и в здоровье; болезни нет и заводить её
  нельзя, она была бы четвёртой шкалой.
- **Здоровье — одна смерть на три беды** (`body.ts`). Волк снимает шестую часть за укус, опустевшая
  нужда — всё здоровье за двенадцать часов (обе сразу — за шесть), мясо возвращает: жареный кусок —
  укус, сырой — треть. Само заживает за двое суток — у горящего огня или под крышей и только пока
  нужды закрыты: без этого человек без мяса лечился бы смертью. Причина смерти — то, что было пусто в
  минуту смерти (тепло, потом живот, иначе зубы), и смерть закрывает отрезок на себе: записанный труп
  у огня не оттаивает.
- **Холод — одна модель, а не две.** Прежние «восемь часов до смерти» стали полосой тепла на сутки —
  **средних по погоде** (`HOUR_OF_COLD = 1 / CHILL_MEAN`: ночь и снег остались теми же отношениями к
  ясному дню, средняя ставка по кольцу — единица); ночь, снег, одежда и крыша — множители к полосе
  тепла, а полсуток здоровья после неё не трогает ничто. От беспечности до смерти — тридцать шесть
  часов, сутки отлучки не стоят ни полена. Второй шкалы холода в папке нет — это тест по исходникам.
- **Зима с первого кадра.** Сезон поляны — зима тем же `SeasonVisuals.jump`, что у деревни; человек
  приходит к огню с сорока процентами тепла (`ARRIVAL_COLD`), иней по краям кадра — картинка из
  полосы тепла, а не своя величина.
- **Полосы видны всегда, но полная молчит**: тонкая, тусклая, без слова; слева сверху на тёмной
  подложке — белым по белому на снегу не бывает. Костёр — строкой под ними, а не полосой.
- **Вещи — окно, а не панель действий** (`pack.ts`): ровно то, что есть, в постоянном порядке,
  надетое помечено. Счётчики в руках ушли в него, и дверь еды переехала вместе со счётчиком мяса —
  больше из окна не применяется ничего.
- **Ремесло — три вещи, и мерка у него одна: снимать давление, а не добавлять беготни.** Дом из
  сорока двух брёвен (три с половиной захода — расчёт из чисел поляны, и это тест), одежда из
  шкуры оленя, стрелы из полена у колоды. Чего ремесло стоит беготни и что даёт взамен — числом в
  отчёте и в документе; четвёртой вещи не заводить. **Сорок два бревна — решение, а не
  недосмотр:** дровами дом окупается за 23 суток отлучек, но укрытие даёт с первой ночи, а
  предыстория задумана режимом, который держит человека неделями, — на таком сроке это долгая цель,
  а не долг. Предлагать дом дешевле — только с новыми числами.
- **Дом растёт ровно на положенное из рук и укрывает только достроенный.** Укрытие — это «небо не
  давит», а не «тепло»: под крышей ночь и снег студят погожей меркой, волк не входит в круг дома
  при любом огне, раны под крышей заживают и без огня, между заходами человек ночует в доме. Дом
  не греет и очаг не укрывает — иначе он стал бы вторым костром.
- **Одежда множит скорость, с которой уходит тепло, ровно на 0.6 (`COAT_CHILL`) в любую погоду** —
  сутки тепла одетый тратит за сорок часов; отогрева не ускоряет и здоровья не держит, а тест держит
  отношение ровно, а не «около». Шкура снимается с разделанной туши, и только пока нужна.
- **Спутница приходит к достроенному дому, и отказ — не тупик** (`kin.ts`). Приход — на чтении:
  первая через 20 с после последнего бревна (`builtAt`), после отказа следующая через сутки
  поляны (`refusedAt`); где она идёт и что делает руками — кадр. Гостий шесть по кругу, у каждой
  своя беда её словами; ждёт, пока не ответят, и за отказ не мстит.
- **Хозяйка двигает одно число — бережёт огонь**, и оно выведено: `KEEP_BURN = 1 / BURN_MEAN`,
  полный очаг с ней в среднем снова горит двое суток. Мера лежит в самом очаге (`Hearth.kept`) и
  переезжает событием, как подложенные дрова. Готовки и второй работы нет нарочно: вторая механика
  размыла бы правило жарки. Остальное видно глазом и словами — хлопочет у очага, оборачивается к
  подошедшему, после отлучки встречает тем, что стало с огнём.
- **Любовь — чистая функция от накопленного, а не от кадров:** четыре дела — разделённая еда,
  объятие, ночь дома и дрова в общий очаг («достроенное вместе») — засчитываются по разу в сутки
  поляны, по 5 за день и не больше 7 дней на дело. В записи — дни, а не любовь, и она не тает. До
  ста нужны хотя бы три дела; путь — от трёх заходов, обычно пять (расчёт прогоном — тест).
- **Объятие — известный приём и ничего сверх:** затемнение, камера под крышей поднимает взгляд к
  потолку, знак, затемнение, обычный вид. Где человек стоит, оно не меняет.
- **Имя сына лежит в `tribe.prologue.v1` → `heir.name` — для будущей передачи в партию, и сейчас
  его не читает никто, кроме родословной.** Правило имени одно (`kin.heirName`): пустое и мусор не
  принимаются, 2–16 букв. Карточка имени у верхнего края — поле выше любой клавиатуры, — а сцена
  не слушает клавиш, пока печатают в поле (`controls.typing`). Версию записи род не поднял:
  разбор читает каждое новое поле с умолчанием, и это тест. Смерть рода не отнимает.
- **В геометрию мира глаз не заходит, и мерка у этого одна на всё** — `glade.EYE_CLEAR` (0.4 м от
  глаза до чего угодно). Круги преград держат тело, а жаловались на глаз: он оказывался внутри
  пня, внутри кроны у всех семи деревьев поляны и в хвое стены леса. Чинится это тремя разными
  способами, и все три — устройством, а не подбором числа: пня больше нет вовсе, у дерева поляны
  крона поднята над головой (`models.CROWN_FROM`), а дерево кромки само отходит настолько, чтобы
  крона не свисала в лицо (`edgeKeep`). Проверяется замером по всей достижимой поляне —
  `npm run prologue:report`, раздел «столкновение»; что мерить, говорит сама сцена (`solids()`),
  стенд своих сведений о поляне не держит.
- **Срубленное дерево валится, уходит и вырастает заново — и всё это одна отметка времени.**
  Мест семь, больше семи не бывает (поляна не зарастает); возврат — двенадцать часов, и он
  щедрее расхода в одиннадцать раз (поляна не лысеет). Падение (1.5 с), уход (0.9 с) и рост (6 с)
  выводятся из `felled[i]` чистой функцией (`glade.treeLook`), тика нет. Единственное, чего в
  записи нет, — **куда** дерево валится: от человека, и живёт это знание столько же, сколько само
  падение.
- **В руках только то, чем сейчас работают.** Топор и лук в кадре разом — поломка, а не вид:
  смену ведёт одна величина `bowK` в обе стороны, второе оружие уходит за нижний край кадра.
  Лук при этом держат как лук: плоскость лука содержит направление выстрела (иначе стрелу
  приходится вынимать из неё обратным поворотом), рукоять в левой, правая тянет тетиву, и тетива
  у стрелка своя, из двух плеч, — склеенная в общий меш хорда не гнётся.
- **Моргание перед концом — пять отчётливых раз, и между ними видно, как уводят сына.** Веки
  сходятся до конца и раскрываются до конца; кривая живёт в `end.vision` рядом с тактами, а не в
  сцене и не в стилях. Проверяется лентой, записанной в странице на каждом кадре: смыкание длится
  60 мс, и опросом снаружи его можно не застать ни разу.
- **Живая сцена в игре одна.** Пока открыта предыстория, диорама не приостановлена, а разобрана:
  `App` не рисует `GameCanvas`. Приостановки мало — два контекста WebGL на телефоне кончаются
  тем, что браузер молча отбирает старший.
- **Холст — пол, а не потолок.** Канву заводит эффект, поэтому в разметке она оказывается
  последней и без `prepend` закрывает собой всю надстройку: позиционированные соседи без слоёв
  рисуются в порядке разметки. Прожило это молча, потому что не видно ниоткуда, кроме глаз;
  стережёт теперь стенд двумя проверками сразу.
- **Красота — светом, рисунком и своими копиями материалов, и у неё свои запреты** (разбор —
  docs/prologue.md, раздел 14). Лица, одежда и рукава печёт холст в памяти один раз; выражение лица
  меняется перекладкой развёртки, а не перерисовкой — тест читает цикл кадра. Ветер, снег на ветках и
  мокрая земля живут в **копиях** материалов поляны (`surface.ts`): общие материалы деревни не меняются
  ни на бит. Сколько снега лежит, выводится из кольца погод, а не копится; зимой — не меньше
  `WINTER_SNOW`. Угол обзора — от формы экрана (`glade.viewFov`), и прицел его не знает — тоже тест.
- **Первая загрузка не растёт от предыстории.** Чанк — 53.4 КБ gzip вместе со стилями (было 51.9),
  общий чанк `three` тот же — 125.0. Первая загрузка при этом выросла на 1.4 КБ, и выросла не от
  режима: столько стоит временная кнопка кодов (docs/cheats.md). Стили нарочно лежат в
  `prologue/prologue.css`, а не в общем файле. Опись сборки знает, что это не первая загрузка.
  Растёт она и молча, через общий чанк `three`: класс, который в игре раньше не использовался,
  едет туда, даже если зовёт его только предыстория, — так было с линиями дождя. **И даже не
  класс, а имя**: константа или материал, которые деревня из общего чанка не берёт, взятые
  предысторией по имени, дописываются в список экспорта общего чанка. Поэтому сложение цветов —
  число (`paint.ADDITIVE` вместо `THREE.AdditiveBlending`), а материал пятен тени — свой, а не
  `SHADE` деревни; оба держит тест.
- **Связи с деревней нет ни в каком виде:** свой ключ в localStorage, `SAVE_VERSION` племени не
  тронут, сервера нет, алмазов и золота нет — всё это тест по исходникам.
- **Финал начинается по имени сына, а не по дому и жене** (`end.endBegins`), и ступеней у него
  пять: чёрный экран «Прошло много дней…» → семья у огня (подложить дров, накормить обоих) →
  дом сыну в пять досок → пятеро из леса → чёрный экран. Всё, что игрок делает руками, кончает
  ступень; всё остальное он смотрит.
- **В записи финала лежит ступень и что на ней сделано — шесть полей, ни одного срока.** Приход
  пятерых, драка, падение, уход в лес и меркнущее зрение живут в кадрах, и **вышел посреди
  последней сцены — вернулся к её началу**. Это решение, а не пропуск: поле «на какой я секунде
  ролика» стоило бы всей границы времени. Проверяется прогоном, а не обещанием.
- **Оружие висит на руке, а не на туловище.** Топор и лук — дети узла рук
  (`arms.add(weapon)`), и где кулак, сказано **один раз** — самой позой руки
  (`people.limb` возвращает хват). Числами на фигуре (`RAIDER_HAND`) их не ставят: так было, и
  руки качались отдельно от оружия — оно и читалось «рядом с телом». Поза рук у топорника и у
  лучника разная, и у лучника есть локоть: прямая рука до тетивы не дотягивается ни при каком
  угле. Держит это тест по исходникам; как это выглядит — только глазами, снимками.
- **Лучники стоят позади и вне досягаемости топора, топорники сходятся по одному.** Двое с
  луками — в 8.3–8.5 м от человека при досягаемости топора в три метра, и это второй замок:
  первый — устройство, лучника нет в списке целей тапа вовсе. Трое с топорами выходят по
  очереди (`FOE_TURN_MS`), каждый в створ между человеком и серединой ватаги (`RAID_MID`, туда же
  смотрит камера); не положили за черёд — отходит, и выходит следующий. Стрелы летят, когда
  перед луками никого не осталось. Куча из трёх разом читалась одним пятном — по этой жалобе всё
  и переставлено.
- **Жену и сына уводят, а не убивают, и крови в кадре нет.** Насилие показано ровно тремя вещами:
  герой падает, зрение меркнет, фигуры уходят. Показанное здесь слабее недосказанного, а уходящий
  вдаль сын — самый сильный кадр режима. Держит это тест по словам финала.
- **В финале не умирают от голода и холода, и волки в него не приходят.** Последняя сцена написана
  про людей; смерть в ней одна и записана тактами (`end.beatOf`), а не шкалой.
- **Кнопка входа временная и помечена в коде** (`PROLOGUE_IS_TEMPORARY` в `ui/start.ts`): позже
  предыстория станет началом для всех, и кнопку выдернут целиком.
- **Чего нет и что не надо доделывать по дороге:** второй ребёнок и поколения, смерть жены и её
  своя шкала, готовка, второй спутник, переход в деревню и чтение имени партией, второй дом, печь
  и что-либо внутри дома, ремесло сверх трёх вещей, второй вид зверя сверх волка, вяление, болезнь
  от сырого, лечение сверх мяса и покоя, звуки кроме воя, смена времён года и метель вместо дождя,
  применение вещей из окна сверх еды, перенос прогресса в партию, сохранение предыстории на сервер.
  У финала своё: взрослеющий сын, второй исход последней сцены (выиграть её нельзя — героя убивают
  стрелы, и это замысел), погоня за уводящими, продолжение про сына, пропуск сцены кнопкой и
  переход в основную игру — он следующей пачкой, и заготовок под него нет нарочно.

## Пропавшая диорама: контекст, фон, размер

Чёрный прямоугольник на месте деревни после сворачивания и разворачивания аппки — три разные
болезни с одинаковым видом: потерян контекст WebGL, холст вернулся нулевого размера, кадры не
возобновились. Закрыты все три; разбор с числами, порогами и тем, что осталось непроверенным, —
[docs/scene-revive.md](docs/scene-revive.md). Здесь только то, что нельзя нарушать:

- **Прибор раньше лечения.** `src/scenelog.ts` — журнал происшествий и приговор по показаниям;
  читается с телефона без отладчика («Задания» → «Служебное» → «Что было со сценой»), копируется
  целиком в буфер. Не сошлось ни с одной причиной — приговор «не знаю», и подставлять вместо него
  ближайшую похожую нельзя: сломанный прибор хуже отсутствующего.
- **Новая сцена — новая канва.** `dispose` отдаёт контекст насильно, а элемент его не отпускает:
  `getContext` на той же канве вернёт тот же мёртвый. Поэтому канву заводит эффект `GameCanvas`,
  а не разметка. Ключ на теге не годится — React переиспользует узел.
- **Цепочка кадров заводится заново, а не продолжается.** Причин остановки четыре (карта, скрытая
  страница, потерянный контекст, выгруженная сцена), они накладываются, и одним флагом их не
  выразить — `render/loop.ts`. В скрытой странице кадра не ждёт ничто.
- **Молча чёрного прямоугольника быть не должно.** Не поднялась сама — на её месте экран с
  причиной и кнопкой (`ui/SceneTrouble.tsx`). Перезагружать игру при возврате как универсальное
  лекарство нельзя: это прячет причину и теряет несохранённое.
- **Проверяется прогоном:** `npm run revive:report` — настоящий Chrome с настоящим WebGL, потеря
  контекста устраивается расширением. Стенд отвечает «да/нет» и падает кодом возврата.

## Старт в позднем средневековье

Эволюционного развития в игре нет — ни эпох, ни технологий, ни стадий поселения. Всё, что
раньше открывалось знаниями, считается изученным и сложено в базовые числа: выработка профессий
(`data/jobs.ts`), жильё дворов, скорость стройки (`BUILDER_RATE`), оборона без бойцов
(`BASE_DEFENSE`), мораль устоявшегося племени (`MORALE_BASE`). Нового «уровня развития» заводить
нельзя: следующая сессия, работая по старому описанию, вернёт лестницу открытий — этого и не надо.

- **Новая партия начинается с готовым посёлком**: все здания первого уровня, включая стену,
  башню, казармы, кузницу и рынок (`createInitialState` идёт по `BUILDINGS` целиком). Стройки
  с нуля нет: у здания нет уровня 0, площадок и этапов модели.
- **Уровни и улучшение — единственная прогрессия посёлка.** Потолок — `def.maxLevel` и общий
  `MAX_BUILDING_LEVEL` (10), ничем сверху не режется.
- **Все гейты сняты.** Золото, налог, рынок, казармы, все восемь видов бойцов и всё снаряжение
  кузницы доступны с первой секунды; замки на карте видны с начала. У зданий, профессий,
  снаряжения, войск и товаров нет поля `requiresTech`, и его нельзя заводить обратно.
- **Лестница войск — не порядок открытия.** Список в казармах идёт от дешёвого к дорогому, выбор
  между видами тактический (кто против кого, см. «Бой») и экономический (снаряжение, люди,
  припас). Порядок в `TROOPS` — порядок показа, не доступности.
- **Сохранение приводится, но не с любой версии.** `SAVE_VERSION` — 12, и цепочка миграций
  начинается с `MIN_SAVE_VERSION` (8, `save.ts`): каждая ступень доводит состояние до
  следующей версии (`migrate`),
  всё, что старше, `deserialize` по-прежнему отбрасывает, `loadGame` возвращает `legacy: true`, и
  `LegacyModal` говорит игроку прямо, что партия начата заново. Молча стирать нельзя, молча
  приводить — тоже: миграция пишет строку в летопись. Ступень 11 → 12 отпустила покровителя
  племени (`s.patron`) — у деревни теперь вера (`s.faith`, см. «Вера»). Само новое поле версию
  не поднимало бы: `deserialize` мержит его поверх новой партии, и старое сохранение приезжает
  с верой по умолчанию. Подняло её **исчезновение старого**: покровитель был необратимым
  выбором за партию и давал охоте ×1.15, фермам ×1.1 или +2 обороны, и молча такое не
  забирают. Веру при этом не подставляют — её называет мир по клетке замка первым же пульсом.
  Ступень 10 → 11 перевела кузницу с наряда
  (`s.forging`, `s.forgeWork`) на очередь заказов `s.forge`: наряд приводить не к чему — за него
  не платили вперёд, — очередь начинается пустой, и склад при этом не беднеет. Ступень 9 → 10
  завела изучение округи в Дозоре (`s.survey`): ступеней пройдено ноль, потому что задним числом
  их взять неоткуда, а видит деревня при этом ровно то же, что и раньше. Ступень 8 → 9 добавила профиль игрока
  (`s.profile`): счётчики начинаются с нулей, потому что задним числом их взять неоткуда, а мощь
  и визитка считаются из посёлка и дружины, которые в сохранении есть. Восьмёрка сведена из двух
  правок, каждая из которых поднимала версию сама: перестройка посёлка (укрытия нет, тотем стал
  церковью, хижина — жилищами, `s.totem` — `s.patron`) и ратуша (`chief_house` стал `town_hall`);
  версии младше восьмой приводить не к чему — там население было списком поимённых жителей.
  Тест «версии 5, 6 и 7 отбрасываются, восьмая приводится» стоит в `profile/profile.test.ts` на
  зафиксированном строкой сейве и держит это: при следующем слиянии двух веток, каждая из
  которых подняла версию, номер обязан вырасти, а не совпасть.
  Сохранение мира — версия 7, и нижняя граница у него тоже 7: земля под координатами
  сменилась целиком (настоящая Европа вместо шума по сиду), приводить старое не к чему.
  Сохранение племени этим не тронуто — координат карты в нём нет ни одного поля.

## Население — число, а не список людей

Поимённых жителей с именем, возрастом, полом и врождённым талантом в игре нет и заводить их
обратно нельзя. Племя — это `s.pop`, а назначение на работу — счётчик, а не список. Единственное
исключение — **герой** (`s.hero`): он не житель, его даёт Статуя, и он один.

- **`s.pop`** — жители посёлка; бойцы и новобранцы считаются отдельно (`population` в `derived.ts`
  складывает всё вместе — с этого числа берут налог).
- **`s.workers`** — сколько человек в каждом здании, ключ — id постройки. **`s.freeJobs`** — сколько
  занято вольным сбором по профессиям. Свободные руки — остаток (`idleCount`), отдельного поля у них нет.
- **Личного навыка у человека нет.** Его роль целиком взял на себя уровень здания: он и добавляет
  места (`buildingSlots` = уровень × `slotsPerLevel`), и поднимает выработку каждому рабочему
  (`levelOutputMult`). Талантов, «звёздочек» и выбора конкретного человека в панели быть не должно —
  выбирать не из кого, люди одинаковы.
- **Рождений, старения и смерти от старости нет.** Вместо них прирост (`sim/population.ts`,
  `popGrowth`): произведение трёх множителей — свободное жильё, запас еды и мораль — на долю от
  населения. **Мораль двигает не только выработку, но и прирост**, и ниже `MORALE_GROWTH_ZERO` (45)
  уходит в минус: недовольное племя разбегается независимо от жилья и запасов. Это и есть цена
  налога и скудного пайка, и она обязана оставаться заметной.
- Голод, холод, болезнь и проигранная стычка забирают **долю посёлка** (`FAMINE_TOLL`, `famineToll`),
  а не одного безымянного человека: на семи сотнях душ одна смерть не была бы даже видна. Летопись
  пишет итог дня одной строкой (`logPopDay`), а не строку на голову.
- Убыль снимается по порядку «свободные руки → вольный сбор → самое многолюдное здание»
  (`losePop`), поэтому зима не оставляет посёлок без единственного кузнеца.
- **Невольники устроены так же, а не рядом:** `s.bonded` — сколько их, `s.bondedWork` — сколько
  стоит в каждом здании. Места у здания общие (`handsCount`), таблица выработки и множитель те
  же, доля — `BONDED_OUTPUT`; едят по головам в `townFoodPerDay`. Жителями они не считаются:
  налога, жилья, обороны и прироста у них нет. Второй системы занятости под них заводить нельзя
  (см. «Невольники и порядок в городе»).

### Масштаб

Игра идёт к боям в сотни бойцов, значит и посёлок другого порядка: **на потолке уровней 600–1000
человек** (сейчас 755), а не полсотни. Из этого следуют все остальные числа, и менять их врозь нельзя:

- жильё (`housing`/`perLevel` Жилищ, ратуши и `BASE_HOUSING`) — оно и задаёт потолок;
- рабочие места: `SLOTS_PER_LEVEL` (12) и `slotsPerLevel` у зданий, где толпа бессмысленна
  (мастерская 6, кузница 4, церковь 2). Всех мест чуть больше, чем людей, — выбор есть, абсурда нет;
- вместимость склада: она обязана держать самое дорогое улучшение десятого уровня;
- цены и труд улучшений: ими и задаётся темп партии;
- работа кузнеца (`data/equipment.ts`) и казарм (`recruitRate` умножается ещё и на уровень) —
  иначе дружину в сотни бойцов не одеть и не обучить за разумное время;
- отопление и налог считаются с населения и масштабируются сами.

**Темп проверяется прогоном, а не на глаз: `npm run pop:report`.** Он играет партию автопилотом и
печатает, за сколько посёлок доходит до каждой сотни жителей и до потолка уровней, что делает зима
на каждом этапе и что будет с племенем, поставившим на поля. Сейчас полный выход на потолок —
около семи часов игрового времени при идеальной игре. Меняешь цену, жильё или выработку — смотри
отчёт.

## Диегетический интерфейс

Данные живут не в глобальных панелях, а внутри зданий. Одно правило без исключений:

- у каждого здания своя панель, она открывается тапом по зданию в сцене или из списка построек
  в ратуше;
- рабочие ставятся числом: ряд шага −10 −1 [n] +1 +10 (`ui/parts/Steps.tsx`), а не
  карточкой на человека — на потолке уровней в поле стоит сотня человек, и сотню строк никто не
  прочтёт; невольники ставятся тем же рядом вторым, под вольными;
- «Племя» — тоже числа: свободные руки, прирост с его тремя множителями, невольники (где стоят,
  сколько без места; здесь же их отпускают) и кто чем занят;
- панель у всех одинаковая: шапка (иконка, название, уровень, кнопка улучшения), рабочие,
  собственные данные здания, его действия — см. `ui/panels/BuildingPanel.tsx`;
- ресурсы и снаряжение целиком видны только на складе (полоска сверху — не замена ему,
  см. ниже), вольный сбор и мораль — у костра,
  указы, рацион, налог и казна — в ратуше, ковка — в кузнице, наём — в казармах,
  закупка за золото и продажа невольников — на рынке, пир за золото — в трактире, герой и его
  род — в Статуе, вера, набожность, устав прихода, обряд и крещение — в храме;
- нижняя навигация — «Племя», «Ратуша», «Задания». Первое и третье не привязаны к месту;
  ратуша — единственное исключение из этого правила, и причина одна: через неё идёт вся
  стройка посёлка, а на 390 px пальцем по крыше не попасть. Отдельного раздела «Здания»
  нет и заводить его нельзя: список построек живёт на вкладке «Стройка» в ратуше
  (`ui/parts/TownBuild.tsx`, у строки есть `data-tut="list-<тип>"`), и одно и то же дело
  не должно делаться в двух местах. Тап по крыше в сцене остаётся.
- самой верхней строкой — день, сезон, население, мораль, порядок (только пока есть
  невольники: без них он всегда сто) и дружина. Читается она первой: это «когда я и что
  вокруг». **Каждая её ячейка, кроме дня, — кнопка справочного экрана** (см. ниже): играть, не
  понимая, откуда взялось число, игрок не должен. С ячейкой порядка строка тесная, и подписи дня
  и дружины прячутся (`.hud-bar.with-order`): на 360 px иначе сжимался бы сезон;
- второй строкой — полоска ресурсов (`ui/ResourceBar.tsx`): семь значков с числом, без
  подписей, тысячи сокращаются (`shortNum`). Она **не отменяет правила «данные живут в
  зданиях»** — полный список запасов, снаряжение и вместимость по-прежнему только на складе;
  полоска отвечает на один вопрос, «хватит ли», и заведена ради решений, которые приходят
  окном поверх всего (см. «Решение, требующее отдать добро»). Два её свойства обязательны:
  её **не закрывает ни одно окно** и она **ничего не нажимает** (`pointer-events: none`),
  иначе тап по ней открывал бы шторку под открытым событием. Полный склад покрашен: добыча
  в него с этой минуты пропадает.
  **Держится «не закрывает ни одно окно» слоем, а не местом в столбце**: у `.res-bar` свой
  `z-index` выше затемнения (21 против 20), у остальных строк шапки — ниже, а сама шапка
  своего слоя не заводит, иначе разнести их было бы нечем. Прежде это держалось вырезом в
  затемнении по верхней кромке экрана и потому работало ровно пока полоска стояла первой
  строкой. Она больше не первая — правило пережило перестановку только потому, что его
  переписали;
- третьей строкой — свой ряд на две кнопки: слева профиль (**одно лицо, без имени**), справа
  карта мира (**один значок, без слова**). Обе видны всегда, обе квадратные в `--tap` (44 px);
  освободившееся от подписей место не занято ничем.

Игрока нельзя запереть за зданием: добыча без места в здании работает «вольным сбором»
(`FREE_RANGE_MULT`).

### Решение, требующее отдать добро, отвечает на свой вопрос само

Правило одно и без исключений: **везде, где игрок отдаёт ресурсы, рядом с запрошенным
количеством стоит, сколько этого есть**, и видно это **до** нажатия. Кнопка, которая не
сработает, гаснет и говорит причину; проваливающихся нажатий не бывает.

Форма у этого одна на всю игру — `ui/parts/Cost.tsx`, «значок, сколько нужно, из скольких
есть», красным при нехватке. Она стоит у стройки, и она же — у события (`EventModal`), у
письма с данью и выкупом (`ui/Letters.tsx`) и у приказов дипломата на карте
(`ui/map/ActionMenu.tsx`). Второй такой формы заводить нельзя: игрок узнаёт её с одного
взгляда, а два способа сказать одно и то же он читает как два смысла.

**Два места правило пока не соблюдают**, и это долг, а не исключение: ковка
(`ui/parts/Smithy.tsx`) и наём (`ui/parts/Barracks.tsx`) рисуют цену своей строкой — красным
при нехватке, но без «из N». Уйдут на `Cost` пачкой-уборкой; нового такого места заводить нельзя.

**Показанный запас и посчитанная нехватка — одно число, а не два похожих.** `Cost` берёт
склад из `s`; мир, гасящий кнопку письма и приказа, считает по `PlayerProfile.stock` — тому
же складу целиком, вместе со спрятанным в тайнике (тайник прячет добро от чужаков, а не от
вождя). `resources` в слепке — другое: это то, что видно набегу, и им «хватает ли» не
считают.

Пришло это из жалобы, а не из красоты: окно события закрывает собой и склад, и всю игру,
отложить его нельзя, — и «отдать припасы» приходилось нажимать наугад. Поэтому у полоски
ресурсов сверху и есть два обязательных свойства (не закрывается окнами, ничего не
нажимает), а у события — объявленная цена.

### Справочные экраны строки состояния

Полос ресурсов и всплывающих подсказок в игре нет, поэтому правило объясняется там же, где
стоит число: тап по ячейке HUD открывает экран про неё. Все пять — обычные разделы шторки
(`Tab`), в нижнюю навигацию не попадают и открываются только из строки состояния (порядок —
ещё из своей строки тревоги).

- сезон → `SeasonPanel` (множители сезона) — образец, по которому сделаны остальные;
- население → `PopPanel` (`pop`): три множителя прироста полосками с пометкой узкого места,
  порог `MORALE_GROWTH_ZERO` на шкале, прирост в минуту и время до заполнения жилья;
- мораль → `MoralePanel` (`morale`): на что она влияет (выработка и прирост — текущими
  коэффициентами), что добавляет и что отнимает — построчно, с текущим вкладом каждого;
- порядок → `OrderPanel` (`order`): срок ропота, цена мятежа при нынешней страже, кто держит
  невольников построчно (`orderBreakdown`) и рычаги кнопками;
- дружина → `ArmyPanel` (`army`): состав, кольцо контрров картинкой (`parts/CounterRing`)
  и карточка вида по тапу (`parts/TroopCardView`).

Два правила без исключений:

1. **Числа живые, а не из начального состояния.** Панель считает их от `s` на каждом кадре
   стора, поэтому они меняются вместе с партией. Копий формул в панели быть не должно:
   прирост берётся у `popGrowth`, слагаемые морали — у `moraleBreakdown` (это же и есть
   `moraleTarget`, а не «то же самое рядом»), множитель выработки — у `moraleOutputMult`.
   Понадобилось число, которое считается внутри симуляции, — выносить его функцией в
   `derived.ts`, а не переписывать в JSX.
2. **Содержимое карточки войск целиком выводится из конфига** — см. «Описание вида бойцов».

## Профиль игрока: мощь, статистика, лицо

Кнопка профиля стоит слева во второй строке HUD, напротив карты, — кружок с лицом и имя
(`ui/ProfileButton.tsx`). Панель — обычный раздел шторки (`Tab` = `profile`), в нижнюю навигацию
не попадает. Всё, что живёт в профиле, лежит в `src/profile/`.

- **Мощь — одна цифра: посёлок плюс дружина** (`profile/power.ts`, чистая функция от состояния).
  Оба слагаемых выведены из уже существующих конфигов, и своей таблицы весов «для профиля» нет
  и заводить её нельзя: она разъедется с балансом ровно так же, как разъезжается любой
  справочник, переписанный руками. Здания — из цены уровня (`work` плюс материалы), делённой на
  цену обычного здания, и уровень входит нелинейно (`LEVEL_EXP` = 1.5): двадцать первых уровней
  не должны весить как один двадцатый. Бойцы — из боевого конфига (`UNIT_STATS`, `GEAR`,
  `MORALE.max`) через тот же перевод в бойцы строя, которым пользуется бой (`weightOf`).
  **В `power.ts` нет ни одного имени здания и ни одного имени вида бойцов** — это тест: новый вид
  войск или новое здание попадает в мощь сам, без правки профиля.
- **Алмазы, золото и покупки в мощь не входят никак**, и это тоже тест по исходнику: слов `gems`
  и `gold` в модуле нет. За алмаз в игре покупается время, а не сила.
- **Статистику правит один модуль** — `profile/stats.ts` (`recordProduced`, `recordSpent`,
  `recordRaidLoss`, `recordTroopsLost`, `recordLoot`, `recordBattle`). Вызовы стоят там, где
  событие действительно происходит: производство в `tick`, траты в трёх местах платежа
  (`sim/actions.pay`, `sim/army.startRecruit`, `sim/smithy`), потери, добыча и счёт битв в
  `sim/expedition` и `sim/battle`. **Ни один экран и ни один компонент в эти поля не пишет** —
  иначе счётчик начнёт считать не то, что случилось в игре, а то, что открыл игрок.
- **Хранится две вещи**: накопительные итоги на всю партию и суточные корзины на месяц
  (`PROFILE_DAYS` = 30) — только по трём показателям: производство, потери от грабежей, мощь.
  Корзины кольцевые и режутся **по возрасту**, а не по количеству — та же ошибка, что когда-то
  была у летописи. Журнала событий в профиле нет и не будет: он растёт без предела, и его никто
  не читает.
- **Визитка** (`ProfileCard`) — готовые значения: имя, аватар, мощь, счёт битв. Она лежит в
  сохранении посчитанной, потому что на карте мира чужой игрок увидит именно её, а собирать там
  мощь из зданий и армии будет не из чего. Пересобирает её `refreshCard` — раз в игровой день,
  после каждого боя и после любой правки имени или лица.
- **Имя и лицо: три источника, порядок жёсткий** — свой выбор, потом Telegram (`first_name`,
  `photo_url`), потом «Вождь» и `01_swordsman`. Переопределение живёт в сейве и приоритетнее
  данных Telegram. Читает это `profile/identity.ts` (только чтение), пишет — `stats.ts`: правка
  обязана пересобрать визитку, иначе игрок переименовался бы, а чужие глаза видели бы старое имя
  до следующих суток. Данные Telegram кладёт в состояние оболочка (`store.init`): симуляция про
  Telegram не знает.
- **Экран выбора лица строится из `AVATARS`** (`ui/parts/AvatarPicker.tsx`), а не из двадцати
  четырёх прописанных карточек: карточка через `card`, кружок через `face`, выбранный в рамке,
  «Сохранить» пишет `avatarId`. Имён видов в разметке нет ни одного, и это держит тест.
  Сам набор (`src/data/avatars.ts`) генерируется `scripts/slice-avatars.mjs` из листов в
  `assets-src/avatars/` — руками его не править.
- **Стены счётчиков в панели быть не должно.** Показано ровно то, о чём игрок себя спрашивает:
  насколько я силён, как воюю, что у меня утекает, сколько добываю. Разбивка по семи ресурсам
  оставлена в одном разделе — в потерях: на вопрос «что утекает» итог не отвечает. Состав дружины
  не дублируется, он есть в своей панели.
- **Ничего в профиле не начисляет алмазы и не открывает к ним путь.** Награды за достижения
  остаются невыплаченными до бэкенда — проверить и выдать их без сервера нечем.

## Задания: две страницы, летопись и ежедневка

Раздел «Задания» (`ui/panels/QuestsPanel.tsx`) — две страницы, и переключатель между ними
живёт местным `useState`, а не в сторе: снаружи на вторую страницу ничего не ведёт, а шторка,
закрывшись, обязана открыться снова на заданиях. (Сравни с `townTab`: тот в сторе именно
потому, что на «Управление» ведёт ссылка из справки о морали.)

- **«Задания»** — задания племени, достижения, летопись, служебное.
- **«Каждый день»** (`ui/parts/daily/DailyPage.tsx`) — задание дня, потом социальные подписки,
  потом приглашение. Порядок такой, потому что игра здесь единственное, что игрок делает
  каждый день, а остальное он читает один раз.

### Летопись живёт по возрасту

`s.log` хранится **не по числу строк, а по возрасту**: старше `LOG_MAX_DAYS` (30 игровых дней)
выбрасывается. Обрезка по количеству врала — при бурной партии полсотни строк укладывались в
один день, при спокойной растягивались на полгода, и «последние 80 записей» означали то неделю,
то век. Возраст — мера, понятная игроку.

- `LOG_MAX` (250) — **запасной** предел по количеству, и он обязан не срабатывать: сработал —
  значит ступень «за месяц» показала меньше месяца. `npm run log:report` кричит об этом
  отдельной строкой. Числа не выбираются на глаз: отчёт играет партию, где кузница под нарядом,
  казармы набирают, а события поднимаются и разбираются, и печатает, **кто** наполняет летопись.
- Возраст режется раз в игровой день на смене суток в `tick`; счёт — на каждой записи;
  сохранение приводится к тому же месяцу на загрузке, в `deserialize`.
- **Повторы склеиваются счётчиком** (`group` и `n` у `LogEntry`, `LOG_COALESCE` — игровые сутки).
  Ключ склейки ставится только там, где источник пишет по строке на единицу товара: ковка,
  наём и заказ на рынке. Всё остальное случается по разу, и две зимы подряд остаются двумя
  зимами.
- **Рынок стоит одной строки в день на товар, и приход каравана не пишется вовсе.** Он не
  событие: игрок сам его заказал, телега едет по улице у него на глазах, груз лежит на
  складе. Событие тут одно — склад полон и часть груза пропала (`market:full:<товар>`), его
  игрок обязан узнать. Без этого правила день торговли стоил двух десятков строк, месячная
  ступень показывала пять дней, а на рынке десятого уровня — девятнадцать. Держат это тест
  «месяц остаётся месяцем и у торгового племени» (рынок и склад десятого уровня, дюжина
  товаров, три тысячи заказов) и раздел «торговое племя» в `npm run log:report`. Запаса до
  `LOG_MAX` на этом потолке остаётся два десятка строк — новый частый писарь его съест. Ищется ключ
  по всему окну суток, а не по верхней строке: между двумя копьями успевают лечь итог дня и
  событие. Поле `at` при склейке не двигается — на порядке записей держится обрезка хвостом.
  В интерфейсе счётчик читается только через `n ?? 1`: у старых записей поля нет.
- В интерфейсе (`ui/parts/Chronicle.tsx`) летопись **свёрнута** и раскрывается ступенями:
  сутки → неделя → месяц. Дальше месяца ступеней нет, потому что дальше месяца ничего и не
  хранится, — и об этом сказано словами. Отметка времени стоит одна на день, а не в каждой
  строке: на 375 px «Д121» в десяти строках подряд съедает четверть ширины.
- Полная летопись поедет на сервер, когда он появится. Пока хранить её негде, и старое
  отбрасывается — молча копить его в сохранении нельзя.

### Ежедневное задание

Одна попытка в календарные сутки, задание **одинаковое у всех игроков** в этот день.
Устроено как прилавок рынка: в состоянии не хранится ни какая сегодня игра, ни что у неё
внутри — и то, и другое выводится из номера дня (`data/daily.ts`).

- **День — календарный и по UTC** (`dayIndex(nowMs)`), не игровой: игровой идёт по минуте, и
  «раз в 24 часа» им не измеришь. У полуночи должна быть одна граница на всех, иначе
  «одинаковое задание у всех» рассыпается на двадцать четыре разных.
- **Часы читает только интерфейс.** В симуляцию день приходит числом, `tick` про ежедневку не
  знает вовсе — поэтому она не ломает ни детерминированность, ни офлайн-догон, а тесты
  обходятся без подмены глобального времени.
- **Три игры чередуются**: дни идут тройками, внутри тройки каждая выпадает ровно раз, а
  порядок внутри выбирает перестановка по хешу номера тройки — пятый день не угадывается из
  второго.
- **Попытка тратится на старте** (`startDaily`), а не на победе, и сразу пишется проигранной:
  уйти с экрана посреди лабиринта и зайти заново — это и есть вторая попытка. Победа поднимает
  запись до выигранной. `finishDaily` кнопке не верит: без начатой попытки итог не принимается.
  Потраченная попытка **кладётся на диск сразу** (`save()` следом за `act`), а не ждёт
  автосохранения: пятнадцать секунд, за которые игру можно закрыть начисто, — это та же
  вторая попытка, только другим путём.
- **День попытки заморожен, пока она идёт.** Панель считает его один раз на старте и держит в
  своём состоянии. Иначе полночь UTC, заставшая игрока посреди лабиринта, сменила бы доску под
  рукой (сид выводится из дня) и отняла бы победу: `finishDaily` не принял бы итог за день,
  которого не начинали.
- **Часы назад не переводятся.** `day < s.daily.day` читается как «этот день уже сыгран»:
  без этого перевод даты устройства на вчера открывал бы попытку заново сколько угодно раз.
  Перевод ВПЕРЁД так не закрыть — игрок с навсегда переведёнными часами неотличим от
  дождавшегося, и это лечится только серверным временем.
  Обратная сторона храповика достаётся не жулику, а человеку со сбитой датой: телефон,
  однажды показавший год вперёд, запирает ежедневку до тех пор, пока календарь не догонит
  запись. Открыть попытку нельзя — этим же ходом её и множат, — поэтому `DailyStatus`
  несёт `clockBehind`, и панель говорит правду вместо «приходи завтра»: дата отстаёт от
  записи, вот число, когда откроется, проверь часы. Молчать нельзя: обещание «завтра»,
  которое не сбудется год, хуже отказа.
- **Две вкладки тоже лечатся только сервером, и это решение, а не недосмотр.** Сохранение
  одно на всех, пишет его последний: вкладка, открытая раньше и не знающая о потраченной
  попытке, своим автосохранением возвращает её обратно — воспроизводится на слое сейва за
  четыре строки. Это не про ежедневку, а про «последний пишущий выигрывает» вообще: так же
  теряется любой прогресс первой вкладки. Городить межвкладочную блокировку под одну
  ежедневку не надо — искать здесь недосмотр не надо тоже.
- **Награда — ресурсами, и это структурный запрет, а не обещание.** Тип награды —
  `Partial<Record<ResourceId, number>>`, а `ResourceId` алмазов не содержит: `{ wood: 40, gems: 2 }`
  не собирается. Считается она от размера посёлка приёмом событий и обрезается долей склада.
- Генераторы — в `game/daily/` (`archery.ts`, `maze.ts`, `quiz.ts`): чистые функции от сида, ни
  React, ни DOM, ни `Math.random`, ни `Date`. Единственный источник случайности — `seeded` из
  `sim/random`. Ход самой игры живёт в компоненте и наружу не выходит: состояние целиком
  уезжает на сервер раз в минуту и на диск каждые пятнадцать секунд, а `tick` переписывает его
  дважды в секунду.
- **Викторина «кто победит» не придумывает вопросов.** Составы прогоняются настоящей
  `simulateBattle` из `src/battle/`, и правильный ответ — тот, что дала она. Ответ нигде не
  хранится: записанный, он молча разошёлся бы с балансом после правки `battle/config.ts`.
  Пары отбираются неочевидными — равные силы, без ничьих и без одностороннего размена, — и
  разбор после ответа берётся из журнала боя, чтобы игра учила кольцу контрров, а не удаче.
  Путь из видов племени в ядро **ровно один** (`quizSetup`): второй дал бы другую разбивку по
  секторам, и тест «ответ совпадает с симуляцией» проходил бы через раз.

### Социальные ссылки и приглашение

**Ни за подписку, ни за приглашённого друга ничего не начисляется, и путей к начислению нет.**
Проверить подписку без сервера физически нечем — это вызов `getChatMember` от имени бота.
Награда за нажатие кнопки досталась бы и тем, кто ничего не подписал. У `SocialLink` поэтому
нет поля награды: дописать его в литерал — ошибка компиляции. Изображать выдачу нельзя,
обходные пути заводить нельзя, и об этом сказано игроку словами.

- Реферальная ссылка собирается единственным рабочим форматом — `t.me/<бот>/<аппка>?startapp=`.
  `?start=` не годится: он открывает чат с ботом, а в мини-аппку не приходит вовсе.
  `BOT_USERNAME` и `MINI_APP_NAME` в `data/social.ts` — **заглушки, их надо заменить** на
  настоящие из @BotFather, и мини-аппку надо там завести: у Menu Button короткого имени нет.
  Пока они заглушки, ссылка собирается и ею можно поделиться, но ведёт она в никуда — и экран
  говорит об этом прямо (`BOT_IS_PLACEHOLDER`). Молчать нельзя: игрок отправил бы её другу и не
  узнал, почему тот не пришёл. Впишут настоящие имена — пометка исчезнет сама.
- Идентификатор игрока берётся только из `initDataUnsafe` и только на показ: подписью он не
  проверен. Вне Telegram его нет — тогда нет и ссылки, и об этом говорится прямо, а не
  подставляется выдуманный код из localStorage.
- `openTelegram` и `openExternal` разведены нарочно: `openLink` на `t.me` уводит игрока во
  внешний браузер, откуда в мини-аппку он не вернётся. У `shareLink` четыре ступени, и порядок
  менять нельзя — `navigator.share` и `window.open` требуют жеста, а жест теряется на `await`.
- **Замок алмазов теперь на всём `src`**, кроме самого `sim/gems.ts`: `gems.test.ts` читает
  исходники, выбрасывает комментарии и валится на любом `creditGems`, на присваивании `.gems`,
  на `s['gems']` и на `Object.assign` с этим ключом.

## Ратуша: стройка, управление, алмазы

Ратуша (`town_hall`, бывший Дом вождя) — сердце города, и дел у неё три, поэтому у панели
вкладки (`ui/parts/TownHall.tsx`; вкладка живёт в сторе — `townTab`, чтобы на «Управление»
можно было привести ссылкой из справки о морали).

- **«Стройка»** (`ui/parts/TownBuild.tsx`) — главная вкладка и единственное место, откуда
  ведут улучшения: «В работе» (очередь), «Постройки» (что можно поднять сейчас) и «Пока
  недоступно» (чему уровень не дать и почему — предел уровня, идущее улучшение, нехватка
  ресурсов). Раздела «можно построить» в этом списке нет и быть не может: строить нечего,
  посёлок стоит целиком. Строка постройки — иконка, название, уровень, цена по ресурсам,
  время, спрос на людей и две кнопки: «Уровень N» и достройка за алмазы. Тап по телу строки
  открывает панель здания (`data-tut="list-<тип>"`) — навигацию по посёлку список тоже забрал.
- **«Управление»** — то, чем правит вождь: указ, рацион, налог и казна.
- **«Алмазы»** (`ui/parts/Gems.tsx`) — премиальная валюта: счёт, достройка и витрина наборов.

**Уровень ратуши ускоряет все стройки посёлка** — `townHallBuildMult`, множитель ко всей
скорости (`TOWN_HALL_BUILD_STEP` = 0.08 за уровень, на потолке ×1.72). Это множитель, а не
ещё одно слагаемое труда: ратуша не строит сама, она распоряжается. Смысл уровня ратуши
держится на этом, а не только на морали и жилье.

`data/policy.ts` — единственное место, где записано, что делают указ, рацион и налог. Логика
только читает таблицу: `decreeOf`/`rationOf`/`taxOf`, множитель выработки в `jobMultiplier`,
множитель расхода в `foodConsumptionPerDay`, дневной сдвиг морали в `tick` через
`policyMoralePerDay`.

- Налог даёт `perPop × население × TAX_PER_POP` золота в день, население — жители, бойцы и
  новобранцы (`population`). Платит за него мораль — а мораль теперь двигает и прирост,
  так что высокий налог виден дважды.
- Последствия пишутся словами в поле `effect` — этот текст стоит **на кнопке**, а не в подсказке.
- Числа должны сходиться ровно: тест сверяет выработку и расход с объявленной величиной.
- Ратуша с 6 уровня даёт жильё — через поле `since` в определении здания.

## Вера

Начало игры — 1200 год, и вера не выбирается из меню: она достаётся вместе с землёй, по
клетке, на которой реестр поставил замок. Полный разбор с числами, регионами и тем, чего в
пачке нет, — [docs/faiths.md](docs/faiths.md). Здесь только то, что нельзя нарушить.

- **Разметка регионов — наша, и это не источник.** Данных о границах вероисповеданий 1200
  года с ясной лицензией нет; пятнадцать прямоугольников по долготе и широте плюс линия
  Тахо в `src/world/faith.ts` нарисованы нами по школьному представлению об эпохе. Мерка —
  узнаваемость, а не точность. Выдавать это за карту исторических конфессий нельзя нигде.
- **Вера клетки — чистая функция координат.** Ни сида, ни состояния, ни порядка чтения:
  карта одна на всех. Порядок областей в списке — часть разметки: побеждает первое
  совпадение, и переставить две строки значит изменить карту.
- **Иудаизма в стартовых верах нет, и это решение.** В 1200-м у него нет территории — он
  живёт общинами в городах, а городов в игре нет вовсе. Записано затем, чтобы через месяц
  никто не решил, что его забыли.
- **Набожность — величина вроде морали, но своего поля в состоянии у неё нет.** Она
  считается при чтении (`derived.pietyBreakdown`) из храма, уклада, обряда, чужой веры
  вокруг и надлома. Тика у веры нет и заводить его нельзя: обряд держится отметкой,
  надлом убывает от отметки, и офлайн-догон проходит мимо всего этого.
- **Уровень храма не даёт прибавки — он растит наклон веры целиком, вместе с ценой**
  (`data/faiths.tiltAt`, доля = уровень / 10 × множитель уклада). Каждая ступень поэтому
  выбор, а не бесплатное усиление. Уклад прихода — тот же рычаг, что рацион и налог: он
  множит наклон и платит за строгость набожностью в другую сторону.
- **Никаких боевых бонусов вида «моя вера бьёт твою», и держится это устройством.** У
  `BattleInput` нет поля веры вовсе. Единственное, что вера кладёт в бой, —
  `ArmySetup.resolve`: одно неотрицательное число, прибавка к стартовой морали **своих**
  секторов, одинаковая против кого угодно. Ядро про источник не знает. Проверяется тремя
  способами разом (исходник, конфиг, прогон) — `game/sim/faith.test.ts`.
- **Ни одна вера не выставляется дурной или отсталой** — ни числом, ни словом. Различия
  идут вбок: хозяйство, мораль, дипломатия, знание. Отношение по вере симметрично
  (`faithAttitude(a, b) === faithAttitude(b, a)`) и в бой не входит ни одним числом.
- **Ересь не заводит второй механики.** Бунта в деревне нет ни в каком виде: `revolts` в
  мире — окно на **чужом** поселении, его поднимает лазутчик. Поэтому ересь идёт туда,
  где деревня и так живёт: слагаемое морали, строка тревоги и событие с выбором. Мятеж
  невольников бунтом не является и сделан по этому же образцу (см. «Невольники и порядок
  в городе»).
- **Крещение — единственный способ сменить веру, и он односторонний.** Только язычник,
  только в католичество или православие, обратно дороги нет. Риск раскола настоящий, но
  это не бросок кости: игра считается на чтении, а спрятанный бросок пришлось бы хранить.
  Обычный приход от надлома проваливается в ересь, подготовленный — выдерживает.
- **Подпись храма зависит от веры** (`derived.buildingTitle`): костёл, храм, мечеть,
  капище. Идентификатор здания при этом прежний (`church`) — от него зависят план посёлка,
  модель, значок и сохранение.
- **Чего в этой пачке нет и что не надо доделывать по дороге:** проповедника и обращения
  чужих (ждёт сервера-судьи), действий между игроками, дробления вер на конфессии,
  отбирания реликвий у других игроков.

## Невольники и порядок в городе

Невольники — руки сверх того, что держат крыши посёлка, и сразу, а не приростом; платят за
них едой, золотом или войной — и порядком. Порядок, упав, кончается мятежом. Разбор целиком,
с таблицами из `npm run order:report`, — [docs/order.md](docs/order.md). Здесь только то,
что нельзя нарушить.

- **Второй системы занятости нет.** Невольник — третье число на тех же местах (см.
  «Население» и «Здания»): та же таблица выработки, тот же множитель, та же функция
  выработки (`yardYield`), доля `BONDED_OUTPUT`; ест по голове в `townFoodPerDay`. Налога,
  жилья, обороны и прироста у него нет. Заводить невольникам свой расчёт рядом — ошибка.
- **Порядок — чистая функция на чтении, как мораль и набожность** (`orderBreakdown`): надзор
  (дворы, бойцы дома, спокойные горожане) к надзору плюс невольники. Поля порядка в состоянии
  нет. **Без невольников он сто** при любом гарнизоне и морали, и мятежа без невольников не
  бывает — тесты.
- **Порядок — не вторая мораль.** Мораль — довольны ли горожане (выработка, прирост), порядок —
  удержат ли невольников (мятеж). Мораль входит в порядок слагаемым, обратно — никак:
  `moraleBreakdown` не читает ни порядка, ни невольников, и это тест по исходнику.
- **Мятеж — не бунт** (`revolts` — окно на чужом поселении) и не третья система: он лёг, как
  ересь, в строку тревоги и в событие общей таблицы (`id: 'mutiny'`, вес ноль). Поднимает его
  срок ропота `s.unrest` — единственное, что механика хранит, секундами, как `starvation`.
- **Мятеж не случается без игрока.** Срок ропота и срок ответа идут только при нём
  (`unrestTick(..., online)`): офлайн-догон их **замораживает**, а не гасит. Довод осады
  («иначе лучшая игра — закрыть приложение») тут не работает — закрытие не отменяет ни ропота,
  ни цены. Защиту не снимать: самая жёсткая потеря в игре не должна приходить во сне.
- **Окно мятежа ждёт ответа не вечно** (`MUTINY_ANSWER`, срок написан в окне через
  `EventDef.deadline`); без ответа стража выходит сама. Окно, открытое сколько угодно, держало
  бы невольников за работой без исхода. Пока идёт ропот, случайные события не поднимаются.
- **Цена объявлена до того, как наступит**, и считает её одна функция — `mutinyForecast`: ей
  пользуются строка тревоги, справка «Порядок», подсказки окна и сам исход. Строка рынка
  говорит, каким станет порядок, **до** покупки. Броска кости нет: стража удержит, если её мощь
  дома не меньше мятежников по мерке жителя на стене (`VILLAGER_DEFENSE`).
- **Не удержала — склад делит `plunder`**, четвёртым случаем, а не своей арифметикой; уходят
  все невольники и доля горожан, последний житель не уходит никогда. Здания, дружина, казна и
  снаряжение остаются.
- **Тупика нет.** Отпустить часть («Племя») и продать торговцам (рынок) можно всегда и сразу; у
  окна мятежа два бесплатных выхода из трёх. Отпущенные жителями не становятся — иначе
  «купить и отпустить» было бы покупкой населения за золото.
- **Тон буднично, и держит его тест.** Все слова механики — в `data/order.ts`; тест читает
  его и разметку панелей на оценочные слова, на «штук», «голов» и «скот». Цена на рынке —
  «за человека». Новую строку о невольниках писать туда, а не в разметку.
- **У бота порядка и мятежа нет** («восстаний у соседей» не заводить); его невольники —
  доля людей, выведенная при чтении, и уйти могут только с победителем павшего города.
- **Версии сохранения механика не подняла** — новые поля приезжают умолчаниями, проверено по
  коду разбора и тестом. У мира версия тоже прежняя: в слепке (`PlayerProfile.bonded`) и в
  ждущем последствии (`HomeEffect.bonded`) поля необязательные и читаются только через `?? 0`.
- **Чего нет и что не надо доделывать по дороге:** восстаний у соседей, освобождения сверх
  «отпустить», невольников в предыстории, в войске и на службе, связи с верой, торговли ими
  между игроками. Увод невольников взятого города — ступень участи «увести людей» (см. «Карта
  мира»), а не своя механика порядка.

## Алмазы

Премиальная валюта — красный алмаз. Не ресурс и не золото: лежит в `s.gems`, склад её не
держит, набег не уносит.

- **Алмаз покупает время и ничего больше.** Мгновенная достройка (`rushUpgrade`) снимает
  ожидание, а ресурсы за уровень списываются как за обычную стройку — нетронутое здание
  оплачивает их тут же через `startUpgrade`. Пропуска ресурсов не заводить ни под каким
  видом: он обнуляет производство, склад и зиму для платящего игрока, а в будущем PvP
  превращает игру в чистый pay-to-win.
- **Цена достройки считается от оставшегося времени, а не от уровня** (`rushPrice`): остаток
  работы, приведённый к нормативной скорости `GEM_REF_RATE`, поделить на `GEM_SECONDS`.
  Нормативной, а не настоящей: иначе цена прыгала бы от того, кого игрок снял с площади,
  и её нельзя было бы повторить на сервере. К концу стройки цена падает до одного алмаза.
- **Начисление ровно одно на всю игру** — `creditGems` в `sim/gems.ts`, и оно требует расписки
  с источником `server`. Клиент такую не выписывает: покупка в Telegram Mini App идёт через
  Telegram Stars (счёт выставляет бот, подтверждает вебхук на сервере), сервера нет, поэтому
  витрина (`data/gems.ts`) показывает наборы, а кнопки не нажимаются, и об этом написано
  словами. Изображать покупку нельзя. Стартовый запас (`TEST_GEMS`) — тестовый и помечен
  таковым в интерфейсе.
- **Ни интерфейс, ни сцена, ни мир алмазы не начисляют.** Это не пожелание, а тест: `gems.test.ts`
  читает исходники `src/ui`, `src/render` и `src/world` и валится на любом `creditGems` и на
  любом присваивании `s.gems`.

## Коды проверки

Маленькая кнопка в правом нижнем углу — в деревне и в предыстории, — и за ней поле ввода.
Три кода: `tribe` (склад, казна, снаряжение, дружина), `glade` (очаг, руки, колчан), `home`
(дом достроен, гостья у огня, любовь полна). Разбор целиком, с тем, что каждый даёт и чего не
даёт, — [docs/cheats.md](docs/cheats.md). Здесь только то, что нельзя нарушить:

- **Это инструмент проверки, а не секрет, и говорить о нём надо так.** Код лежит в бандле
  обычной строкой и виден любому; слов «защита», «пароль» и «секретный» рядом с ним быть не
  должно. Игра длинная, и без этой двери дальний кусок пришлось бы каждый раз доигрывать руками.
- **Алмазов код не даёт и дать не может.** Замок по всему `src` (`game/sim/gems.test.ts`) стоит и
  над тремя файлами кодов, без единой строки исключения: они попали под него сами. Десятым
  обходом код не стал — он стал десятым файлом под замком.
- **Партия, где применяли код, помечена навсегда:** поле в сохранении (`s.cheated`, у поляны своё),
  строка в летописи, строка в «Заданиях» → «Служебное» и в родословной поляны. Метка нужна не
  игроку, а нам: накрученную партию через месяц примут за настоящую и сделают из неё вывод о
  балансе. Снимается она только новой партией.
- **Уровней зданий код не поднимает, жену не назначает и сына не называет.** Уровни — вся
  прогрессия посёлка, а жена и имя — два решения игрока; подставить их значило бы проверять свою
  же подстановку вместо игры.
- **Снимается всё одним действием** — `CHEATS_ON = false` в `src/cheats.ts`: кнопки нет нигде,
  набранный код не значит ничего, и правила стилей не применяются ни к чему. Перед тем как пустить
  посторонних, это надо сделать.

## Снаряжение и войско

- **Снаряжение** (`data/equipment.ts`) — счётчики в `s.equipment`, а не ресурсы. Вместимость склада
  на них не действует (полный склад молча остановил бы кузницу) и чужой набег их не уносит.
  Видны они всё равно на складе, отдельным разделом. Куётся всё с первого дня.
- **Кузница работает по заказам, а не по наряду.** Игрок заказывает десять мечей — кузница
  делает десять и встаёт. Очередь заказов одна (`s.forge`) и идёт последовательно, остаток
  работы переходит следующему заказу — тем же складом, что и набор в казармах. **Материалы
  списываются при постановке и целиком:** заказ, вставший посреди дела из-за пустого склада, —
  это потерянные часы, о которых игрок узнаёт, вернувшись; заплатив вперёд, он получает
  обещание. Скорость по-прежнему у кузнецов (`forgeRate`): заказ обещает сделать всё, а не
  сделать быстро. Отмена возвращает нетронутое целиком, начатый предмет — наполовину, как у
  брошенного улучшения. **Простаивающая кузница обязана быть видна**: маркер ⚒️ над крышей и в
  списке построек (`buildingAttention` = `order`), строка в панели, погасший горн в сцене и
  тревога в `AlertBar`. Кузница без людей при этом не «простаивает» — она пуста, и лечится это
  людьми. Летопись получает **одну строку на весь заказ**, а не строку на предмет. У строк
  заказа есть `data-tut="forge-<предмет>"`.
- **Войско** (`data/troops.ts`) — счётчики в `s.army`. Боец не житель с профессией: роли «воин» в
  `JobId` нет. Цена найма — ресурсы + снаряжение + один свободный житель + время учений; всё
  списывается сразу, как за стройку. Ушедшие на учения числятся в самом заказе
  (`RecruitOrder.people` — число), и отмена возвращает ровно столько же голов. У кнопки найма —
  `data-tut="recruit-<вид>"`. Скорость учений — `recruitRate`, и она растёт с уровнем казарм
  быстрее выработки зданий: дружину в сотни бойцов иначе не набрать.
- Очередь найма одна и идёт последовательно; остаток работы переходит следующему заказу.
- **Мощь армии считается из состава отряда** (`armyPower`) и ничем больше не множится: снаряжение уже
  вложено в вид бойца. Эту же мощь берёт карта мира через `soldierPower` в `world/bridge.ts`.
- Бойцы едят (`SOLDIER_FOOD`), но жилья не требуют: они живут в казармах. Дружина — главный
  сток еды, и это она делает зиму задачей.
- **Мастерская** — про стройку: ремесленники ускоряют улучшения (`crafterBuildRate`,
  `CRAFTER_BUILD`), других дел у неё нет.

## Золото и рынок

Золото есть с первого дня: стартовая казна, налог в ратуше и рынок у ворот.

- **Золото — не ресурс.** Оно лежит в `s.gold`, и вместимость склада на него не действует. Видно
  его там, где им пользуются, — в ратуше (казна и налог) и на рынке.
- **Казну уносит тот, кто взял город, — тем же правилом, что склад.** Прежнее «набег казну не
  уносит» отменено решением владельца (docs/DEFEAT_LADDER.md): казна входит в дележ восьмым
  припасом, тайник прячет столько же золота, сколько зерна, обоз поднимает золото наравне с
  добром. Следствие принято заранее: копить опасно всё, кроме снаряжения, и перековка добра в
  копья — лучший тайник в игре. Мятеж казну по-прежнему не трогает: у него нет победителя.
- **Налог** — просадка морали вычитается **после** приведения цели к шкале (`moraleTarget`): иначе
  в большом посёлке, где мораль и так упёрлась в потолок, налог не стоил бы ничего. Низкая мораль
  режет всю выработку, поэтому высокий налог выгоден в короткую, но не как уклад — тест сверяет,
  что за игровой год он приносит меньше, чем отнимает.
- **Рынок** (`data/market.ts`, `sim/market.ts`) — здание у ворот, одно, растёт уровнями.
  За золото покупаются ресурсы и снаряжение из ассортимента кузницы.
  Правило баланса одно: **покупать всегда заметно дороже, чем производить самому**. Держится оно
  на трёх ограничителях, и каждый проверяется тестом:
  1. цена не опускается ниже `selfCost × MIN_MARKUP` ни при каком уровне рынка — уровень добавляет
     запас и ассортимент, а цену первой единицы не трогает;
  2. дневной запас (`goodStock`) ограничивает, сколько уйдёт с прилавка за игровой день;
  3. цена каждой следующей единицы за день выше предыдущей (`PRICE_RAMP`), и считается она
     поштучно — дробление покупки не даёт ни лимита в обход, ни копейки скидки.
  **Партия на высоком уровне при этом дешевле, и так задумано:** рост цены считается долей
  дневного запаса, а запас растёт с уровнем. 30 еды за день стоят 385 золота на первом уровне,
  354 на пятом и 341 на десятом; первая единица — 10 на любом. Ниже черты из пункта 1 не
  опускается ни одна единица: рост цену только поднимает.
  Еда — самый дорогой товар и с самым жёстким запасом: дневного запаса не хватает, чтобы
  прокормить посёлок с дружиной, поэтому зима остаётся угрозой, а не строкой расходов.
- **Ассортимент нигде не хранится**: он выводится из номера игрового дня (`offerFor`), поэтому
  перезагрузка не тасует прилавок, а сервер потом получит тот же список из того же числа.
  В состоянии живёт только счётчик купленного за день (`s.market`).
- **Караван** (`s.caravans`). Золото списывается сразу, груза на складе нет, пока телега не
  вернётся из ворот: в сцене она едет по главной улице (`render/caravan.ts`). Отмена возвращает
  золото целиком и освобождает дневной запас.
- **Невольничий ряд — строка того же прилавка, а не вторая лавка.** `BONDED_GOOD` в общий
  `GOODS` не входит и в круговороте дня места не занимает: `marketOffer` приставляет его к
  прилавку последней строкой всегда — продажа невольников рычаг против мятежа, а рычаг через
  день рычагом не является. Покупка идёт тем же караваном, дневным запасом и ростом цены.
  Продажа — единственная продажа на рынке: за `BONDED_SALE` цены (без роста) и не больше
  дневного запаса (`bondedSaleLeft`, счётчик `s.market.sold`), так что купить и продать —
  отдать разницу торговцам. Правило «покупать дороже, чем делать» к людям не применимо
  (`selfCost` у них 0); вместо него — окупаемость не быстрее `BONDED_PAYBACK_DAYS`, и это тест.
- **Золото идёт тремя ручьями, и замков среди них нет:** налог в ратуше, десятина прихода (у
  католиков — той же дверью `taxIncomePerDay`) и продажа невольников на рынке. Золото из
  казны замка (`Loot.gold`) — механика спящая: поселения мира сейчас одни логова, и казны у
  них нет (см. «Карта мира»).
- **Второй выход у золота — пир в трактире.** `feastInfo`/`throwFeast`: плата по числу ртов,
  прибавка морали на `FEAST_DAYS` дней, откат сокращается уровнем. Прибавка ложится **после**
  приведения морали к шкале, там же, где вычитается налог: постоянных источников морали в
  посёлке на потолке уровней и так больше, чем вмещает сотня, и ещё одно слагаемое до
  `Math.min` не стоило бы ничего. Так пир отыгрывает просадку от налога, голода, тесноты и
  холода — и ни разу не переполняет шкалу. Третий выход — смена рода войск у героя.
- Интерфейс рынка — две вкладки: закупка у проезжих торговцев и место под торг между игроками.
  Торга между игроками нет и не должно появиться до сервера.

## Проводка первых шагов

Новичок видит готовый посёлок, и ему негде прочитать правила: полосы ресурсов нет, данные спрятаны
в здания. Поэтому первая партия ведётся за руку — `game/data/tutorial.ts` (шаги) и `ui/TutorialOverlay.tsx`
(строка и «дырка» в затемнении). Путь — вокруг того, про что игра: тапнуть кузницу → поставить
кузнеца → заказать копья → открыть ратушу → найти казармы в списке построек → нанять
копейщика (строка объясняет ожидание, пока копьё куётся) → открыть карту → тапнуть соседа →
отправить разведку.

- Ни одного шага без действия игрока: экранов с «Далее» нет, шаг закрывается настоящим тапом
  в настоящем интерфейсе. Исключение — строки-заставки в начале и в конце, они закрываются тапом
  в любом месте.
- Шаг засчитывается по факту (`done(s, ui)`), а не по порядку: нанял бойца до просьбы — шаги про
  наём проматываются. Условие пишется щедро, чтобы игрок не застрял на уже сделанном.
- Обучение видит интерфейс (`TutorialUi`): открытую панель здания, раздел навигации, открытую
  карту и карточку клетки. Слой рисуется и поверх карты; разведка засчитывается по
  `s.scoutsAway`, который мир проставляет на пульсе.
- Симуляция не останавливается. Слой ничего не перехватывает: затемнение — это тень самой «дырки»
  (`box-shadow` наружу), у неё `pointer-events: none`.
- Подсветка здания считается проекцией из 3D (`TribeScene.screenSpot`) каждый кадр — она не отстаёт,
  когда камеру ведут или приближают. Подсветка интерфейса ищется по `data-tut`.
- Прогресс живёт в сохранении (`tutorialStep`, `tutorialDone`), а не в отдельном ключе localStorage.
- Пока обучение идёт, `tick` придерживает случайные события — но не дольше `TUTORIAL_EVENT_MUTE`,
  иначе брошенное на середине обучение выключило бы их навсегда.
- Отладка: «Задания» → «Служебное» → «Пройти обучение заново».

## Визуальный рост зданий

Уровень виден в сцене, иначе он остаётся числом в панели.

- Три ступени на здание: уровни 1–3, 4–7, 8–10 (`VISUAL_TIERS`, `visualTier`). Каждая следующая заметно
  крупнее и подробнее: у Жилищ прибавляется двор, потом ещё два; у рудника — копёр, потом
  колесо и рельсы; у ратуши — палата, потом донжон с зубцами; у стены — камень, башни, стяг.
- Внутри ступени постройка ещё подрастает масштабом (`levelScale`), а весь посёлок ужат общим
  множителем плана `PLAN_SCALE`: модели рисовались под прежнюю вольную расстановку и для кольцевого
  посёлка велики. Стена — исключение: она и есть это кольцо, её масштабировать нельзя.
- Стиль один на всю игру — позднее средневековье: `ROLES` (какие цвета палитры у ролей: штукатурка,
  черепица, каменный цоколь) и `FEATURES` (черепичная кровля, каменная труба, окна, фахверк,
  пологая крыша) в `render/buildings.ts`. Материалы старых моделей — `STYLE`, краски набора
  деталей — `stylePaint()`. Новый материал крыши надо добавить и в `render/season.ts`, иначе
  зимой он не побелеет. То же для новых материалов дорог и разметки.
- Модель пересобирается только при смене ступени — не на каждом уровне.
- Улучшение модель не трогает: вокруг неё появляются леса (`scaffold`), здание работает, рабочие
  ходят туда же. Этапов стройки (площадка, каркас) нет — строить с нуля нечего.

## Графика: палитра, свет, набор деталей

Стиль — low-poly с плоским затенением, без текстур. Качество делают свет, цвет и посадка в землю,
а не полигоны. Четыре модуля держат это, и правила у них жёсткие:

- **Палитра** (`render/palette.ts`) — единственное место с hex. Все материалы (`render/materials.ts`)
  и сезонные переопределения берутся из неё по имени; цвет «по месту» — ошибка. Чистого белого и
  чёрного нет ни в одном канале, кроме огня и источников света (`palette.test.ts`). Сезон не заменяет
  палитру, а переопределяет её часть (`SEASON_OVERRIDES`): снег ложится на то, что лежит горизонтально —
  землю, кроны, кровли, дороги, — а стены, столбы, цоколь и металл остаются собой. Новый материал,
  на который ложится снег, обязан попасть в переопределения зимы.
- **Материалы** — три набора: `KIT` с цветом вершин для склеенной геометрии, `LEGACY` без него для
  старых моделей, `DECAL` для наложений на землю. Материал с `vertexColors`, получив геометрию без
  атрибута `color`, красит её чёрным — наборы не смешивать; `kit.test.ts` проверяет инвариант
  на всех моделях всех ступеней.
- **Свет** (`render/lighting.ts`) — один тёплый направленный источник с тенью, слева-спереди от
  стартовой камеры и никогда в зените (52° в полдень), холодная полусфера сверху и тёплая снизу,
  `NeutralToneMapping`. Синева теней получается сама: в тени поверхность видит только полусферу.
  Второй источник с тенью не заводить. Ночью та же лампа становится луной. Риг общий для игры и
  стенда — иначе снимки со стенда ничего не доказывают. Всё, что не должно тонмапиться (маркеры,
  кольцо выбора, огонь, снег), помечается `toneMapped: false`.
- **Набор деталей** (`render/kit.ts`) — здание собирается из общих деталей (стена, цоколь, конус и
  двускатная кровля, столб, крыльцо, труба, дверь, окно, фахверк, ограда) и склеивается в
  один меш: группы по материалу, один вызов отрисовки на материал. Несезонные детали пекут цвет
  палитры в вершины на общем «теле» (`KIT.body`), сезонные (кровля, пашня) — настоящие материалы,
  чтобы их переливал сезон. В вершины запекается и контактное затемнение у земли — множитель с
  уходом в синеву (`AO_*` в палитре); под зданием лежат декали вытоптанной земли и умножающего пятна
  тени (`village.groundDecals`). Состав набора задан один раз — `ROLES` и `FEATURES`.
  Правила размеров на телефоне: столб r ≥ 0.09, труба ≥ 0.32 и квадратная, дверь ≥ 0.42, свес ≥ 0.3;
  окна только на стенах шире 1.8. Ступень меняет тип силуэта (число масс и ширину).
  Переведены пока Жилища; остальные модели живут в старом коде до раскатки, но уже **склеены**:
  `K.collapse` превращает готовую группу мешей в один меш по правилам набора (материал по
  имени → краска палитры, мировая матрица запекается в геометрию, вызов на материал, контактное
  затемнение `GROUND_AO`). Именованные меши (пламя костра), светящиеся (огонь, горн) и уже
  склеенные остаются отдельными. Той же склейкой собраны стена, леса стройки, окружение, дороги
  и декор посёлка. Новая старая модель без склейки — ошибка: вызовов у неё будет по одному на доску.
- **Фигурки** — горожане, восемь видов войск, герой и кони: инстансы, семь примитивов, одиннадцать
  вызовов на всех. Пропорции, силуэты, позы, бюджет и запреты — в [docs/figures.md](docs/figures.md).
  **Чем боец вооружён, фигура не решает.** Оружие в руках, щит и ступень снаряжения выводятся из
  `TroopDef.gear` в `data/troops.ts` — из того же поля, по которому карточка вида называет предметы
  ковке (`weaponOf`, `hasShield`, `hasArmor`, `gearOfTroop` в `game/battle/kinds.ts`). Второй
  таблицы «у щитоносца щит, у лучника лук» в сцене быть не должно: две правды об одном бойце
  расходятся молча и ровно тогда, когда снаряжение вида меняют. Держит это тест
  «снаряжение вида — один источник на карточку и на фигуру» в `render/units.test.ts`: он правит
  `gear` в конфиге и требует, чтобы правка дошла и до текста карточки, и до набора деталей.
  Герой одевается тем же `dressSoldier` по виду того рода, который ведёт; своего у него только
  рост и плащ.
- **Земля** (`render/terrain.ts`) — полярная сетка, ровная внутри расчистки (здания, дороги, стена
  и бойцы на y = 0), с рельефом и чашей за ней (`groundHeight` — чистая функция, детерминированная
  по сиду). Пятна травы и вытоптанность внутри стены — множители в цвете вершин, поэтому зимой они
  же дают сине-серые тени на снегу. Всё, что ставится за расчисткой (окружение, жители, снежинки),
  берёт высоту из `groundHeight`.
- **Стенд** (`render/showcase.ts`, `?showcase=building|village`) — ряд здания по ступеням
  (`type=hut&tiers=0,1,2`) или посёлок заданного уровня (`levels=10`, все постройки разом;
  `buildings=hut:10,smithy:3` правит отдельные); силуэтный режим, честный счёт вызовов с теневым
  проходом (`info.autoReset = false`), снимок в файл через `?snap=имя` → `snaps/`. Бюджет: посёлок
  на потолке — ≈150 вызовов и ≈70k треугольников (лес и тени), потолок — 450 вызовов. Частота
  кадров меряется на телефоне: `?perf=8` крутит камеру восемь секунд и шлёт итог на dev-сервер
  (`POST /__perf` → `snaps/perf.jsonl`); открывать стенд с телефона по адресу машины в локальной
  сети (`vite --host`). Меняешь модель или свет — снимай стенд, не описывай словами.
  **Стенд собирается и в продакшен** — это инструмент, а не отладочная ветка: гейта по
  `import.meta.env.DEV` у него нет и заводить его нельзя, иначе на выложенном адресе
  замерить телефон будет негде. В продакшене адресов `/__perf` и `/__snap` не существует:
  тогда итог замера остаётся на экране, а тап по подписи кладёт отчёт целиком в буфер обмена.
  В игру стенд не попадает — он лежит отдельным чанком и грузится только по `?showcase=`.

## Значки интерфейса

Двумерный слой переезжает с эмодзи операционной системы на нарисованный набор — 192
значка тремя очередями. Техзадание художнику — [docs/ART_HANDOFF.md](docs/ART_HANDOFF.md),
как очередь попадает в игру — [docs/icons.md](docs/icons.md).

Правило, из которого следует всё: **значков всегда меньше, чем мест, где нужен значок**.
Есть картинка — показываем картинку, нет — остаётся эмодзи, и решается это в одном
месте (`ui/icons/Icon.tsx`), а не проверкой в каждом компоненте. Файлы кладутся в
`assets-src/icons/`, `npm run icons:build` их проверяет, сверяет имена **с данными
игры** и собирает лист `public/assets/icons/sprite.svg`; сборка падает на лишнем, на
недостающем и на браке формата. Список значков нигде не пишется руками. Брак не
правится у себя — он возвращается автору, а его имя лежит в `assets-src/icons/RETURNED.md`.

## Палец: тап по зданию и обзор деревни

Диорама и карта мира — два холста одной игры, а палец один. Числа жестов поэтому
записаны в **одном месте** — `src/gestures.ts` (лежит вне `ui/` и вне `render/` по
той же причине, что и `debug.ts`: нужен обоим).

- **Разбор жеста общий у деревни и карты — `Gesture`, и второго быть не должно.**
  Общее не только число: «тап это или ведение» судит один класс, а что тап значит,
  каждый холст решает сам (деревня — здание под нажатием, карта — клетку под
  отпусканием). Раньше разбор был написан дважды, и копии успели разойтись: карта
  снимала тап при втором пальце, деревня — перебивала им первое нажатие, и палец,
  мигнувший посреди ведения, открывал здание под первым.
- **Команду «камера, поехали» даёт тот же разбор — `Gesture.panning`, и второго
  судьи у камеры быть не может.** Сами камеры общими быть не могут, и сводить их не
  надо: у диорамы перспективная камера, у карты плоское аффинное преобразование со
  своими `panBy`/`zoomAt`. А вот момент, с которого картинка едет, обязан быть
  один — иначе получается ровно то, что было в деревне: `OrbitControls` брал
  `pointerdown` себе и начинал панораму с первого же пикселя, пока разбор ещё считал
  жест тапом. Сначала у него отобрали ввод, а с уходом поворота убрали и его самого:
  зажимать наклон стало нечего, приближение зажимает щипок по `zoomRange`, а позицию
  камеры целиком считает `Scene.place()` из четырёх своих чисел (цель, наклон,
  расстояние, единый на игру `AZIMUTH`). Держит это тест по исходнику
  (`render/camera.test.ts`, читает код без комментариев).
- **Панорама деревни — один к одному, как на карте.** Взяли землю лучом в той точке,
  где лёг палец, и держим её под ним (`Scene.groundAt`/`pan`). Прежняя панорама
  `OrbitControls` считала сдвиг линейно от дистанции до цели и по вертикали отставала
  от пальца на треть: замер настоящим касанием — палец 90 px, земля 61 px. Вот эту
  разницу игрок и называл «в деревне камера не такая, как на карте».
- **Тап бывает только одним пальцем.** Второй палец на экране — это щипок, и тапа в
  этом жесте больше нет ни у одного из пальцев, даже если второй тут же сняли.
- **Тап судится по пути, а не по точке отпускания.** Точка отпускания в счёт не идёт
  вовсе, и это не мелочь: на телефоне пятно контакта схлопывается несимметрично, и
  сообщённый системой центр прыгает на 20–25 px — мышь так не умеет. Прежнее правило
  сравнивало нажатие с отпусканием и отбрасывало 78–88% тапов молча; возвращать это
  сравнение нельзя.
- **Два порога, два разных смысла, и часов между ними нет.** `TAP_MOVE` (10 px) —
  камера пошла за пальцем; `TAP_SLIP` (32 px) — тапа в этом жесте больше нет. Между
  ними картинка уже едет, а тап ещё жив, и противоречия тут нет: панорама идёт один к
  одному, значит на тридцать два пикселя картинка уезжает ровно настолько, насколько
  прошёл палец, а палец при этом остаётся на той же постройке (`TAP_SLIP` меньше
  `TAP_TARGET` — на этом стоит тест).
- **Выдержки `TAP_SETTLE` больше нет, и возвращать её нельзя.** Она держала тап между
  порогами только 90 мс с первого схода, а дальше защёлкивала ведение — и этим терялся
  тап на телефоне. Замер настоящим касанием (не синтетическим событием): палец, ложась
  на экран, проезжает 14–20 px в первые 60–80 мс — пятно контакта растекается, пока
  подушечка садится, — и потом лежит неподвижно ещё 200–400 мс, пока игрок целится. К
  снятию выдержка давно истекала, и обычный человеческий тап отбрасывался молча.
  Прежний стенд этого не видел: он моделировал сход **только перед снятием**, а
  единственную свою строку про ранний сход подписывал «медленное ведение» и ждал от
  неё нуля. Цена обратной ошибки несравнима: панель, открывшаяся после сдвига в
  двадцать пикселей, закрывается одним касанием, а тап, не открывший ничего, игрок
  повторяет вслепую и решает, что игра сломана.
- **`TAP_MS` — 700 мс, и это тоже была причина, а не запас.** Прежние 350 мс: замер
  на живой сцене давал 21 из 21 при 340 мс и **ноль из 21** при 420 мс, а прицелиться
  в постройку размером с палец дольше трети секунды — обычное дело. У самого браузера
  предела на длительность `click` нет вовсе, системное долгое нажатие начинается с
  500 мс. Отдельного жеста «долгое нажатие» в игре нет и заводить его нельзя: иначе
  это число придётся делить с ним, и тап снова начнёт теряться.
- **Мышь — такой же ввод, как палец, и колесо у деревни своё.** Оно жило в
  `OrbitControls` и пропало вместе с ним молча: на телефоне щипок работал, а на ПК
  деревня перестала приближаться совсем, и стенд этого не видел — он умел только
  касания. Теперь колесо слушает сама сцена (`Scene.onWheel`), шаг общий с картой
  (`WHEEL_STEP` в `src/gestures.ts`, 1.12 за щелчок), читается только **знак**
  `deltaY` — величину браузеры отдают то в пикселях, то в строках. Пол и потолок —
  те же, что у щипка, из `zoomRange`. Стенд следа пальца проверяет колесо, ведение
  мышью и клик отдельным разделом «МЫШЬ (ПК)» настоящими событиями CDP.
- **Приближение идёт туда, куда смотрят, — и у мыши, и у пальца.** Земля под
  курсором (под серединой между пальцами) остаётся на месте: `Scene.zoomTo` — то же
  правило и тот же луч, что у панорамы, и то же, что делает карта (`zoomAt` в
  `ui/map/grid.ts`). Второго способа приблизить сцену нет: и колесо, и щипок ходят
  через `zoomTo`.
- **Поворота камеры нет никакого — ни одним пальцем, ни двумя, и возвращать его
  нельзя.** Одним пальцем камера **водит**, двумя — приближает (`Scene.pinchZoom`), и
  это ровно те же два жеста, что на карте. Поворот был третьим, двумя пальцами, и
  убран по жалобе с телефона: щипок и поворот живут на одном движении пальцев, поэтому
  наезд постоянно сбивал ракурс, а смотреть на кольцевой посёлок с другой стороны не
  за чем — планировка симметрична, ворота нарочно смотрят в камеру. Убран **жест
  вместе с состоянием**: ушли `ROTATE_SPEED` и `orbitDelta` из `render/camera.ts`,
  хранение азимута в сцене, середина между пальцами в щипке и сам `OrbitControls`.
  Угол теперь один на всю игру — `AZIMUTH` в `render/camera.ts`, из него же выведен
  угол ворот, и стенд-витрина берёт его оттуда же. Середина между пальцами при этом
  вернулась, но за другим делом: за ней едет земля и к ней идёт наезд — ровно как на
  карте. Единственный оставшийся поворот —
  автоповорот стенда (`Scene.spin`, `?showcase=village&perf=8`): им меряют частоту
  кадров, и игроку он не достаётся ничем.
- **Целятся нажатием.** Здание выбирается в момент `pointerdown` и открывается на
  отпускании: сообщённая системой точка на отпускании прыгает, а игрок целился в
  момент нажатия. Отсюда важное: **прицел никогда не считался по сдвинувшимся
  координатам** — `aimed` берётся до первого `pointermove`. Когда тап терялся, дело
  было не в попадании: `pick` находил ту самую постройку, а приговор «это ведение»
  отбрасывал её после. Искать причину пропавшего тапа надо в разборе жеста, а не в
  областях попадания.
- **Попадание по силуэту, а не по мешу.** У каждого здания своя невидимая область —
  описанная коробка модели, спроецированная на экран (`render/pick.ts`), — накрывающая
  постройку целиком, и основание, и высоту. Тонкая геометрия ранних ступеней тапу не
  мешает. Рейкаста по сцене здесь нет и заводить его не надо.
- **Область не меньше пальца.** На 390 px силуэт здания первого уровня занимает
  7–27 px, то есть меньше отпечатка; область раздувается до `TAP_TARGET` (44 px) —
  той же величины, что `--tap` в стилях. Держит это тест.
- **Промах прощается** в `TAP_FORGIVE` (26 px): не попал никуда, но рядом дом —
  открывается дом, при нескольких рядом ближайший. Тап в чистое поле не открывает
  ничего. Внутри области мерка нормирована на её размер: попал в самую середину
  мелкой постройки — её и открыли, раздутый сосед этого не перебьёт.
- **У стены области нет и быть не может**: её силуэт — весь посёлок, любая коробка
  съела бы каждый тап внутри кольца. Её спрашивают последней и по-своему: тап
  опускается на землю и меряется до кольца (`pick.onRing`).
- **Подсветка обучения считается тем же кодом** (`screenSpot` берёт ту же область):
  «тапни кузницу» и «попал в кузницу» обязаны совпадать.
- **Журнал касаний читается с телефона** — `src/gestlog.ts`, экран «Задания» →
  «Служебное» → «Что было под пальцем», кнопка «Скопировать». Пишут в него оба
  холста, и это главное: жалоба звучала как «на карте работает, а в деревне нет», а
  сравнить их можно только в одном списке. На касание записываются число пальцев,
  длительность, самый дальний сход, длина пути, исход и то, на сколько уехала
  картинка. Прибор честный, как и журнал сцены: чего не измерил — пишет «не знаю»,
  причину не называет. Нужен он ровно для того, чего стенд не воспроизводит, — для
  перехвата жеста вебвью Телеграма и прочего, что живёт только на устройстве.

### Стенд следа пальца

`npm run tap:report` (`scripts/tap-report.ts`) поднимает настоящую игру в headless
Chrome на 375×812 и гонит след пальца по каждой постройке. Печатает четыре таблицы:
силуэт и область попадания у каждой постройки, матрицу «сход × **когда** он
случился» — сколько построек открыло свою панель, — ту же матрицу про сдвиг деревни
под пальцем, длительность касания и прочее: ведение, щипок двумя пальцами, тап в
чистое поле, тап по кладке стены. `LEVEL=10` поднимает посёлок: у моделей другая
визуальная ступень и другой силуэт. Ни одного своего числа о геометрии в стенде
нет: где здание на экране, он спрашивает у самой сцены.

**Палец здесь настоящий, и это условие, а не подробность.** Ввод идёт
`Input.dispatchTouchEvent` через CDP при включённой тач-эмуляции — тем же путём, что
и живое касание: настоящие `pointerId`, настоящий захват указателя, настоящая
склейка движений кадрами. Часы тоже настоящие, и прогон поэтому идёт минуты, а не
секунды. Перед каждым следом стенд спрашивает у страницы, свободна ли точка
касания (`document.elementFromPoint` — это канва?), и ждёт, пока уедет шторка от
предыдущего следа: пока она едет, касание достаётся ей, а не деревне, и таблица
начинала зависеть от того, что открылось строкой выше. Не дождался — говорит об
этом строкой, а не молча считает такой след промахом.

**Прежний стенд врал двумя приёмами сразу, и оба выглядели экономией.** Он подавал в
канву `new PointerEvent(...)` — и, поскольку синтетический `pointerId` браузеру
неизвестен, вынужден был глушить `setPointerCapture`, то есть выключать кусок
настоящего пути. И он подменял часы виртуальными, чтобы след шёл мгновенно. Оба
приёма позволили третьему, главному: след моделировал сход пальца **только перед
снятием**. Живой палец так себя не ведёт — ложась, он растекается в первые 60–80 мс
и потом лежит неподвижно. Единственная строка стенда про ранний сход была подписана
«медленное ведение» и ждала нуля. Отсюда «21 из 21» при потерянном каждом втором
тапе на телефоне. **Ось «когда» — то, чего не хватало; убирать её нельзя.**

**WebGL при этом по-прежнему нет.** Контекст канвы подделан заглушкой, которую
скрипт подкладывает странице сам (плагин dev-сервера, в игру он не попадает): three
поднимается целиком, сцена собирается, камера кадрируется, области попадания
считаются — а рисования не происходит. Это первый способ проверять **поведение**
сцены там, где GL недоступен вовсе.

**Это стенд, а не тест: он ничем не падает, таблицы читаются глазами.** Правила
разбора жеста держат юнит-тесты (`gestures`, `gestlog`, `pick`, `render/pick.test.ts`,
`render/camera.test.ts`), а числа, которых из правил не выведешь — настоящая камера,
планировка, модели, живой ввод, — видны только здесь.

Раздел «МЫШЬ (ПК)» в конце — про то, чего у телефона нет вовсе: колесо, ведение с
зажатой кнопкой и клик, настоящими `Input.dispatchMouseEvent` и со снятой тач-эмуляцией
(с ней Chrome отдаёт мышь странице не тем путём). Он появился после того, как колесо
пропало из деревни вместе с `OrbitControls`, а стенд остался зелёным: раздела про мышь
у него не было.

Чего он **не** меряет:

- **не рисунок** — кадра нет вовсе, поэтому **снимки с него чёрные**; за внешним
  видом — на стенд `?showcase=` и в `snaps/`;
- **не разметку** — касания идут в точку экрана, но двумерный слой в счёт не входит
  (поверх канвы в игре только «дырка» обучения с `pointer-events: none`);
- **не быстродействие** — кадров нет, мерить нечего; бюджет кадра — на стенде витрины;
- **не вебвью Телеграма** — это Chrome, а не он. Перехват жеста клиентом здесь не
  воспроизвести ничем, и на такой случай в игре стоит журнал касаний («Задания» →
  «Служебное» → «Что было под пальцем»). **Зелёный стенд проверкой на устройстве не
  является и заменять её не может.**

Обзор деревни отпущен и водится **как карта мира: один палец ведёт, щипок приближает,
колесо мыши приближает к курсору**.
Разные жесты в двух местах одной игры игрок не прощает — а теперь они и не разные:
третий жест диорамы, поворот двумя пальцами, убран совсем. Ограничители —
`render/camera.ts`, чистые числа:

- **привязка к деревне** (`PAN_LEASH` = `OUTSKIRTS_RADIUS`): центр экрана доходит до
  самого дальнего двора и ни на шаг дальше — за окрестностями только лес;
- **пол приближения** — 0.28 кадровой дистанции: ближе видно нутро моделей, дальше
  здание не дорастает до пальца (при кадровой дистанции оно 20 px);
- **потолок отдаления** не выпускает застройку в туман: он не просто доля кадра, а
  обещание, что дальний край посёлка останется по эту сторону `fog.far`.

## У костра стоят свободные руки

Ходьбы на работу и обратно нет и не должно появиться. Она стоила дорого — путь, поворот,
покачивание на каждого работника каждый кадр — и не сообщала ничего: на 390 px не видно, кто куда
пошёл. Хуже, она давала обратный смысл: чем лучше идут дела, тем пустее деревня, потому что все
разошлись по углам.

- **На площади видно свободные руки.** Сколько их — считает `idleCount`; фигурка ничья (агент не
  привязан к человеку, потому что людей поимённо не существует), назначенный на работу со сцены
  исчезает, снятый возвращается (`render/villagers.ts`, `Scene.sync`).
- **`MAX_VILLAGERS` (10) и `MAX_SOLDIERS` (14) — потолки показа, а не потолки племени.** При
  населении в сотни толпу всё равно не сосчитать, а рисовать её дорого: сцена показывает не больше
  десятка фигурок у костра и полутора десятков дружины, точное число стоит в строке состояния и в
  «Племени». Снимать эти потолки нельзя.
- **Занятость показывает здание, а не человек** (`render/worksigns.ts`, таблица `WORK_SIGN`).
  Признак загорается, когда в здании есть рабочие, и гаснет, когда их нет: груз у стены (лежит один
  тюк, второй ходит вверх-вниз), дым из трубы, горн у кузницы. Ходьбы и поиска пути нет.
  Склад — единственное исключение из правила «есть рабочие»: их у него не бывает вовсе, поэтому
  мешки он показывает по запасам (`STORAGE_SHOWN`).
- Цена всего этого — два вызова отрисовки: один на все грузы разом (инстансы, цвет через
  `instanceColor`) и один на весь дым труб (точки). Горн был в модели кузницы и раньше — он просто
  гаснет без кузнецов, поэтому его имя `forge` нельзя менять: по нему сцена его и находит.
  Дым очага и дым труб — две системы точек, а не одна: размер и плотность у точек задаются
  материалом, то есть одни на всё облако, а трубе нужна заметнее очага (`FIRE_LOOK`/`CHIMNEY_LOOK`).
- Проверять глазами: `?showcase=village&levels=10` — посёлок укомплектован, у костра
  пусто, у дворов груз и дым; тот же адрес с `&workers=none` — все руки свободны, у костра десяток,
  признаков работы нет ни у одного здания.

## Музыка

Мирная музыка деревни и боевая под ролик. Дорожки лежат в `public/assets/music/`, собирает их
`npm run music:build` из паков в `assets-src/` (что откуда взято и по какой лицензии —
`assets-src/MUSIC.md`; паки в репозиторий не едут, 718 МБ WAV). Машинки — в `src/sound/`:
`village.ts` (круг деревни), `music.ts` (слои боя), `web.ts` (среда), `manifest.ts` (список и
режим), `settings.ts` (переключатель).

- **Деревня играет по кругу**: четыре пьесы, порядок перемешан, между соседними перелив
  (`VILLAGE_FADE`), одна и та же дорожка не идёт дважды подряд — стык кругов тоже стык.
- **Вес — главное ограничение, и правила структурные, а не на слово.** Потолок всей музыки —
  **4.5 МБ** (`WEIGHT_CAP` в скрипте сборки, сейчас занято 3.45 МБ), и скрипт валится, если
  сборка в него не влезла. В бандл не попадает ни байта звука: файлы берутся по адресу, а не
  импортом. Качается **ровно одна дорожка за раз**, следующая — за `VILLAGE_LEAD` (12 с) до конца
  текущей и никогда раньше. Без жеста игрока не грузится ничего; выключенный звук не грузит вовсе —
  не «грузит и не играет», а не грузит.
- **Формат — mp3, моно, 72 кбит/с.** Не ogg и не opus: их не играет Safari на iPhone, а вебвью
  Telegram на iOS — это он. Заводить второй формат нельзя: он означал бы либо запасной путь в
  коде, либо 404 на каждой загрузке.
- **Музыка по умолчанию выключена, и рычаг на неё один** — строка «Музыка» в разделе
  «Настройки» (`ui/parts/Settings.tsx`). **Компонент один, показан он в двух местах**:
  разделом в профиле (аватар в шапке ведёт туда) и окном на стартовом экране. Копии
  разметки нет, и копии состояния нет тоже: флажок читается подпиской у самой настройки
  (`subscribeSound` + `useSyncExternalStore`), а пишет его по-прежнему одно `setSoundOn`.
  Пока каждый показ держал своё `useState`, «одно состояние» держалось на том, что два
  показа не бывают на экране разом, — то есть на совпадении. У нового
  игрока не качается ни байта, пока он сам не включит: игру открывают где придётся, и
  заигравшая без спроса музыка — не подарок, а неожиданность, которую гасят вместе со
  вкладкой. Второго переключателя быть не должно ни в каком месте: он стоял в ролике о бое,
  рядом с «Пропустить», и убран оттуда целиком — два способа включить одно и то же расходятся
  ровно тогда, когда правят один из них. Держит это тест по исходникам (`sound/music.test.ts`,
  «рычаг на музыку один на всю игру») — и читает он целиком `src/ui`, `src/prologue` и
  `src/sound`, а не список файлов: список ловит только те файлы, о которых подумали.
- **Флажок один на деревню, бой и вой волка в предыстории.** Игрок слышит «музыку», а не три
  подсистемы. Разделять их на переключатели не надо: это лишний выбор в первую минуту. Вой
  спрашивает настройку на каждом вое, поэтому настройкам про волков знать не нужно — и они не
  знают. Появятся звуки другого рода — щелчки, оповещения — тогда и разделим, по надобности.
- **Включение — само по себе жест**, и звуковой контекст открывается прямо в обработчике
  нажатия (`villageMusic.toggle(true)`); `await` в этом обработчике запрещён — активация
  теряется. Боевую музыку включение **не заводит**: у неё свой жест, «Смотреть бой», а качать
  `battle.mp3` из настроек значило бы платить мегабайтом за нажатие, которое о бое не просило.
  Выключение гасит обе.
- **Первое нажатие в интерфейсе тоже годится за жест** (`pointerdown` в `App.tsx` →
  `villageMusic.arm()`): оно поднимает круг деревни у того, кто музыку уже включал. Слушатель
  после первого раза не снимается нарочно — при выключенном звуке `arm` не делает ничего, и
  нажатие после включения обязано сработать.
- **Ролик о бое деревню глушит, а не останавливает** (`villageMusic.duck`): круг идёт под роликом
  и возвращается после, и это не стоит ни одной загрузки. Останавливать значило бы платить за
  каждый бой лишним мегабайтом.
- **Контекст один на всю игру** (`Engine` в `web.ts`): обе музыки и вой волка. На iOS каждый
  `AudioContext` — отдельный аппаратный поток, который вебвью усыпляет по своему усмотрению; два
  контекста означали бы, что звуки засыпают врозь и просыпаются врозь. Второй заводить нельзя.
  Звук, живущий в другом чанке, берёт у движка только выход — `openBus`.
- **Громкость дорожек выровнена при сборке** по EBU R128 линейным усилением, а не динамическим
  `loudnorm`: в перемешанном круге пьесы не должны прыгать по громкости, но и дышать от
  компрессии музыке нельзя.
- Настройка звука живёт в **localStorage**, а не в сохранении: сохранение уезжает на сервер и
  притащило бы громкость на все устройства. Версию сохранения переключатель не поднимает.
- Код машинок **нельзя грузить лениво через `import()` из обработчика жеста**: `await` теряет
  пользовательскую активацию, и звук после жеста уже не откроется. Приехать вместе с экраном,
  который её зовёт, машинке можно — к жесту она уже в памяти: так едет вой чанком предыстории.

## Планировка поселения

Автоподбора свободного места нет. У каждого типа здания своё **именованное место** на круговой
планировке — `render/plan.ts`, чистые числа без three.js, чтобы их можно было проверить тестом.

- Кольца от центра: площадь (костёр и колодец) → ратуша, Жилища, церковь, Статуя Героя →
  склад, мастерская, кузница, казармы, рынок у ворот → службы посёлка (лазарет, дозор, конюшня,
  тайник, трактир) → **стена** → ресурсные дворы (лесопилка, каменоломня, навес собирателей,
  охотничий домик, ферма, загон, рудник) → угодья.
- **Производство стоит за стеной, и это не косметика.** Четвёртое кольцо (`OUTSIDE_RING`,
  `isOutside`, `OUTSIDE_BUILDINGS`) лежит снаружи: поле, каменоломня и штольня стоят там, где
  ресурс. Отсюда всё остальное — набег дотягивается ровно до этих зданий и ни до каких других
  (`sackOutskirts`), а внутри стены сидят жильё, власть, ремесло, склад и службы. Стена получает
  настоящую работу, нападение — смысл помимо кражи со склада.
- **Радиус стены задан раз и навсегда** (`WALL_RADIUS`), и место под каждое здание зарезервировано по
  габаритам его **третьей визуальной ступени на десятом уровне** (`MODEL_RADIUS` × `PLAN_SCALE` ×
  `levelScale(10)`). Иначе к концу партии крыши вылезут за стену и друг на друга.
- Кольца идут в шахматном порядке: второе смещено на полшага от первого, третье — от второго. Ворота
  приходятся на просвет первого кольца и на пустое место второго, поэтому главная улица ни во что не
  упирается. Углы записаны числами: место здания — факт, который должно быть видно глазом в таблице.
- Каждое здание развёрнуто фасадом к центру (`facingCenter`): перёд модели — её `+z`.
- Ворота всегда в одном месте и смотрят в камеру при стартовом ракурсе (`GATE_ANGLE` выведен из
  азимута камеры). Кадр камеры привязан к `FRAME_RADIUS`, а не к постройкам (`Scene.applyFraming`):
  с дворами за стеной кадрировать по кольцу укреплений нельзя — половина хозяйства уехала бы
  за край экрана. Коробка теней накрывает всю застройку (`OUTSKIRTS_RADIUS`), а не только посёлок.
- Дороги (`render/village.ts`) тоже родом из плана: кольцевая вокруг площади, окружная под стеной,
  просёлок по угодьям за стеной (`FIELD_ROAD`), главная улица от площади через ворота до просёлка
  и отводы к каждому зданию. Покрытие одно — мощёный камень.
- Свободные места плана (там, где раньше стояло хранилище знаний, и `SPARE_PLOTS`) заняты
  хозяйством: поленницы, бочки, телеги, сушила, загородки с животными. Декор лежит отдельной
  группой `decor` — по ней тест проверяет, что изнутри он не наезжает на стену.
- **Рынок стоит прямо на воротах** — единственное здание, сквозь которое главная улица идёт
  нарочно (`ROAD_THROUGH`): торговые ряды по обе стороны проезда, между ними дорога, по ней
  выезжает караван. Отвода у него нет — улица от ворот и есть его подъезд. Модель обязана держать
  проезд шириной `THROUGH_HALF` свободным, и это отдельный тест.
- `render/plan.test.ts` держит всё это, и проверка «всё на месте» разделена на два множества:
  внутреннее целиком помещается **внутри** стены, внешнее стоит целиком **снаружи** — не садится
  на кладку, не наезжает друг на друга, не загораживает выезд из ворот и не выходит за расчистку.
  Плюс прежнее: габариты совпадают с настоящими моделями, площадь свободна, дороги не идут сквозь
  постройки, фасады смотрят в центр. **Меняешь модель — прогоняй этот тест и правь `MODEL_RADIUS`.**

## Зона расчистки вокруг поселения

У посёлка есть **зона расчистки**: `CLEAR_RADIUS = OUTSKIRTS_RADIUS + CLEAR_MARGIN`
(`render/plan.ts`). Считается она от края застройки, а не от стены: ресурсные дворы стоят
снаружи, и лес обязан расступиться перед ними тоже.

- Внутри этого круга нет ничего, кроме самого поселения, его дворов за стеной, дорог и стены:
  ни деревьев, ни камней, ни кустов, ни прочего декора.
- Расстановка детерминирована по сиду — позиции считаются хешем. Позиция внутри запретной зоны
  не двигается «куда-нибудь рядом», а **отбрасывается**. Сдвиг ломал бы узнаваемый рисунок угодий
  и всё равно мог упереться в стену. `inCleared(x, z, r)` учитывает габарит объекта: за черту не
  должна выходить и крона.
- Перед воротами по направлению дороги оставлен свободный коридор (`GATE_CLEAR_HALF`): выезд не
  упирается в лес, и по нему идёт караван.
- По краю расчистки стоит полоса вырубки шириной `CLEAR_EDGE`: пни, поваленные стволы, срезанный
  подлесок. Без неё граница читалась бы дырой в лесу, а не расчищенным местом.
- За полосой вырубки — сплошной лес до края мира (`FOREST_FROM`), с прогалинами под угодья
  (`GLADES`): у скал, ягодника и полей деревья расступаются, охотничья зона — редколесье.
  Посёлок должен читаться поляной в лесу, а не кольцом посреди пустого зелёного диска;
  `CLEAR_MARGIN` — 2.6, больше не надо.
- **Лес стоит дёшево, и это условие его существования.** Сплошной пояс не добавляет ни одного
  вызова отрисовки (он склеен), но давал 45 тысяч треугольников из 115 тысяч. Резать его нельзя —
  он и держит композицию, — поэтому вместо резки сняты две платы: окружение **не отбрасывает тень**
  (`collapse(root, GROUND_AO, false)`): коробка теней накрывает только посёлок (`WALL_RADIUS + 2`),
  а склеенный меш культуре не поддаётся и уходил в теневой проход целиком; и дальние деревья
  (за `FOREST_FAR`) рисуются одним конусом без ствола и без донца (`makeFarTree`, `openEnded`) —
  пять треугольников против сорока четырёх. Новый объект окружения обязан вписаться в это: тень
  ему не положена, а модель у края мира — самая грубая, какую терпит силуэт.
- Угодья (`ZONES`) вынесены за эту границу и стоят ровно в тех направлениях, куда смотрят
  ресурсные дворы: лесопилка лицом к лесу, каменоломня к скалам, ферма к полям. `WORLD_RADIUS` —
  40: расчистка выросла вместе с выносом дворов наружу, и лес отодвинулся за ними.
- `render/terrain.test.ts` держит обещание: ни один объект окружения не попадает внутрь радиуса,
  кольцо стены третьей ступени не пересекается ни с окружением, ни с декором посёлка,
  а коридор перед воротами свободен.

## Структура

- `src/boot/` — запуск и переходы: `stage.ts` (единственная дверь в экран загрузки: имена
  стадий; сам экран — в `index.html`, см. «Экран загрузки»), `paint.ts` (уступить кадр
  перед долгой работой — одна функция на экран загрузки и на занавес перехода).
- `src/battle/` — ядро боя: чистая детерминированная функция без единого внешнего импорта.
- `src/game/battle/` — мост из племени в бой: роды, расстановка, шаблоны, оборона деревни,
  `describe.ts` (описание вида бойцов из конфига боя — всё, что показывает карточка).
- `src/game/` — чистая симуляция, без React и three.
  - `types.ts`, `constants.ts` — состояние и константы (день = 60 сек, уровни и множители зданий,
    `BUILDER_RATE`, `CRAFTER_BUILD`, `TOWN_HALL_BUILD_STEP`, `BASE_DEFENSE`, `MORALE_BASE`,
    `TEST_GEMS`).
  - `data/` — контент: `buildings.ts`, `jobs.ts`, `quests.ts`, `events.ts`, `names.ts`, `seasons.ts`,
    `policy.ts` (указы, рацион, налог, `TAX_PER_POP`), `equipment.ts` (снаряжение), `troops.ts`
    (войска), `market.ts` (товары рынка, цены, запас, ассортимент дня), `gems.ts` (наборы
    алмазов на витрине), `tutorial.ts` (шаги проводки первых шагов),
    `daily.ts` (календарь ежедневки: `dayIndex`, `dailyGameOf`, `dailySeed`, три игры и их
    награды), `social.ts` (ссылки на группу и канал, сборка ссылки приглашения; поля награды
    у них нет и быть не может), `order.ts` (все слова о невольниках, порядке и мятеже — в
    одном модуле, потому что тон проверяет тест, читающий ровно его).
    `seasons.ts` — вся сезонная конфигурация: `SEASON_DAYS` (5 дней = 5 минут на сезон), таблица `SEASON_MODIFIERS`,
    отопление, смягчение первой зимы.
  - `derived.ts` — производные величины (уровни и слоты зданий, вместимость, множители выработки
    рабочего `workerMultiplier` и морали `moraleOutputMult`, свободные руки `idleCount`,
    мораль по слагаемым `moraleBreakdown` (из неё же считается `moraleTarget`),
    армия и оборона, кузница, золото и рынок, скорость стройки с ремесленниками, сезон и прогноз
    зимы, маркеры внимания `buildingAttention`, критические тревоги `alerts`, службы посёлка
    `statOf`/`healShare`/`intelKeen`/`warningSeconds`/`cavalryTrain`/`hiddenStash`/`feastInfo`,
    герой `heroInfo`/`heroMen`/`heroReady`, невольники `bondedTotal`/`handsCount`/`bondedIdle`,
    порядок по слагаемым `orderBreakdown`, `orderState`, цена мятежа `mutinyForecast`).
  - `sim/tick.ts` — шаг симуляции (нормализация назначений, производство, улучшения, ковка, учения,
    рынок, рост, события, задания); `catchUp` — офлайн-догон.
  - `sim/workers.ts` — кто где работает: `assignWorker`, `unassignWorker`, `assignBonded`,

- `src/net/` — личность игрока, хранение прогресса и общий реестр замков:
  `roster.ts` (единственная дверь к тому, где стоят живые игроки: своя клетка, соседи и
  честная отметка «данные старые»), `clock.ts` (единственная дверь к «сейчас»),
  `api.ts` (разговор с сервером: срок на запрос, неудача значением, а не исключением),
  `sync.ts` (правило встречи двух копий — `decide`: продолжение уезжает наверх, расхождение
  уступает серверу, отвергнутая копия ложится рядом),
  `session.ts` (признак устройства и ведение партии между вкладками), `snapshot.ts` (что уедет
  на сервер), `notify.ts` (присутствие и список черновиков на сервер; заперт `NOTIFY_ON`).
  Про игру знает только `snapshot.ts`; остальным отдают строку.
- `netlify/` — серверная часть: `lib/initdata.ts` (единственная дверь к личности — HMAC по токену
  бота), `lib/contract.ts` (договор между игрой и сервером, один файл на обе стороны),
  `lib/http.ts` (ответы, пределы, ограничитель частоты), `lib/roster.ts` (правила реестра
  замков: `upsert` трогает одну строку, прополка по сроку и потолку), `lib/notify.ts` (правила
  исходящих: приём, присутствие, отправка, тихие часы, потолки), `lib/deliver.ts` (проход
  доставки без отправки: условная отметка «ушло» и счётчик прохода),
  `functions/save.mts`, `functions/time.mts`, `functions/castles.mts`, `functions/notify.mts`
  и `functions/deliver.mts` (по расписанию, раз в минуту).
  Лежит вне `src` и своим проектом типов (`netlify/tsconfig.json`): у неё Node без DOM.
- `src/telegram/webapp.ts` — обёртка Telegram API: вьюпорт (`--app-h`), вырезы (`--tg-*`), тема из `themeParams`,
  haptics, подписанная строка запуска (`tgInitData`). Облако CloudStorage здесь только типом и
  только на чтение; сам подъём — в `src/telegram/cloud-rescue.ts`.

## Правила

- Симуляция мутирует состояние на месте; стор после действия делает `set({ s: { ...s } })`, чтобы React перерисовался.
- Новый контент добавляется в `data/*` и, при необходимости, в `derived.ts`,
  `render/buildings.ts` (модель) + `FOOTPRINT` и `render/plan.ts` (место и `MODEL_RADIUS`).
  Новое здание попадает в стартовый посёлок само: `createInitialState` ставит всё из `BUILDINGS`.
- Тексты интерфейса — на русском. Эмодзи используются как иконки в UI.
  Проверяй, что символ рисуется: эмодзи Emoji 13.0 и новее (🪵, 🪨, 🪙) на части систем показываются квадратом.
- Для файлов с эмодзи писать через Write, не через bash-heredoc (обрезается на некоторых символах).
- Размеры и отступы берутся из CSS-переменных `--app-h`, `--safe-*`, `--nav-h`, `--tap` (44 px) — не `100vh` и не голый `env()`.
- Изменение формата сохранения: поднять `SAVE_VERSION` в `state.ts` и дописать ступень в
  `migrate` (`save.ts`), не забыв запись в летопись, — прогресс не пропадает и не меняется молча.
  Сохранение младше `MIN_SAVE_VERSION` по-прежнему отбрасывается с объяснением игроку
  (`LegacyModal`). Новые поля состояния со значением по умолчанию версию не поднимают:
  `deserialize` мержит сохранение поверх `createInitialState()` (словари счётчиков — `equipment`,
  `army`, `stats`, `profile` — мержатся отдельно, иначе новый вид бойца приедет как `undefined`;
  `workers` и `freeJobs`, наоборот, берутся как есть — мерж оставил бы рабочих за снесённым
  зданием). Ступень нужна там, где умолчания мало и величину надо посчитать из самого состояния.
- Сезон меняет баланс только через таблицу `SEASON_MODIFIERS`. Логика читает её в одном месте — `seasonMods(s)` в
  `derived.ts`, а `tick` берёт множители один раз за шаг и передаёт вниз. Новый сезонный эффект добавляется полем
  в `SeasonModifiers`, не условием по коду.
- Сезон и год выводятся из `s.time`, отдельного состояния нет: `seasonOf`, `yearOf`, `seasonProgress`.
  Первая зима (год 1) мягче — её штрафы гасятся `FIRST_WINTER_SOFTEN`.
- Модалки делят один слой: новая не должна накладываться на `EventModal` — смотри guard в `WinterModal`.
- Склад стоит в посёлке с первого дня: полный список ресурсов виден только в его панели, без него
  игрок не видит ни одного числа о запасах.
- Здания одного типа второго не бывает, и снести здание нельзя: событие отнимает уровень, а не
  постройку. Пожар отнимает уровень Жилищ, но не ниже первого (`data/events.ts`).
- **События считают от размера посёлка, а не константами.** Всё, что событие даёт или отнимает,
  умножается на `amount()` — во сколько раз племя больше стартовых тридцати; толпа считается долей
  (`crowd()`), а сила случайного противника — долей обороны (`foePower()`). Иначе к середине партии
  «+25 еды» тонет в дневной выработке, а стая волков перестаёт быть боем. Новое событие с числом
  в коде — ошибка.
- **Цена события объявлена полем `cost`, а не спрятана в `apply`.** Одно число на три дела:
  его показывает `Cost` («нужно / из»), по нему гаснет кнопка (`eventBlock`) и по нему же
  списывается добро (`payEventCost` в `resolveEvent`). `apply` получает состояние уже
  оплаченным и про цену не знает, а подпись варианта говорит только о том, что игрок
  **получит**: цена, переписанная словами второй раз, разойдётся с числом при первой правке —
  это тест. Отсюда же следует правило, без которого запрет опасен: **у каждого события
  обязан остаться вариант, который ничего не стоит** — окно события не закрывается, и
  погасшие выходы заперли бы игрока. Тоже тест (`data/events.test.ts`).
- **Люди приходят и уходят толпой.** Поимённых жителей нет, поэтому событие про человека — это
  событие про группу: беженцы у ворот (принять всех, взять сколько поместится, прогнать), бродячая
  артель (осесть или отработать день на стройке), мор. Принять сверх крыш можно — платит за это
  мораль, и теснота считается долей вместимости (`CROWDING_PENALTY`), а не головами.

## Здания: все стоят, растут уровнями

Зданий 24, каждого типа в посёлке ровно одно, все они стоят с первого дня, и вся линия развития
постройки — уровни. Полный справочник с числами — [docs/BUILDINGS.md](docs/BUILDINGS.md).
Отсюда следует всё остальное:

- Улучшение — стройка на уже стоящем здании: `workRequired > 0` (`isSite`). Оно ничего не
  отключает: `buildingSlots` и `workerMultiplier` смотрят на `level`, а он при улучшении не меняется —
  рабочие остаются на местах, выработка идёт, новые места добавляются к старым в момент завершения.
  Всё строится одной очередью — `currentSite(s)`; работают свободные руки (`BUILDER_RATE`) и
  ремесленники мастерской (`crafterBuildRate`).
- Мест столько, сколько уровень × `slotsPerLevel` (по умолчанию `SLOTS_PER_LEVEL` = 12), каждый
  уровень даёт +10% базовой выработки каждому рабочему (`levelOutputMult`) — у дворов, мастерской и
  кузницы. Служителя храма уровень не усиливает: мораль и набожность он держит головой, до
  потолка, и места храма с седьмого уровня ничего не прибавляют. Цена и труд улучшения растут
  в `UPGRADE_GROWTH` (1.4) раза за уровень от `def.cost`/`def.work`.
- **Что даст уровень, кнопка улучшения говорит замером, а не по полю здания** (`ui/parts/upgrade.ts`).
  Она прогоняет настоящий расчёт игры на нынешнем уровне и на следующем и называет разницу
  величин посёлка — с потолками, множителями веры и всем, что между полем и местом, где игра его
  читает. Прежняя подпись брала разность поля и врала там, где функция его режет: лазарет
  обещал прибавку сверх потолка, храм — «+10 %» служителям, Дозор — округлённые минуты, а у
  Статуи и ратуши главного числа на кнопке не было вовсе. Уровень, не меняющий ничего, так и
  говорит: «Этот уровень ничего не прибавит». Проценты на кнопке — рост против нынешнего, а не
  шаг от базы. **Читать поле здания в этом модуле нельзя** — держит это тест по исходнику, а
  совпадение каждого числа с замером на каждом уровне каждого здания — прогон
  (`ui/parts/upgrade.test.ts`). Граница у теста честная: число без замера на кнопку не пройдёт,
  и поле здания, которое кнопка не видит, тоже поймается (тест удваивает каждое поле и ждёт, что
  кнопка это заметит). А новую **формулу** от уровня — как скорость казарм или прилавок рынка —
  замер сам не узнает: её величину заводят в `GAUGES` руками, одной функцией игры.
- Потолок уровня — минимум из `def.maxLevel` и `MAX_BUILDING_LEVEL` (10). Ничем сверху не режется.
- Пассивные эффекты (жильё, склад, защита, мораль) растут не множителем, а полем `perLevel` в определении
  здания; поле `since` задаёт уровень, с которого эффект вообще появляется (жильё ратуши — с шестого).
  Числа подобраны так, чтобы на потолке население было 600–1000 человек.
  Меняя `perLevel`, прогоняй тест «на потолке уровней посёлок держит сотни людей» и `npm run pop:report`.
- **Стена делит посёлок надвое.** Ресурсные дворы (лесопилка, каменоломня, рудник, ферма, загон,
  охотничий домик, навес собирателей) стоят **снаружи** — поле и штольня там, где ресурс. Внутри
  жильё, власть, церковь, склад, кузница, мастерская, казармы, рынок, статуя и службы. Признак
  задаёт поле `outside` в определении здания (`isOutsideWall`, `OUTSIDE_TYPES`), а не план
  поселения: от него зависит набег (`sackOutskirts`), и это правило игры, а не рисунок.
- **Восемь зданий не дают ни рабочих мест, ни ресурсов — только своё одно число.** Лазарет
  (`heal` — доля потерь, вернувшихся ранеными, потолок `INFIRMARY_HEAL_CAP`), Дозор (`intel` —
  во сколько раз медленнее стареет разведка, `warn` — насколько дольше видно чужую армию, плюс
  изучение округи: уровень здания — потолок ступени, `data/survey.ts`),
  Конюшня (`train` — скорость учений конницы, `mountGear` — ступень её снаряжения), Тайник
  (`hidden` — вместимость схрона: сколько каждого припаса победитель не достанет;
  растёт геометрически — `stashAt`), Трактир (`feast` — прибавка морали
  на время пира), Статуя (`command` — сколько бойцов, по головам, уводит полководец, главное
  ограничение похода; `hero` — сколько бойцов строя идёт за героем), плюс частокол
  (`defense`) и башня (`archers`). Храм в этот список не входит: у него есть и места
  (служители), и своё число (мораль), и наклон веры сверх того — см. «Вера». Новые здания заводить лучше такими: рабочих мест уже
  960 на 755 человек, и разрыв расти не должен.
- Кто где работает, хранится числами: `s.workers[id]` и `s.freeJobs[job]`, дублирующего списка нет.
  Невольники — третьим числом на тех же местах, `s.bondedWork[id]`: места общие, занятость
  спрашивают у `handsCount`, и ставят их только на работы с `JobDef.bonded` (поле, лес, камень,
  руда, загон, сбор — `BONDED_JOBS`).
  `normalizeAssignments` вызывается каждый тик и чинит назначения после любых изменений мира:
  снимает лишних сверх слотов, выбрасывает записи снесённых зданий и подрезает назначения под
  убывшее население — сначала вольный сбор, потом самые многолюдные здания. Мест стало меньше —
  первыми с них уходят невольники: вольного ради невольника с места не сгоняют.

## Карта мира

**Земля одна на всех и настоящая: Европа, Магриб, Анатолия.** Мир перестал быть личной картой,
сгенерированной из зерна, — он запечён из данных Natural Earth и одинаков у каждого
([docs/atlas.md](docs/atlas.md): масштаб с расчётом, проекция, вес, что тронуто в отрисовке).
**Игроки видят друг друга, и на этом всё.** Сервер держит реестр замков (`/api/castles`):
кто, где стоит, как называется, какова мощь и когда был в игре. Место выбирает он, а не
клиент. Между игроками при этом не происходит ничего — ни походов, ни осад, ни дипломатии,
ни писем, — и общего состояния мира по-прежнему нет: землю каждый клиент считает сам из того
же атласа, а фоновую жизнь (набеги соседей, войны дворов) выдумывает у себя. Поэтому замки
живых игроков и лежат отдельным списком, вне `gen.settlements`: приписать выдуманное живому
человеку нельзя. Разбор целиком — [docs/sync.md](docs/sync.md), раздел 4.

Поселений ботов на общей карте больше нет ни одного. Всё, что осталось без участников —
дипломатия, письма, осады, разорение, зоны влияния, — не выпилено: оно ждёт живых игроков, и
спящие случаи помечены в тестах (`grep -rn waitsForPlayers src`).

Код по-прежнему написан так, чтобы источник данных менялся без переписывания экранов. Как экран
карты рисуется — два масштаба, выпечка земли, силуэты поселений — в
[docs/world-map.md](docs/world-map.md). Туман войны двумя слоями, фигуры
на карте и правило «армия ходит только с полководцем» — в
[docs/fog-and-figures.md](docs/fog-and-figures.md) — там же **поводок камеры** и отладочный
обзор мира. Реки, переправы, хребты, проходимость и зоны влияния —
в [docs/geography.md](docs/geography.md). Выбор агента, меню приказов, отношения с
поселениями (нейтралитет, пакт, война) и то, как по ним ходят боты, —
в [docs/MAP_ACTIONS.md](docs/MAP_ACTIONS.md); там же замысел лазутчика и полководца целиком.
Письма — ожидающие решения игрока, стол на пять, срок в сутки и разрешение без него —
в [docs/letters.md](docs/letters.md). Осада: одно окно, часы голода, срезанный приток,
падение города, замок на выход, приказ «Осадить», вылазка и лагерь как цель —
в [docs/siege.md](docs/siege.md). Разорение поселения после выигранного набега —
одно окно, остановленные часы двора, пустой склад и месть соседа с потолком —
в [docs/sack.md](docs/sack.md).

- **Вся работа с миром идёт через `worldApi()`** — список поселений в области, карточка, отправка похода,
  фигуры и их приказы, свои походы, отчёты, разведданные, племена, договоры. Ни один компонент не лезет
  в `LocalWorld` напрямую и не импортирует его (кроме `world/store.ts`, который его подключает).
  Появится сервер — рядом встанет `HttpWorld` с тем же интерфейсом.
- **Все методы асинхронные, даже локальные.** Синхронный вызов «потому что данные рядом» — ошибка:
  при переезде на сервер придётся править каждое место вызова.
- **Земля одна на всех и запечена, а не сгенерирована.** Настоящая Европа, Магриб и
  Анатолия из данных Natural Earth: `src/world/atlas/` (сборка — `npm run world:build`,
  источник и лицензия — `assets-src/world/SOURCES.md`, разбор — [docs/atlas.md](docs/atlas.md)).
  Сетка 800×800 клеток по 6.13 км, проекция коническая равноугольная Ламберта.
  `src/world/atlas/data.ts` **сгенерирован, руками не правят.**
- **Сид больше не рождает землю и не выбирает переправы.** В подписях он остался
  (`terrainAt(seed, x, y)`) и не значит там ничего: у двоих игроков на одной реке мост
  обязан стоять в одном месте, поэтому выбор перехода солится постоянным `GEO_SALT`.
  Держит это тест «земля одна на все сиды» — он сверяет признаки клетки целиком. Сид
  по-прежнему решает, где встал замок игрока и куда легли логова, и остаётся солью
  походов, боёв и писем; `Math.random()` в этих местах звать по-прежнему нельзя.
- **Местность рождает решения, а не множители.** Река — преграда (×18 без переправы), переправы
  редки (одна на блок в 22 клетки, то есть примерно раз в 135 км), через хребет ведёт перевал,
  пустыня ×2.4, вода ×7.6. Время пути — интеграл вдоль линии с постоянным шагом замера: при
  прежних 24 замерах на любой путь река растворялась в длине. Числа — в разделе «География» в
  `data/tuning.ts`, проверка — `npm run world:report`.
- **Трактов на карте нет.** Они соединяли станы племён, а станов не осталось вместе с
  поселениями ботов. Прокладка (`road`, `roadNet`) цела — не хватает только концов;
  дороги вернутся вместе с настоящими городами.
- **Вода дорога, но никого не запирает.** Море занимает сорок процентов карты, поэтому
  замок игрока ставится по правилу, а не по удаче: связная суша от клетки не меньше
  `MAINLAND_MIN` (20 000 клеток при материке в 365 926 и Британии в 5 695). Считается это
  дешёвым обходом с потолком (`reachableLand`), а не полной разметкой в 160 мс. До первого
  логова тоже идут посуху — прямая дороже `LAIR_REACH_FACTOR` в цель не годится.
- **Камера игрока привязана к своим.** Она стоит на своём поселении или на одной из фигур
  (ряд якорей внизу слева), а смещение ограничено поводком — обзор якоря плюс запас, но не дальше
  половины экрана. Приказ движения в темноту при этом обязан оставаться возможным: ради него поводок
  и заведён. Прежний свободный обзор мира — отладочный режим за флагом `?worldview=1|open`
  (`src/debug.ts`), игроку он недоступен.
- **Изучение округи в Дозоре открывает землю и только её.** Десять ступеней, каждая раскрывает
  вокруг деревни радиус терра инкогнита навсегда; уровень Дозора — потолок ступени, а не её
  источник. В мир едет одно число (`PlayerProfile.survey`, радиус в клетках), как предупреждение о
  набеге и вместимость отряда: мир про здания не знает. Живой обзор деревни при этом не растягивается
  ни на клетку.
- **Дальше разведанного карту не отдалить.** Панорама ограничена поводком, обзор — потолком
  отдаления (`zoomFloor` в `ui/map/grid.ts` от `exploredReach` в `world/fog.ts`): в кадр пускают
  разведанное **вокруг якоря** плюс `ZOOM_MARGIN`. Вокруг якоря, а не по общей границе всего
  открытого, — иначе первый дальний поход разведчика растянул бы предел на весь мир. Мерка в
  клетках, а не в пикселях: на телефоне и на мониторе потолок означает одно и то же. Приближение
  не ограничено.
- **Зоны влияния племён красятся только на разведанной местности.** Влияние считается от поселений
  с затуханием (`world/territory.ts`) и едет в куске карты (`RegionChunk.influence`) — но лишь для
  клеток, которые игрок открыл: цвет чужого владения такие же разведданные, как численность гарнизона.
- **Время пути симметрично.** `terrainFactor` приводит концы отрезка к одному порядку и берёт пробы в
  серединах равных долей — путь туда и обратно считается по тем же клеткам. Обратная дорога получается
  из той же длительности (`turnHome`), отзыв — из уже пройденного времени.
- **Разведка стареет.** Снимок хранит время; `readIntel` отдаёт точное число, потом диапазон, потом ничего
  (пороги — `INTEL_*` в `data/tuning.ts`). Своя мощь видна всегда, чужая — только из разведки или боя:
  обзор фигуры её не заменяет и заменять не должен.
- **Туман войны — два слоя, и сводить их к одному нельзя.** Местность (рельеф, лес, вода, сам факт
  поселения) открывается навсегда — битовая маска по кускам, `world/fog.ts`; списка координат строками
  здесь быть не может, на половине карты это 195 КБ против 5 КБ у маски. Живые данные (численность,
  стадия, чьё оно, идут ли оттуда войска, где сейчас чужой отряд) видны только пока клетка в **живом
  обзоре**; вышла из него — остаётся последний снимок (`Sighting`) с отметкой давности, и об этом
  говорится словами.
- **Живой обзор дают ровно двое: круг у деревни (`HOME_SIGHT` — 17 клеток, отсюда два-три соседа на
  старте) и лазутчик, стоящий наблюдателем.** Всё остальное — разведчик, дипломат, полководец, свои
  отряды в пути, изученная Дозором округа — открывает **только местность**. Правило живёт в одном
  месте (`world/sight.ts`, чистый модуль), и считают по нему двое: мир и карта. Второй правды о том,
  кто наблюдает, между ними быть не должно. Наблюдение — приказ: пока лазутчик смотрит, он не
  выведывает войско и не поднимает бунт, и приказы возвращаются с причиной, а не гаснут молча.
  Наблюдают стоя, отправленный в путь наблюдать перестаёт. Второго лазутчика заводить нельзя — на
  выборе «смотреть или действовать» всё и держится.
- **Отряды на карте видно: кто идёт, куда и велик ли.** Поход рисуется колонной людей со
  знаменем стороны, наконечником хода и дорогой под ногами; лагерь осады — шатрами;
  полководец — тем войском, которое ведёт. Спрайт печётся один раз на (сторона, размер,
  вид, направление), движение не стоит ни одной перепечки: положение — чистая функция от
  времени. **Сколько людей в чужом отряде, показывается только в живом обзоре** — иначе
  колонна становится пыльным облаком без единой фигуры, потому что донесение Дозора
  говорит «идут», а не «сколько». Решает это тот же `world/sight.ts` через
  `world/store.sightDiscs`, каким мир решал, показывать ли отряд вообще; второй правды об
  этом между картой и миром быть не должно, и держат это тесты по исходнику. Числа
  лестницы размеров и бюджет кадра меряет `npm run map:report`; разбор —
  [docs/world-map.md](docs/world-map.md), раздел «Отряды».
- **Чужой отряд виден по двум причинам, и берётся та, что случится раньше:** он в живом обзоре — или
  о нём донёс Дозор (`AI_WARNING_BASE` плюс `warn` здания). Без донесения набег из дальнего двора
  входил бы в круг уже за отметкой `DEFENSE_FREEZE`, и перехват в поле стал бы кнопкой, которая не
  нажимается; без живого обзора круг у деревни не значил бы ничего. Меряется прогоном:
  `npm run raid:report`.
- **На карте четыре фигуры, по одной каждой** (`world/data/figures.ts`): разведчик, дипломат,
  полководец, лазутчик. Приказы агентам, отношения с поселениями и работа лазутчика —
  в [docs/MAP_ACTIONS.md](docs/MAP_ACTIONS.md).
  **Каждая узнаётся силуэтом, а не цветом и не значком в одинаковом кружке** (`ui/map/agent.ts`):
  цвет на карте занят стороной, и второго значения на него вешать нельзя. Шляпа разведчика,
  подол дипломата, капюшон лазутчика, гребень полководца; печётся один раз на
  (вид, направление, корзину), в кадре — `drawImage`. Поза, снаряжение, знак стороны и тень
  под ногами делают из силуэта фигурку, но опознание держат не они: узнаётся фигура формой и
  на самом мелком масштабе.
  **Подписей под фигурами на полотне нет ни в каком виде, и заводить их обратно нельзя.**
  Имя отвечало ровно на тот вопрос, на который обязан отвечать силуэт, и стояло меткой на
  местности: четверо дома писали лесенку из четырёх строк поверх собственной деревни. Читается
  имя в панели агентов, в подсказке про фигуру в руке и в шапке меню приказов — это тест, как и
  само отсутствие подписи. Раз опознание держится на форме, оно **меряется числом**
  (`npm run map:report`, раздел «агенты»): совпадение залитых пятен тем же порогом, что у видов
  бойцов в трёхмерной сцене, плюс признаки в пикселях. Панель агентов — уголок в правом низу без
  слова «Агенты»; свёрнутой она обязана говорить, есть ли кому дать приказ. Разбор —
  [docs/world-map.md](docs/world-map.md), раздел «Агенты».
  Положение выводится из времени выхода и прибытия, поэтому офлайн даёт ровно то же, что непрерывная
  игра, а туман открывается по **пройденному пути**, а не по нынешней точке. Погибшая фигура
  возвращается через `FIGURE_DOWN` — потерять её насовсем нельзя, как и героя.
- **Армия ходит только с полководцем.** `send` набеги не принимает вовсе: цель назначается тем, что
  полководец у неё стоит, и бой считается там же (`attack`). Состав меняется только вплотную к своей
  деревне (`setGarrison`). **Армий две, и боец переходит из одной в другую, а не копируется:**
  гарнизон — войско города, дружина — те, кого полководец из города забрал, и Статуя ограничивает
  не оборону, а то, сколько можно вынести. Держать ему можно всё войско без походов (`roomOf`), а не
  «гарнизон плюс то, что уже при нём».
- **Полководец в городе — его дружина часть гарнизона, во всех ролях сразу.** Собрана и стоит у своих
  ворот — она в гарнизоне: у частокола, у амбара в осаде, под рассеянием при падении и **на
  вылазке**, один раз и без отдельного действия. Пока идёт сбор или роспуск, эти люди не защищают
  никого; в пути, в поле, в погоне и в лагере дружина **занята** и в гарнизоне её нет, даже в двух
  шагах от ворот. Занятость — не поле: это `postureOf` из места полководца и срока сбора,
  прочитанных в минуту боя. Удара «от своих ворот» нет: из города за ворота выходят вылазкой, а из
  поля бьёт только дружина в поле (`fieldTroops`) — полководец в городе такого приказа не отдаёт, и
  держит это учёт, а не проверка на входе. Обе цены — сбора и похода — видны игроку **до** приказа.
- **Где стоит боец, считает одно правило — `world/muster`, и гарнизон с обороной читает мир сам.**
  Слепок везёт всё войско; второго счёта «сколько бойцов свободно» заводить нельзя — из двух таких
  правд вышла дружина в сто десять из десяти, и ядро боя считало всех. Держит это
  `world/muster.test.ts`, разбор — [docs/fog-and-figures.md](docs/fog-and-figures.md), «Армия ходит
  только с полководцем».
- **Армия в походе не защищает деревню.** Кто не в обороне, живёт числами `warriorsAway`/`scoutsAway`
  в состоянии племени, их вычитают `defense()` и `buildRate()`. Число не хранится дважды: `syncAway`
  каждый пульс выводит его из списка походов и места дружины, поэтому потерянное сохранение мира не
  оставит деревню без армии.
  Панель отправки обязана показывать, какой станет оборона. Мир считает отряд числами, поэтому в него
  уходит средняя мощь бойца (`soldierPower`), а состав знает только племя.
- **ИИ ходит мягко.** Набег редкий, слабее обороны игрока (`AI_POWER_VS_DEFENSE`) и виден заранее
  (`AI_WARNING_BASE` плюс то, что даёт Дозор игрока) — в `AlertBar` с таймером.
- **Правила отсутствия нет: враг подходит и осаждает, в игре хозяин или нет.** Прежде набег,
  пришедшийся на время без пульса игрока, не состоялся бы, а осада без игрока не начиналась
  (`AWAY_GRACE` в `resolveIncoming`); снято решением владельца (docs/DEFEAT_LADDER.md) вместе с
  `WorldSave.seenAt`. Держит это прогон, а не слово: набег, пришедшийся на отсутствие, кончается
  так же, как при игроке (`world.test.ts`). Мятеж — не враг и правило сохранил: его срок идёт
  только при игроке (см. «Невольники и порядок в городе»).
- **Отряд, которому не взять стену, садится в осаду.** Осада — не второй набег: она режет
  приток (хлеб в ноль, прочее четвертью), а решает всё окно времени, из которого при чтении
  выводятся часы голода. Из осаждённого города не выступают — это отказ в точке отдачи
  приказа, а не проверка потом. Числа, следствия и то, чего в осаде нет, —
  [docs/siege.md](docs/siege.md).
- **Осада — приказ, доступный обеим сторонам, и реализация у неё одна.** Полководец игрока
  садится в осаду под чужим городом тем же окном и теми же часами голода; увод полководца
  снимает осаду, и сказано об этом **до** приказа (`CAMP_LEAVE`), а не после. Второй ветки
  кода под «нашу» осаду быть не должно — держит это тест, считающий по исходнику.
- **Из-под осады выходят вылазкой, а лагерь — цель на карте.** Состав вылазки выбирает
  игрок; победа снимает осаду, поражение нет, но **лагерь теряет людей в любом случае** —
  вылазка без урона противнику была бы чистым минусом, и кнопку не нажал бы никто. По
  лагерю бьют и снаружи: полководец, выручка соседей, вылазка осаждённого бота — бой у всех
  трёх один.
- **Лагерь укрепляется, и время работает против города** (`world/works`). Укрепление —
  функция от минуты, когда лагерь встал, дозревает за `CAMP_WORKS_RIPE` (28 мин) и сужает
  проход: к бою пробивается не больше `люди лагеря × CAMP_WORKS_PASS / доля` бойцов строя
  нападающих, остальные стоят у рогаток и не дерутся. **Людей лагерю оно не прибавляет** —
  прежняя прибавка в четверть заменена им целиком, второй прибавки за то же нет, и держит
  это тест. Действует на всех, кто бьёт по лагерю, и на обе стороны; часов голода не
  касается. Игрок видит проход до нажатия (окно осады, экран вылазки, карточка чужого лагеря,
  меню полководца), а в отчёте после боя — «пробились N из M»; окно и бой считают это
  одной функцией (`throughWorks`), и сверяет их тест настоящим боем. Проход режет строй
  долей по родам, а не головами: латник весит восьмерых.
- **Проход через рогатки — поток, а не порция** (`CAMP_GATE_CLEAR`, 10 мин). Прошла часть
  пропуска — такая же часть прохода занята и освобождается за ту же часть времени;
  семнадцать вылазок за минуту проводят столько же, сколько одна, и скорость нажатия
  умением не становится. Отката у вылазки нет и заводить его нельзя. Хранится по отметке на
  сторону в окне осады (`SiegeWindow.gateAt` у фронта, `rearGateAt` у тыла), пишет их только
  бой у лагеря, читаются они при чтении, тика нет; окно без отметки (старое сохранение) —
  свободный проход. Проходы уходят вместе с окном. Вылазка, которой некого протолкнуть,
  получает отказ до боя — те же слова стоят на экране вылазки до нажатия. Замер —
  `npm run siege:report`, «частые вылазки»; разбор — [docs/siege.md](docs/siege.md).
- **У лагеря две стороны: фронт к городу и тыл в поле** (`world/works`), у каждой своя
  готовность и свой проход; кто лезет с одной стороны, другую не занимает. Вылазка и
  выручка бьют во фронт, полководец из поля — в тыл, приказом издалека, бой в минуту
  прихода. Под своим городом можно позвать гарнизон: он лезет во фронт, дружина в тыл, бой
  один, стен и города в нём нет; потери делятся по сторонам (`splitLosses`). Готовность
  стороны — древесина, которую лагерь рубит сам, одно число на сторону (`CAMP_WOOD`);
  дозревшая сторона отдаёт долю другой. **Фронт — единица, и это замок:** его готовность
  буква в букву прежняя, утверждённая кривая вылазки не сдвигается — тест. **Тыл — половина,
  меряно:** при единице удар с тыла шёл по кривой вылазки точка в точку, и сторон по смыслу
  не было; при половине он верен до 20-й минуты, когда вылазка уже безнадёжна. **Лагерь игрока
  делит древесину сам**, в окне осады, пятью шагами (`works.WOOD_SHARES`): рубит он одну сторону
  за 28 минут (`PLAYER_CAMP_WOOD`) — всё во фронт даёт прежние 28 минут фронту, поровну — 56
  обеим; бот рубит полторы и не делит. Смена долей посреди осады не переписывает прошлое:
  вложенное к её минуте становится базой (`works.rebaseWood`, `SiegeWindow.wood`), и готовность
  не убывает ни на каком пути смен — тест. Обороняющийся видит готовность сторон и подсказку о
  слабой, перед ударом — кто пробьётся с каждой стороны, в записи — «с тыла N из M, со стороны
  города K из L»; всё той же `campGate`, что и бой. Разбор и замеры —
  [docs/siege.md](docs/siege.md), «Две стороны и древесина».
- **Осада — два окна, по одному на сторону, и считают они тем же, чем бой.** Окно
  обороняющегося (`panels/SiegePanel`) — объявленная участь и что город потеряет (`SiegeView.fall`,
  той же дверью участи, что и падение), своя еда, частокол, стороны лагеря (`works.campSides`),
  вылазка и удар полководца с тыла. Окно осаждающего (`panels/CampPanel`) — город и чем он
  держится, **сколько ему осталось хлеба** (решение владельца: срок видит участник осады — и
  видит одинаково в окне, в карточке города и на экране вылазки: одно чтение окна
  `LocalWorld.hungerOf`, одни слова `ui/parts/hunger.ts`), стороны лагеря, доли древесины, выбор участи и
  три приказа: осаждать (объявить участь заново), штурмовать (удар снимает лагерь до боя,
  `STORM_LIFTS`), отступить. Место под осадные орудия подписано и пусто. Плашка осады в деревне и
  меню полководца — входы в окна; удар по лагерю — одна часть `parts/CampStrike` на окно и меню.
  Ни одного числа окно не считает само — тест по исходнику и сверка с боем и с племенем замером.
- **Частота осад ограничена нарочно.** Порог (`SIEGE_IF_BELOW`) отвечает за смысл — штурм
  безнадёжен; за частоту отвечают доля попыток (`SIEGE_CHANCE`) и остывание
  (`SIEGE_COOLDOWN`), и крутятся они врозь. Без них крепкая деревня видела бы лагерь вместо
  набега почти всегда, то есть вложение в стену наказывалось бы исчезновением набега как
  события: было 81% приходов, стало 15% (`npm run siege:report`).
- **Прорвавшийся набег разгоняет хозяйство за стеной** (`sackOutskirts`): работники с
  одного-трёх дворов разбегаются. Уровней он там **не снимает** — у падения уровней один
  источник, участь взятого города (пункт ниже); разбежавшиеся работники — последствие боя у
  стены, а не участи. Мир про здания не знает — он передаёт одно число `sacked` (0..1), а что с
  ним делать, решает племя.
- **Участь взятого города — одна дверь, `spoils.fate`,** и зовут её все четыре места, где город
  взят: прорвавшийся набег и голод у нашего города, наш набег и наш лагерь у чужого. Своего
  дележа ни у одного из них нет — тест по исходнику. **Ступеней три, строками `FATES`, и выбирает
  её победитель в момент приказа** — «Ударить» (`AttackOrder.fate`) или «Осадить» (`besiege(fate)`
  → `SiegeWindow.fate`); у отряда ИИ — `StoredMarch.fate`, логова объявляют «ограбить». Падение
  читает объявленное через одну проверку (`fateAt`): недоступное подменяется умолчанием.
  - **Ограбить** — склад и казна до тайника, сколько поднимет обоз; невольники остаются.
  - **Увести людей** — то же, плюс невольники города первыми и `LED_POP_SHARE` (30 %) горожан тем
    же конвоем (`lead`); каждый уведённый вычитает `HEAD_CARRY` (150 — курс `carry/escort`
    воина) из **открытого склада**, а не из обоза, ровно один раз — тест.
  - На обеих **пять построек теряют по уровню, не ниже первого, тайник — никогда**
    (`FALL_BUILDINGS`, `FALL_LEVELS`, `expedition.FALL_SPARED`).
  - **Сжечь** — победителю ничего; всё сверх тайника сгорает, `BURN_POP_SHARE` (80 %) горожан
    расходится, невольники разбегаются все, **все постройки по `BURN_LEVELS` (2) вместо пяти по
    одному**, улучшения в работе сгорают без возврата (`burnWorks`), тайник не горит ни уровнем,
    ни стройкой. Мгновенно: окна и стоянки у ворот нет — решение владельца. Логову и двору мира
    не предлагается (`FATES.burn.vsWorld`). Сожжённый город сутки нельзя сжечь снова, но можно
    ограбить (`BURN_IMMUNE`, `WorldSave.burnImmune`, тем же приёмом, что `siegeImmune`).
  Лестница монотонна на одном входе — замером на посёлке, тест. Какие пять построек — решает дверь
  из соли события (сид мира и минута падения, `fallSeed`), а не бросок при применении: список лежит
  готовым в `HomeEffect.fallen` и `Report.fallen`. Мир про здания не знает: уровни ему везёт слепок
  ключами (`PlayerProfile.levels`), снимает их племя (`fallBuildings`), горожан — `popLost`,
  стройку — `burned`. Уведённые из чужого двора ложатся в его разбитость (`leadFrom`) — у логова
  это и есть его люди. Цена по этапам партии — `npm run sack:report`, раздел «лестница»; разбор —
  [docs/DEFEAT_LADDER.md](docs/DEFEAT_LADDER.md).
- **На разведку можно повлиять — Дозором.** Снимок запоминает `keen` в момент разведки и стареет
  во столько же раз медленнее (`readIntel`); он же удлиняет предупреждение о набеге. Правило
  «предупреждение длиннее заморозки обороны» держит база: Дозор время только прибавляет.
  **С появления Дозора (7406a7e) и до аудита это обещание не исполнялось ни разу:** поле было
  объявлено и читалось, а `snapshot()` его не писал, и читатель молча брал единицу. Держит его
  теперь тест «снимок разведки несёт всё, что читает readIntel» (`world/world.test.ts`): чтения
  читателя записывает прокси, и каждое поле обязан писать каждый, кто выпускает снимок, —
  разведчик, лазутчик и бой. На снимок чужого замка живого игрока (`sightings`) Дозор не
  действует: это живой обзор, а не разведка.
- **Победитель забирает со склада и из казны всё, кроме того, что помещается в тайник.**
  Правило одно на обе стороны и написано один раз — `plunder` в `src/world/spoils.ts`: склад
  минус тайник, но не больше, чем поднимет отряд (`stackCarry`). Зовут его ровно двое: дверь
  участи (`fate`, все четыре места, где город взят) и мятеж, который стража не удержала
  (`sim/mutiny.ts` — единственный импорт мира в `src/game` вне тестов, и ради того же: второй
  арифметики добычи быть не должно). Из
  правила следует всё остальное — копить на складе рискованно, тратить выгодно, а склад
  после набега пуст **по факту**, а не по коэффициенту.
  **Тайник при этом ничего не «защищает»** — он вместимость: сколько каждого припаса
  просто не достанут. У игрока её даёт здание (`stashAt`, растёт множителем `UPGRADE_GROWTH`
  — тем же, каким дорожают улучшения, иначе обещание «хватает на улучшение своего уровня»
  протухает к десятому); у чужого двора она выводится из его же склада (`AI_STASH_SHARE`),
  ровно так же, как гарнизон выводится из мощи, — мир про чужие постройки не знает и знать
  не должен. Одностороннего правила тут быть не может: игрок раскусит его за день.
  Слепок деревни везёт в мир **весь склад и число тайника рядом** (`stock` и `stash`);
  вычитать одно из другого заранее нельзя — делит добычу тот, кто делит, и одинаково.
  Числа и вывод таблиц — [docs/sack.md](docs/sack.md).
- **Осаждённый город и взятый город видны с карты.** Вокруг осаждённого — ров и два ряда
  рогаток (фронт ближе к городу, тыл дальше; каждый набирается по готовности своей стороны
  той же `works.sideWorks`), под павшим — нарисованный знак участи, сходящий через `FALL_MARK`
  (сутки, он же `BURN_IMMUNE`). Знак — участь, что случилась, а не объявленная
  (`WorldSave.falls`, поле необязательное, версия мира прежняя). Туман не тронут: чужую осаду
  видно только в живом обзоре, срок голода — только участнику. **Всё это спрайты поверх двора,
  а не земля**: выпечек тайлов не прибавилось ни одной, и держит это счётчик на настоящем кадре
  (`siegemark.test.ts`). Разбор и замеры — [docs/world-map.md](docs/world-map.md), «Осада и
  взятый город видны с карты».
- **Выигранный набег оставляет чужой двор разорённым, и это видно с карты.** Двор не
  исчезает и владельца не меняет — уничтожить можно только логово, — но на четыре
  реальных часа его собственные часы стоят: не растёт мощь и население, не чинится
  разбитый гарнизон, **не наполняется склад заново**. Пустым его делает не окно, а
  сам дележ (см. пункт выше); окно отвечает за то, что двор не отстраивается, —
  два эти механизма разведены и проверены тестом порознь. Механизм окна — тот же,
  что у бунта и осады, и общего у них ровно одно: потерянное время считается по
  **объединению** окон, а не по сумме (`haltElapsed`), иначе двор, разорённый
  посреди бунта, поехал бы во времени назад.
  **Разорение — свойство чужих дворов, и своя деревня им не помечается.** Прежде
  оно резало игроку выработку на четверть; с появлением дележа это стало третьим
  наказанием за одно событие — при вычищенном складе и опустевших дворах за стеной
  (`sackOutskirts`), — и убрано целиком вместе с `SACK_YIELD`, `GameState.sack` и
  `syncSack`. Асимметрия тут честная и названа словами: склад бота наполняется
  оттого, что идёт время, а склад игрока — оттого, что игрок играет.
  Набег роняет отношение и при поражении: врагов наживают нападением, а не
  победой, — и с третьего набега двор объявляет войну сам, но не больше
  `REVENGE_WARS_MAX` дворов разом, и мир у них по-прежнему покупает дипломат.
  Числа и замеры — [docs/sack.md](docs/sack.md).
- **Невольников взятого города уводят только на ступени «увести людей»** — на «ограбить» они
  **остаются** на любом пути поражения, у нас и у чужих, а на «сжечь» разбегаются. Прежде падение
  голодом уводило их всегда, а прорвавшийся набег — никогда: два пути, два правила; решено
  владельцем привязать увод к ступени (docs/DEFEAT_LADDER.md). Правило увода по-прежнему одно —
  `lead` (всех, но не больше, чем конвоирует победитель: `UnitDef.escort`, `stackEscort`), и
  зовёт его только дверь участи. У чужого города невольники выводятся из его населения
  (`AI_BONDED_SHARE`), у нашего едут в слепке (`PlayerProfile.bonded`); обратно число едет
  полем `HomeEffect.bonded`. Какой город пал, решает сам город (`id === HOME_ID`), а не
  лагерь — [docs/siege.md](docs/siege.md), «Осада по приказу игрока».
- **Логово можно убрать с карты, и это единственная такая цель.** Победа его
  сжигает: набеги оттуда прекращаются вместе с уже вышедшими, на месте остаётся
  пепелище и через несколько часов сходит само. Пока логово не трогают, оно
  крепнет и шлёт набеги сильнее и чаще — бездействие тоже стоит денег. Сила,
  добыча и срок пепелища выводятся из двух отметок времени, тика у логова нет.
  Числа, потолок роста и почему срок реальный, а не игровой, — [docs/lairs.md](docs/lairs.md).
- **Замков с казной на карте сейчас нет, и механика их спит.** Поселения мира — одни логова, а у
  логова `castle: false` (`gen.makeLair`), поэтому казна замка (`castleGold`) всегда пуста.
  Устроено спящее так: гарнизон с флагом `castle` стоит стеной и снаряжён на ступень выше
  (`garrison.ts`), взятое золото соразмерно выбитому гарнизону и едет домой добычей, ключом
  `Loot.gold`, а привезённое золото засчитывает племени взятый замок (`stats.castles`). Числа
  замка в `data/tuning.ts` (`CASTLE_CHANCE`, `CASTLE_POWER`, `CASTLE_POP`, `CASTLE_MIN_DISTANCE`)
  сейчас не читает никто. Задание и достижение «Взятый замок» убраны: недостижимое задание
  навсегда занимало место в заданиях. Вернуть их заставит тест (`data/quests.test.ts`), и в обе
  стороны: нет замков — нет заданий на них, появился замок в мире — задание обязано быть.
  **Спящая ошибка того же пути:** деньги торгового договора (`payPact`) едут тем же
  `Loot.gold` и засчитались бы взятым замком; договоров пока заключать не с кем.
  Чужие замки живых игроков — другое: это реестр (см. «Личность игрока»), и казны у них нет.
- **Карта и сцена не рисуются одновременно.** `mapOpen` в сторе гасит рендер-луп
  `TribeScene.pause()`, но сцена не разрушается: `sync` продолжает идти, возврат не
  перезагружает геометрию, и переход в обе стороны мгновенный (27 и 29 мс). Выгружать
  диораму на время карты пробовали и откатили — [docs/loading.md](docs/loading.md),
  раздел 3. Проверено замером, а не на слово: десять кругов туда-обратно оставляют ровно
  одну живую диораму (`npm run scene:report`).
- **Письмо отнимает возможность, а не посёлок.** Ожидающие решения копятся столбиком слева
  внизу в деревне: пять ячеек, одна из них под предупреждение о набеге. Срок — сутки,
  и неоткрытое письмо разрешается само тем же исходом, что и отказ, только холоднее
  (`LETTER_SILENCE_EXTRA`). Ни один исход не трогает ни людей, ни здания, ни дружину —
  полей для этого в `LetterOutcome` просто нет. Очереди за столом нет: лишнее письмо
  сгоняет то, у которого срок ближе всех, тем же разрешением и с той же **одной** строкой
  в летописи. Срок и пауза связаны равенством `LETTER_TTL / LETTER_PAUSE_MIN ≈ слоты − 1`
  и врозь не правятся. Подробно — [docs/letters.md](docs/letters.md).
- **Письмо, требующее дань или выкуп, показывает и запас** — тем же `Cost`, что стройка
  (см. «Решение, требующее отдать добро»). Число в «из N» и число, по которому мир гасит
  «Заплатить», — одно и то же: `PlayerProfile.stock`, весь склад вместе с тайником.
- **Имя поселения стоит только там, где строка переносится.** Оно приходит из данных,
  и длину его никто не обещал: самое длинное, какое может сгенерироваться, — «Логово
  разбойников». В теле письма, в строке молчания и в подписи «от кого» имя есть, и они
  переносятся; **в подписи выбора его нет ни у одного вида писем** — там сосед «оттуда»,
  «зовущие», «там». Держит это тест, подставляющий самое длинное имя. Подпись выбора у
  письма стоит под названием кнопки, а не справа: справа помещается «+40 еды» события, а
  не фраза с условием.
- **Лупа в письме показывает место, а не сведения.** Она ведёт на карту, ставит камеру на
  двор отправителя и отмечает его пульсом; **письмо при этом остаётся на столе** — ни
  ответа, ни срока, ни строки в летописи, а возврат с карты открывает его обратно
  (`letterBack`, подписка на `mapOpen` в `world/store.ts`). Клетку мир отдаёт **только
  разведанную**: у неразведанного двора лупы нет, вместо неё румб и расстояние словами.
  Выключенных кнопок нет нигде: нет источника на карте — нет и кнопки. Новых прав камере
  лупа не даёт — поводок и потолок отдаления те же, до дальнего двора она дотягивается
  единственным законным способом, отходя.
- **Числа мира правятся в `data/tuning.ts`**, а не по коду.
- Мир сохраняется своим ключом `tribe.world.v1` в localStorage. Мира на сервере
  по-прежнему нет — считает его клиент, — но **строка сохранения уезжает на сервер хранения вместе
  с партией, одной записью** (см. «Личность игрока и хранение прогресса»): без неё обещание
  «игра открывается с любого устройства» выполнялось бы наполовину — деревня приезжала бы, а карта,
  туман, походы и фигуры оставались бы дома. Сервер эту строку не разбирает. Версия формата — `WORLD_SAVE_VERSION` (7), и
  **нижняя граница равна ей же**: `MIN_WORLD_SAVE_VERSION` — тоже 7. Земля под координатами
  сменилась целиком, и замок, стоявший на 541|822, оказался бы посреди Бискайского залива:
  приводить тут не к чему и нельзя. Всё, что старше, читается как «мира нет», и мир
  собирается заново. Цепочка ступеней сейчас пуста — это состояние, а не забывчивость.
  Сохранение племени этим не тронуто.
  «Начать заново» в заданиях пересоздаёт и мир (`resetWorld`).
- **Перехват в поле считается уравнением, а не тиком.** Движение — прямая с постоянной
  скоростью, выведенная из времени выхода и прибытия, поэтому точка встречи решается один
  раз, в момент приказа (`world/pursuit.ts`, чистый модуль). Смена курса цели — новое
  событие выхода, и встреча пересчитывается в нём же. Фоновой работы за перехватом нет и
  заводить её нельзя.
- **Вместимость отряда полководца даёт Статуя Героя**, а передача дружины идёт время в
  обе стороны: пока она идёт, эти люди не защищают деревню и не годятся в бой. Без
  вместимости гарнизон уводили бы в поле целиком, и оборона перестала бы быть решением.
- Чего в этом этапе нет и что не надо доделывать по дороге: торговля между игроками, порты,
  временные события на карте, фильтры сверх базовых, вторые полководцы, разделение войска
  на отряды. Место в данных заложено (`lootMix`, `Rect`, стадии,
  вторая вкладка рынка, `troops` у фигуры), реализации быть не должно.

## Бой

Боевая система описана в [docs/BATTLE_SYSTEM_FOR_CLAUDE.md](docs/BATTLE_SYSTEM_FOR_CLAUDE.md) —
**читать целиком перед любой работой над боем**. Сделаны ядро (`src/battle/`), мост из племени
(`src/game/battle/`), разрешение боя в мире, интерфейс подготовки с отчётом и режиссура ролика
о бое. Сервера, PvP, фейковых атак и осадных машин нет — они идут следующими шагами и не должны
появляться по дороге.

**Ролик о бое — проигрыватель журнала, а не второй симулятор**; камера, строй, число фигур и
подписи выводятся из журнала, а не считаются заново. Не хватает данных для показа — журнал
дописывается, а не добирается из симуляции: так в запись боя попали состав по видам бойцов
(`BattleRecord.troops`, мост — `game/battle/faces.ts`), потери по секторам на фазу
(`PhaseSpan.bySector`) и место с часом (`BattleRecord.place`, мост — `game/battle/ground.ts`).
Раскадровка, такты камеры, строй и бюджет кадра — в [docs/battle-replay.md](docs/battle-replay.md).
Сделаны пять пачек: режиссура, масса (знамёна, лес древков, пятно под строем — фигур на сторону
не больше сорока четырёх, и число показывается массой, а не ими), действие (залп стрел, клин
конницы, удар линий с замиранием, паника от края), красота (низкое тёплое солнце по игровому
часу, земля той клетки, где случился бой, небо градиентом, поле после боя) и звук — музыка слоями
по тактам (`src/sound/`).

**Музыка идёт слоями из раскадровки, и без жеста игрока не звучит ничего.** Слой выбирает такт
(`MUSIC_BY_ACT`): ударные — близкий план, гармония — отъезд и залп, полный трек — бой, тишина —
спуск и финал. Звуковой контекст открывается только в обработчике нажатия «Смотреть бой»
(`battleMusic.arm()`) — переключателя звука в самом ролике больше нет, музыка правится в
настройках (см. «Музыка»), — выключенный звук не грузит файлов вовсе, а сами дорожки лежат в
`public/assets/music/` и в бандл не попадают — сборка без них собирается и работает молча.
Звуков боя (свист залпа, грохот удара) нет и в этой пачке не будет.

**Слоёв сейчас нет, и это состояние пака, а не кода.** Боевой пак, который приехал, стемов не
содержит — пять цельных пьес. Что качать и с какими громкостями это играть, решает `MUSIC_MODE` в
`sound/manifest.ts` одной строкой; в цельном режиме такт меняет не материал, а громкость одной
дорожки, и `silence` по-прежнему означает обрыв перед финалом. **Обе половины режима живут в
манифесте** (`battleFiles`, `battleLevels`, `battleLoop`): разведи их по модулям — и следующий
режим окажется реализован наполовину. Просить у сервера три файла, которых заведомо нет, нельзя:
это три 404 на каждый первый бой.

**Показ не читает мир.** Земля и свет выводятся из записи боя чистой функцией, а не добираются из
карты в момент показа: иначе раскадровка перестанет быть самодостаточной ровно тогда, когда журнал
приедет с сервера. Отсюда и `BattleRecord.place`. **Зимнее поле боя красит только себя**: у сцены
боя свои материалы и свой ключ снега (`fieldSnow`), общий сезонный механизм на неё не
распространяется — иначе ролик, запущенный зимой, перекрасил бы деревню, которая рисуется теми же
материалами.

**У леса древков нет своей геометрии: он живёт на решётке строя.** Место древка — то же
`figureSpot`, по которому стоит фигура, и второго способа сказать, где стоит боец, у показа быть не
должно: своя, более плотная решётка у леса и была причиной древков без хозяина — сразу в промежутках
между шеренгами, за флангом и вокруг конницы. У конницы леса нет вовсе, длина древка — то же копьё,
что кладётся в руку (`SPEAR_LEN`), а включается лес по видимому размеру бойца (`SHAFT_PX`), а не по
такту камеры: подменять невидимого бойца древком можно там, где подмену не поймать глазом.

**Цвет — это сторона, на всех деталях бойца, включая щит.** Наши в синем, чужие в красном; по
любому кадру должно быть видно, где чьё войско и где они сошлись. Однотонность здесь не бедность,
а всё правило: щит — самая большая плоскость бойца, и «вернуть ему дерево для разнообразия»
значит его сломать. Разнообразие идёт силуэтом — форма щита, оружие, рост, гребень, — а не цветом.

- **`simulateBattle(input)` — чистая детерминированная функция.** На вход состав и настройки
  обеих сторон плюс сид, на выход исход, потери и журнал. Модуль ни от чего не зависит: ни
  `@/`-импортов, ни React, ни three, ни состояния игры, ни `Math.random`. Это условие того, что
  ровно этот код потом запустит сервер, а клиент прогонит его же для показа. Новый импорт извне
  в `src/battle/` — ошибка.
- **Все числа — в `battle/config.ts`.** Треугольник контрров (`COUNTER`), характеристики родов
  (в том числе базовая мораль), снаряжение (`GEAR`), характер (`TEMPER`), тики фаз, мораль
  (`MORALE`), планы, приказы. Логика в `sim.ts` только читает таблицы; баланс правится без
  правки логики. Числа кольца (×2.0, ×1.8, ×0.5, ×1.5, ×0.8, ×0.7) стоят как в документе;
  конница против пехоты — ×1.3 (документ поправлен: при ×1.0 одна пехота была почти оптимальна).
- **Мораль своя у каждого сектора**, не у армии. Сектор с нулевой моралью бежит и не держит
  линию, паника перекидывается на соседей, армия отступает, когда сломанные сектора весят
  половину или линии больше нет. Это и есть нормальный конец боя: до гонга доживают доли
  процента. Ограничитель держит тест: при перевесе 10% размен не выше ≈1.5 — сломанная армия
  выходит из контакта сразу, потолок преследования 4%, фаза морали после слома обрывается.
  Мораль — характеристика рода (пехота ниже копейщиков) плюс ступени снаряжения `gear`
  в расстановке; характер родов — множитель потерь морали по ситуации. В модели морали каждая
  лишняя потеря стоит дорого: планы выровнены заново (матрица «план против плана» в отчёте),
  копьям снижена база — при 70 они не проигрывали никому.
- **Шесть секторов и резерв, девять фиксированных фаз.** Полоса 0 — левый фланг со стороны
  своей армии; левый фланг нападающего стоит против правого фланга обороняющегося (`facing`).
  Бой всегда укладывается в 50–100 тиков: стрелковая фаза 8–20 (темп планов), остальные
  фиксированы, бой линий может оборваться раньше, когда сторона сломалась, — тогда обходы и
  ввод резерва пропускаются, а фаза морали, отступление и преследование идут всегда.
- **Превосходство условно.** Копья ×2.0 против конницы только пока держат линию (`advance` даёт
  ×1.2); конница ×0.5 о сомкнутые копья — в лоб или в закрытый тыл (тыловое каре сомкнуто со всех
  сторон, фронт — только спереди); лучники после того, как их цель вошла в рукопашную, бьют
  ×0.3 (`afterContact`), а «держать дистанцию» работает только против тех, кто медленнее. Копья
  медленные: пока быстрых нет ни у кого, рукопашная начинается на `SLOW_CONTACT.delay` позже.
- **Журнал — часть ядра, не украшение.** События именованные (`BattleEvent`), с фазой, тиком,
  стороной и сектором: залп до контакта, копья остановили удар, конница вырубила лучников, фланг
  обойдён, сектор смят, резерв вошёл, мораль рухнула, проиграли размен. События о размене
  выводятся из матрицы «кто кого выбил» по полосам (`kills`), порог значимости — `EVENT_MIN`/
  `EVENT_SHARE`. Отчёт потом строится из журнала; событие, которого нет в журнале, в отчёт
  не попадёт, поэтому новая механика обязана писать своё событие.
- **Быстрая атака — четыре пресета** (`QUICK_PRESETS`: стандарт, анти-кавалерия, удар по
  центру, оборона), `quickAttack(army, seed, intel)` берёт один по сиду похода детерминированно,
  разведданные сдвигают веса — **любой давности**: мир отдаёт в бой состав из последнего
  снимка (`save.intel[…].kinds`) и возраста его не спрашивает. `quickSetup` — стандартный
  пресет, им пользуются тесты.
  Известный контрер стандарта выигрывает у него ≈75%, у случайного пресета — ≈20%: контрить
  нечего, пока не знаешь, какой пришёл. Настроенная армия (`bench.ts`, `TUNED`) против быстрой
  атаки — ≈17%, коридор 10–25% держит тест; потолок по перебору 192 расстановок ≈25%.
  Пресет без якоря пехоты на флангах — ловушка (проигрывал заякоренным на 40–90%), резерв
  с приказом «держать фланг» выходит навстречу обходу — иначе тыл любого пресета открыт.
- **Тесты — раздел 16 документа целиком** (`battle.test.ts`): нет доминирующего состава,
  разрыв быстрой атаки и известный контрер, кольцо по парам, условность превосходства,
  досрочный конец боя, ограничитель перевеса 10%, паника и якорь, мораль как характеристика
  и снаряжение, пресеты, детерминированность, 50–100 тиков, осмысленный и непротиворечивый
  журнал. Наборы для них — в `bench.ts`, и те же наборы печатает `npm run battle:report`
  (матрица составов с победами/ничьими/поражениями и разменом, кольцо, планы, пресеты, разрыв,
  длительность с долей досрочных, ограничитель; `SHOW=а:б SEED=n SCALE=1.1` — журнал одного
  боя с моралью секторов и потерями по фазам). `npm run battle:sweep` с `GRID='[{...}]'` —
  быстрый перебор чисел конфига. **Меняешь число в конфиге — смотри отчёт, не гадай.**
  Баланс в модели морали стоит на лезвии: в зеркале одинаковых армий перевес в 5% даёт 10/0/0,
  поэтому **все пороги — по размену** (`RATIO_EVEN`), а не по счёту побед; счёт поля в отчёте
  показывается рядом, но выводов по нему нет. Поле держит тот, у кого дольше мораль (копья), и
  это замысел — не чинить; следствие закрыто третьей категорией исхода: **победа с непомерными
  потерями** (`pyrrhic`, размен ниже `PYRRHIC_BELOW`), у каждой стороны `verdict`, журнал
  называет её прямо. Составы без пешей линии в ограничителе держат свой потолок
  (`OVERSIZE_CAP.noLine`), а не исключены из него.

### Мост из племени в бой

Ядро про племя не знает и знать не должно. Отображение живёт в `src/game/battle/`, и обратной
зависимости быть не может: оттуда в ядро идут только типы.

- **`kinds.ts` — восемь видов бойцов в четыре рода боя.** Мощь вида (`TroopDef.power`) переводится
  в бойцов строя: `BATTLE_MAN = 2`, дубинщик — единица измерения, латник весит восьмерых. Иначе
  экономика не сходится: ядро знает только род и ступень снаряжения, а она даёт мораль, не урон,
  и один латник считался бы за одного дубинщика. Ступень `gear` — число предметов кузницы на
  бойце (0..3). Потери рода возвращаются в виды слабыми вперёд, как в `removeSoldiers`.
  **Конница у племени есть:** всадник (`rider`) — единственный верховой вид, его нанимают в тех же
  казармах, и он дороже любого пешего сразу по трём статьям (ресурсы, снаряжение, время учений):
  конь, сбруя и седло. Без него у игрока были бы мертвы угол кольца «конница бьёт лучников», план
  «кавалерийский удар», кавалерийские приказы и перехват обхода резервом — а у чужих гарнизонов
  конница есть всегда, и кольцо работало бы в одну сторону. Отдельного здания под него не заводить:
  конюшня и лошади как ресурс — следующее решение, а не побочный эффект. Тест гоняет настоящие бои:
  всадники режут лучников и вязнут в сомкнутых копьях.
- **`formation.ts` — расстановка глазами игрока**: свои виды бойцов по шести секторам и резерву,
  плюс план, приказы и условие ввода резерва. Панель показывает те же числа, что казармы;
  в роды и бойцов строя это переводит `toArmySetup`, и только он (округление одно на род, иначе
  отряд то прибывал, то убывал на человека при перекладывании между секторами). `clampFormation`
  подрезает схему под наличный гарнизон — на этом держатся и шаблоны, и оборона, пережившая потери.
- **Ополчение** — та часть обороны деревни, которую дают не бойцы, а частокол, башня и жители
  (`militiaMen`). В поле оно выходит пехотой без снаряжения и встаёт во фронт само: расставлять
  частокол игроку незачем. **Башня переводит часть его в стрелков** (`militiaArchers`): они
  встают во вторую линию. В этом и разница двух укреплений — частокол даёт плоскую оборону,
  башня почти не даёт её, зато ставит людей на стену с луком.
- **Герой** (`s.hero`) — единственный поимённый человек в игре. Его даёт Статуя, он уходит с
  одним походом за раз и приводит `heroMen` бойцов строя в выбранный род (`toArmySetup`).
  Мощь армии он не трогает: `armyPower` ничем не множится. Род меняется в Статуе за золото.
  Павший не пропадает — выбывает на `HERO_DOWN_DAYS` и возвращается. С быстрой атакой он не
  ходит: там расстановку выбирает пресет по сиду, и вести ему некого.

### Описание вида бойцов

`game/battle/describe.ts` — единственное место, откуда интерфейс берёт слова и числа про
войско: карточка вида (`ui/parts/TroopCardView`) и кольцо контрров (`ui/parts/CounterRing`)
только раскладывают то, что вернул `troopCard(troop)`.

- **В JSX не пишется ни одного множителя и ни одной характеристики.** Причина простая: после
  следующей правки баланса рукописный текст разойдётся с настоящим числом, и игрок будет
  учиться неправде. Новая механика боя обязана появиться здесь строкой, а не в разметке.
- **Множители читаются из конфига при каждом вызове**, а не запекаются в константы модуля:
  `specs()` — функция, и правка `COUNTER` немедленно меняет строку на карточке. Это и
  проверяет `describe.test.ts`: подменили число в конфиге — изменился текст.
- **Показываются и невыгодные множители.** Карточка — не рекламный листок: у каждого рода два
  списка, «чем бьёт он» (`dir: 'out'`) и «чем бьют его» (`in`), и у каждой строки написано
  условие, при котором множитель вообще действует.
- **Сильные и слабые стороны выводятся правилами, а не перечисляются.** Правило — это вопрос
  к конфигу: самый высокий свой множитель, самый низкий, самый больной чужой, самая высокая
  мораль рода, самая высокая мощь, самый долгий наём, порог `SLOW_CONTACT`, ступень `GEAR`,
  якорь `ANCHOR`. Порядок правил и есть их важность; берутся первые три, которым есть что
  сказать про этот вид. Тест держит договор: у каждого вида две-три строки в каждом разделе,
  а «самый-самый» переезжает к другому виду вслед за правкой конфига.
- Руками здесь пишутся только слова, которых из числа не выведешь: падежи родов, названия
  ситуаций `TEMPER` и условия множителей. Само число всегда рядом и всегда из таблицы,
  а приказы в условиях называются теми же словами, что и в панели приказов (`ORDER_NAMES`).

### Подготовка боя и отчёт

- **Подготовка боя и оборона поселения — одна панель** (`ui/panels/BattlePanel.tsx`): у боя цель и
  кнопка удара, у обороны таймер и заморозка. Всё остальное общее, и разводить это по двум экранам
  значило бы держать две копии одной панели. Состав в бою не выбирается: армия уже стоит у ворот
  при полководце, и менять её можно было только дома.
- **Перетаскивания в расстановке нет и не должно появиться**: на 375 px внутри шторки оно дерётся
  со скроллом. Тап по сектору открывает выбор состава прямо под схемой.
- **Нерасставленные войска видны отдельной клеткой** и при отправке уходят в резерв — потерять
  половину армии по недосмотру нельзя.
- **Быстрая атака — один тап в карточке цели**, у которой стоит полководец, без захода в подготовку:
  тем, что при нём, а расстановку выберет пресет по сиду.
- **Прогноза исхода нет нигде.** Ни шансов, ни предварительного расчёта: игрок не знает плана и
  резерва противника, и вся неопределённость держится на этом. Показав вероятность, мы убьём
  и разведку, и блеф.
- **Разведданные показываются в окне расстановки**: состав по родам, построение по шести секторам
  и отметка возраста. Резерв и план в снимок не попадают никогда. Данные устарели — так и сказано,
  а не показана пустота.
- **Оборона запирается за пять минут до прихода чужой армии** (`DEFENSE_FREEZE`). Отметку считают
  двое по одной формуле: `defenseLock` для панели и `LocalWorld.lockDefense` для мира. Запертую
  панель показывают запертой, а не игнорируют нажатия молча.
- **Отчёт строится из журнала** (`battle/report.ts`), а не из чисел рядом: события, которого нет
  в журнале, в отчёте не будет. Три категории исхода словами, потери обеих сторон, ключевые
  события и журнал по фазам. Две кнопки — мгновенный итог и просмотр; выбор запоминается
  (`s.battleWatch`), при несопоставимых силах подставляется итог.
- **Бой считается там, где стоит полководец**, а не при отправке: пока фигура шла через карту,
  защитник мог перестроиться — это та же фора, ради которой бой раньше считался на приходе отряда.
