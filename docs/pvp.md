# Война между игроками

Рабочий документ ветки `game/pvp` (05.10.2026, облако). Цель владельца — закрытый тест с небольшой группой
игроков: весь путь войны от найма до итога у обеих сторон работает и понятен. Баланс и красота — потом.

## 1. Разбор: что было на `347ec9c`

До этой ветки «между игроками не происходит ничего» — правило устройства, а не недоделка
(docs/sync.md, раздел 4): замки живых игроков лежат отдельным списком (`LocalWorld.castles`), вне
`gen.settlements`, и до них не дотягивается ничего, кроме карты. Мир живёт на клиенте (`LocalWorld`), сервер
хранит партию непрозрачной строкой и читает ровно две записи — реестр замков и исходящие уведомления.

| Что | Было | Где |
| --- | --- | --- |
| Чужой замок на карте и его карточка («Город соседа»), туман и снимок с датой | есть | `castleView`, `castleCard`, реестр `/api/castles` |
| Выбрать чужой замок целью похода | **нет** | `castleCard`: `can` — все `false`; `touching`, `attack`, `besiege`, `send` ищут только в `gen.settlements` |
| Поход к другому игроку на сервере | **нет** | у сервера четыре адреса: `save`, `castles`, `notify`, `time` |
| Расчёт боя на сервере | **нет**, но ядро годится | `src/battle` чистое; `world/battle.resolveField` — одна дверь в ядро; сервер собирает его (esbuild берёт пути `@/` из корневого `tsconfig.json`, `tsc -p netlify` — с путями) |
| Время похода | есть, чистая | `geo.travelTime` + `terrainFactor`, без `@/` |
| Защитник узнаёт о походе (тревога, срок прихода) | **нет** для игроков | есть только для набегов логов: `visibleMarches`, `store.marchesOnHome` |
| Итог, отчёт и ролик у защитника | **нет** для игроков | у набега логова — `gateRecord`, `site: 'wall'` |
| Штурм | против логова и двора мира | `attack` → `attackAt` |
| Осада лагерем, часы голода, падение | против логова и двора мира | `besiege` → `openSiegeAt`, `siege.ts`, `siegeFalls` |
| Штурм из лагеря, отход | свой лагерь под логовом | `attack` (снимает осаду до боя), `retreat` → `leaveCamp` |
| Вылазка гарнизона | только против лагеря логова под своим городом | `sortie` → `campBattle` |
| Удар с тыла, совместный удар | только против лагеря логова под своим городом | `strikeCamp` → `resolveStrike` → `campBattle` |
| Что осада делает с городом | частично | хлеб не идёт, прочее — четверть (`derived.siegeYield`); найм и торговля не стоят; гарнизон не слабеет |
| Ролик боя | есть для всех мест | `BattleRecord.site`: `wall`, `sortie`, `camp`, `joint` |
| Защита слабого | против логов | `lairs.weakCity` (жители или мощь войска) |
| Регион | для логов и приказов | `theatre.inHomeTheatre` |

Итог разбора: механика осад и боя целиком на клиенте и целиком против мира; против игрока нет ни одной
двери, а серверу нечем ни посчитать бой (он не видит войска защитника), ни сказать о нём другой стороне.

## Передача

- Ветка `game/pvp` от `347ec9c` (`origin/master`). Шаг 1 (разбор) — раздел 1.
- Шаг 2а — сервер: `/api/war` (`netlify/lib/routes/war.ts`, правила — `netlify/lib/war.ts`), общая дверь боёв
  `src/world/fights.ts` (мир на клиенте зовёт её же: `gateField`, `gateLosses`, `campBattle`), путь войны
  `src/world/pvp.ts`, слепок обороны `SaveRecord.war` (`contract.WarSheet`). Тесты сервера зелёные.
- Дальше: клиент — слепок в запись партии, опрос `/api/war`, мир показывает войну (поход, тревога, лагерь, окно
  осады, вылазка, удар) и применяет итоги; интерфейс карточки чужого города.
