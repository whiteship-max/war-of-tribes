# Пакет передачи визуала — TRIBE

Снято 5 сентября 2026 года с ветки `master` (`1b9407b`). Всё снято или скопировано
в один заход, поэтому картинки, палитра и числа согласованы между собой.

**Снимков в репозитории нет** — `docs/handoff/shots/` в `.gitignore`. Они лежат
отдельным архивом `tribe-handoff-shots-2026-09-05.zip` и передаются отдельно: это
23 МБ картинок, которые стенд пересоздаёт с любого коммита за пару минут (адреса —
в разделе «Как пересняты»). В git остаются README, копии `palette.ts` и `figures.md`
и замеры — они маленькие и документируют состояние на этот коммит.

Стиль — low-poly с плоским затенением, без единой текстуры. Качество делают свет,
палитра и посадка в землю, а не полигоны. Прежде чем что-то менять, прочитайте
[figures.md](figures.md) (фигуры) и раздел «Графика» в корневом `CLAUDE.md` (всё остальное).

### Как пересняты — и как переснять

Всё снято стендом-витриной, а не руками: `npm run dev`, потом адрес вида

```bash
npm run dev
```

- здание: `?showcase=building&type=<id>&tiers=0,1,2&dpr=1.5&snap=b_<id>`
- стена: `?showcase=building&type=palisade&tiers=0,1,2&spacing=24&margin=0&dpr=1.5&snap=b_palisade`
  (стена — кольцо радиусом 15.6, при обычном шаге три ступени налезают друг на друга)
- войска: `?showcase=units&units=clubman,spearman,archer,axeman,swordsman,shieldman,rider,legionary&dpr=1.5&snap=u_troops`
- горожане: `?showcase=units&units=folk0,folk1,folk2&dpr=1.5&snap=u_folk`
- конь: `?showcase=units&units=horse&turn=90&zoom=0.45&dpr=1.5&snap=u_horse` (профиль: одиночную фигуру надо отодвинуть `zoom`, иначе кадр её режет)
- герой: `?showcase=units&units=hero&hero=swordsman&action=guard&zoom=0.4&dpr=1.5&snap=u_hero`;
  рядом с рядовым того же вида — `?showcase=units&units=swordsman,hero&hero=swordsman&action=guard`
- строй: `?showcase=units&count=40&dpr=1.5&snap=u_formation40`
- посёлок: `?showcase=village&levels=10&dpr=1.5&snap=v_l10`
- силуэт: к любому из них `&silhouette=1`; вид сбоку — `&turn=90`

`?snap=имя` работает только на dev-сервере: страница шлёт PNG на `POST /__snap`,
а плагин `snapPlugin` в `vite.config.ts` кладёт файл в `snaps/`. На выложенной
сборке такого адреса нет и снимок просто не сохраняется.

## 2. Точки входа

### Фигура

Одна фигура — это `Figure`: скелет из суставов плюс список «слотов», каждый слот —
один из **семи** примитивов (`limb`, `body`, `head`, `cap`, `shaft`, `plate`, `shield`).
Своих мешей у фигуры нет вовсе: рисует всех разом пул инстансов, по одному вызову
на примитив, поэтому сорок бойцов стоят ровно столько же вызовов, сколько один.

| Что | Где |
| --- | --- |
| `Figure`, `PARTS`, `addSlot`, `FigurePool` | [`src/render/figures.ts`](../../src/render/figures.ts) |
| скелет человека и его пропорции | `humanRig(height, build)`, `MAN_HEIGHT = 1.05` — [`units.ts:22,48`](../../src/render/units.ts) |
| скелет коня | `mountRig(height)` — [`units.ts:370`](../../src/render/units.ts) |
| **боец** | `dressSoldier(f, troop)` — [`units.ts:256`](../../src/render/units.ts) |
| **горожанин** | `dressVillager(f, kind)`, `FOLK_KINDS = 3` — [`units.ts:130,136`](../../src/render/units.ts) |
| **герой** | `dressHero(f, troop)` — [`units.ts:354`](../../src/render/units.ts): тот же `dressSoldier` плюс рост и плащ |
| **конь без всадника** | `dressMount(f)` — [`units.ts:424`](../../src/render/units.ts) |
| позы | `poseFigure(f, action, t)`, `ACTIONS` — [`src/render/poses.ts`](../../src/render/poses.ts) |
| кто стоит в сцене | `villagers.ts` (свободные руки), `soldiers.ts` (дружина), `hero.ts` (герой у статуи) |

**Чем боец вооружён, фигура не решает.** Оружие в руках, щит и ступень снаряжения
выводятся из `TroopDef.gear` в [`src/game/data/troops.ts`](../../src/game/data/troops.ts)
через `weaponOf` / `hasShield` / `hasArmor` / `gearOfTroop`
([`game/battle/kinds.ts`](../../src/game/battle/kinds.ts)) — из того же поля, по которому
карточка вида в интерфейсе называет предметы ковке. Второй таблицы «у щитоносца щит,
у лучника лук» в сцене быть не должно: две правды об одном бойце расходятся молча
и ровно тогда, когда снаряжение вида меняют.

### Здание

| Что | Где |
| --- | --- |
| **модель здания** | `createBuildingGroup(type, tier)` — [`buildings.ts:1218`](../../src/render/buildings.ts) |
| какая ступень у уровня | `visualTier(level)`, `VISUAL_TIERS` (1–3 / 4–7 / 8–10) — [`buildings.ts:17`](../../src/render/buildings.ts) |
| подрост внутри ступени | `levelScale(level)` — [`buildings.ts:24`](../../src/render/buildings.ts) |
| стиль: роли и черты | `ROLES`, `FEATURES`, `STYLE`, `stylePaint()` — [`buildings.ts:55,90,107,114`](../../src/render/buildings.ts) |
| набор деталей | [`src/render/kit.ts`](../../src/render/kit.ts): `box`, `roofGable`, `roofCone`, `chimney`, `door`, `halfTimber`, `porch`, `fenceRun`… |
| склейка в один меш | `K.assemble(parts)` для нового кода, `K.collapse(root, GROUND_AO)` для старых моделей — [`kit.ts:432,481`](../../src/render/kit.ts) |
| леса при улучшении | `scaffold(w, d, h)` — [`buildings.ts:930`](../../src/render/buildings.ts) |

Порядок сборки один: детали набора → `assemble` → один меш, группы по материалу,
**один вызов отрисовки на материал**. Из набора пока переведены Жилища; остальные
модели живут в старом коде, но проходят через `K.collapse`, который делает с ними
то же самое. Новая модель без склейки — ошибка: вызовов у неё будет по одному на доску.

Материалы — три несмешиваемых набора: `KIT` (с цветом вершин, для склеенной геометрии),
`LEGACY` (без него), `DECAL` (наложения на землю). Материал с `vertexColors`, получив
геометрию без атрибута `color`, красит её чёрным.

### Цвет

[`palette.ts`](palette.ts) — **единственное место с hex во всём проекте**. Материалы
(`render/materials.ts`) и зимние переопределения берут цвет отсюда по имени; цвет
«по месту» — ошибка. Правила записаны в шапке файла: hex — это то, что видно на
освещённой солнцем горизонтальной грани в полдень; теплохолодность делает свет, а
не краска; чистого белого и чёрного нет ни в одном канале, кроме огня. Сезон не
заменяет палитру, а переопределяет её часть (`SEASON_OVERRIDES`): снег ложится на
то, что лежит горизонтально. **Новый материал, на который ложится снег, обязан
попасть в зимние переопределения** — иначе зимой он останется летним.

Свет — [`render/lighting.ts`](../../src/render/lighting.ts): один тёплый направленный
источник с тенью (52° в полдень, никогда в зените), холодная полусфера сверху и тёплая
снизу, `NeutralToneMapping`. Синева теней получается сама. Второй источник с тенью
не заводить. Риг общий у игры и стенда — иначе снимки отсюда ничего не доказывают.

## 3. Откуда берутся габариты

Габарит здания записан **дважды и по разным поводам**, и оба числа обязаны сходиться
с моделью:

| Число | Где | Зачем |
| --- | --- | --- |
| `FOOTPRINT[type]` → `footprintOf(type, tier)` | [`buildings.ts:1177,1206`](../../src/render/buildings.ts) | основание модели в метрах сцены; по нему считаются мишень тапа, леса и декали земли. Ступень раздаёт его множителем `TIER_SPREAD` = 1 / 1.22 / 1.45 |
| `MODEL_RADIUS[type]` → `plotRadius(type)` | [`plan.ts:59,97`](../../src/render/plan.ts) | радиус площадки в плане посёлка. Место резервируется по **третьей ступени на десятом уровне**: `MODEL_RADIUS × PLAN_SCALE × levelScale(10) + PLOT_MARGIN` |

Общий масштаб посёлка — `PLAN_SCALE = 0.62` ([`plan.ts:20`](../../src/render/plan.ts)):
модели рисовались под прежнюю вольную расстановку и для кольцевого посёлка велики.
**Стена — исключение, её масштабировать нельзя:** она и есть это кольцо,
`WALL_RADIUS = 15.6`.

Планировка — не автоподбор места, а таблица: у каждого типа своё именованное место
`PLAN[type]` (кольцо + угол), кольца `RING_RADIUS = [0, 5, 8, 11.9, 20]`, четвёртое
кольцо (`OUTSIDE_RING`) лежит **снаружи стены** — там стоят ресурсные дворы. Вокруг
всего этого зона расчистки `CLEAR_RADIUS = OUTSKIRTS_RADIUS + CLEAR_MARGIN`, внутри
которой не бывает ни деревьев, ни камней, ни декора.

**Меняете модель — правьте оба числа и прогоняйте `plan.test.ts`.** Он читает
настоящие модели всех ступеней и сверяет с таблицей.

Габариты фигур — в [`figures.md`](figures.md): рост человека `MAN_HEIGHT = 1.05`
единицы сцены (это 1.79 м эталона), всё остальное задано долями от него, включая коня.

Настоящее устройство, 392×735 @ dpr 2.75, Chrome 151 / Android. Восемь секунд
вращения камеры, кадры считаются по `afterRender`.

| Сцена | Вызовов | Треугольников | fps | Худшие 5 % |
| --- | ---: | ---: | ---: | ---: |

| Сцена | Вызовов | Треугольников |
| --- | ---: | ---: |
| посёлок, уровень 1 | 164 | 46 020 |

## 6. Что стоит знать, прежде чем править

- **Лес стоит дёшево, и это условие его существования.** Сплошной пояс не добавляет
  ни одного вызова (он склеен), но давал 45k треугольников из 115k. Резать его нельзя —
  он держит композицию. Вместо этого сняты две платы: окружение **не отбрасывает тень**,
  а дальние деревья рисуются одним конусом без ствола и донца (5 треугольников против 44).
  Новый объект окружения обязан вписаться в это.
- **Модель пересобирается только при смене ступени**, не на каждом уровне. Улучшение
  модель не трогает — вокруг неё появляются леса, здание продолжает работать.
- **Занятость показывает здание, а не человек** (`worksigns.ts`): груз у стены, дым из
  трубы, горн у кузницы. Ходьбы на работу нет и не должно появиться. Имя меша `forge`
  менять нельзя: по нему сцена находит горн кузницы.
- **Стенд собирается и в продакшен** — это инструмент, а не отладочная ветка. Гейта по
  `import.meta.env.DEV` у него нет и заводить его нельзя, иначе замерить телефон на
  выложенном адресе будет негде. В игру он не попадает: отдельный чанк (5.2 КБ gzip
  в сегодняшней сборке), грузится только по `?showcase=`.

## 7. Найдено и починено при сборке пакета

Три расхождения между документацией и кодом, все исправлены этим же коммитом:

- Зданий **24**, а не 23, как было написано в `CLAUDE.md` и `docs/BUILDINGS.md`. Полный
  список: `campfire, town_hall, houses, storage, gathering, sawmill, quarry, hunter_hut,
  mine, workshop, farm, pen, church, statue, infirmary, watch, stable, cache, tavern,
  palisade, tower, smithy, market, barracks`.
- `CLEAR_MARGIN` в коде — **2.6**, в `CLAUDE.md` было записано 3.2.
- `docs/BUILDINGS.md` всё ещё описывал **Дом вождя (`chief_house`)** с панелью
  `ui/parts/ChiefHouse.tsx` — здания с таким именем нет с переименования в Ратушу
  (`town_hall`, коммит `3b6570a`). Раздел переписан, добавлен множитель скорости
  стройки `townHallBuildMult`, которого в справочнике не было вовсе.

Плюс одна правка стенда: у него не было режима показа героя отдельной фигурой
(в каталоге были только горожане, войска и конь). Добавлен
`?showcase=units&units=hero&hero=<вид>` — одевается тем же `dressHero`, что и герой
у статуи, второй правды о его виде не заведено. `HERO_SCALE` вынесен в экспорт
из `render/hero.ts`.

## 8. Ограничения проверок и срез фигур (05.09.2026)

- Старый тест пула сравнивает число мешей с `PARTS.length`, поэтому сам по себе
  не ловит расширение списка примитивов. В срезе фигур отдельная проверка
  `articulation.test.ts` фиксирует именно семь разрешённых примитивов.
- Проверка `MODEL_RADIUS` обмеряет только третью визуальную ступень здания.
  Первые две ступени этим сравнением не защищены. Здания в срезе фигур не менялись.
- Читаемость на ширине 390 px автоматические тесты не доказывают: нужны кадры
  при игровом масштабе, цвете стороны и разных направлениях.
- `TribeScene` обновляет тень через кадр, а `runPerf` сохраняет счётчики последнего
  кадра. Поэтому число из телефонного JSON нельзя смешивать со случайным кадром
