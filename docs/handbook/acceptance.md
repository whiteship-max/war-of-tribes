## Как `npm run reports` выбирает и сверяет (правило 9)

*Правило — `CLAUDE.md`, «Работа с ветками», правило 9; здесь — устройство целиком.*

   **Принцип: какие отчёты гнать, решает подсчёт, а не человек и не таблица.** Команда берёт
   изменённые файлы — `git diff origin/master..HEAD` плюс незакоммиченное в рабочей копии — и
   гонит те отчёты, в чьё **замыкание** попал хоть один. Замыкание выводится из самих файлов
   (`scripts/lib/deps.ts`): импорты, строки, называющие существующий файл или папку
   (`'../dist'`, `'/assets/music/'`, куски `path.join`), и три свойства инструментов — кто
   поднимает vite сервером или сборкой, тот отдаёт `index.html` со всем достижимым и всю
   `public/`; кто читает `dist`, тот зависит от команды `build` целиком; кого запускает vite,
   тот читает `vite.config.ts`, каждый `tsconfig.json` и `package*.json`. Отчёты — это
   команды `*:report` из `package.json`, их список тоже не пишется. Таблицы «файл → отчёты»
   нет и заводить её нельзя: написанная рукой, она разошлась бы с кодом при первом новом
   импорте, и не заметил бы никто — ровно так расходились подписи с механиками.

   **Страховка: сомнение — гоняем все двадцать четыре** (двадцать второй — `stability:report`, СБ-1, двадцать третий — `market:report`, РН-1, двадцать четвёртый — `roam:report`, ПН-0). Полный прогон, если хоть одно из:
   - изменений нет вовсе;
   - подсчёт упал, или в замыкании отчёта есть то, чего он не понял: импорт не разрешился,
     `import()` не строкой, `import.meta.glob`, команда отчёта без входного файла;
   - изменился сам подсчёт — `scripts/reports.ts` и всё, что он импортирует, `package.json`,
     `package-lock.json`, `vite.config.ts`, `tsconfig.json`: судья, которого правят, не судит;
   - изменился файл **без владельца**. Владелец у файла — отчёт, чьё он замыкание; тесты
     (`test.include` и всё, что из них достижимо, вместе с импортами одних типов — их держит
     `typecheck`); прочая команда `package.json` (`map:shots`, `world:build`…); документ из
     белого списка `docs/`, `CLAUDE.md`, `README` (`affected.DOCS`). Файл, которого не читает
     никто из них, — файл, про который неизвестно, что он делает.

   Причину полного прогона команда печатает словами. Изменились только тесты, документы и
   файлы инструментов — отчёты не нужны, и это тоже вывод подсчёта, а не разрешение.

   **Подсчёт проверяет себя каждым прогоном.** Отчёт гонится с записью прочитанного
   (`scripts/lib/trace-fs.mjs` через `NODE_OPTIONS`, наследуют и дочерние процессы), и файл
   репозитория, прочитанный мимо замыкания, роняет приёмку строкой «ПРОЧИТАНО МИМО
   ЗАМЫКАНИЯ». Это не шум и не повод гнать всё руками: подсчёт ошибся, и на нём уже выбирали.
   Чинится правилом в `deps.ts` — тем же коммитом, — а не списком исключений. Так уже нашлось
   одно: vite читает не корневой `tsconfig.json`, а каждый в дереве.

   **Прогон «до» не гоняется второй раз.** Вывод каждого прогона ложится в общую папку git
   (`.git/tribe-reports/<отчёт>/<отпечаток>`, в репозиторий не попадает и виден всем worktree)
   под отпечатком замыкания — блобами всех файлов, от которых отчёт зависит. Одинаковое
   замыкание на любом коммите даёт тот же ключ, поэтому вывод базы находится сам, если базу
   гоняли, а гоняли её тем пушем, который её и принёс (кэш живёт в клоне на этой машине, а не на сервере). Нет вывода базы — `npm run reports --
   --before` сам заведёт второй worktree на `origin/master`, прогонит там недостающее и уберёт
   его. Сверка печатает на отчёт «совпал» или «СДВИНУЛСЯ» со строками сдвига.

   **Сверка машинная, и держится это тем, что замер отчёт помечает сам.** Всё, что меряется
   часами, кадрами и кучей, отчёт печатает через `measure()` из `scripts/lib/measured.ts`, и в
   выводе оно стоит в `‹…›`. Содержимое скобок не сравнивается, всё остальное — буква в букву
   (пробелы сводятся к одному, строка из одних замеров пропускается). Новое живое число в отчёте
   без `measure()` — это сдвиг на каждом прогоне, и маскировать его глазами после прогона
   нельзя: маска, закрывающая все числа, закрывает и настоящий сдвиг. Обратное тоже запрещено:
   свойство кода в `‹…›` не заворачивается, иначе его перестанут сравнивать.

## Приёмка на сервере (задел УС-2)

*Решение владельца 22.10.2026: тяжёлое считаем на боевом сервере (Contabo, `ssh tribe@169.58.98.192`, 8 ядер, 23 ГБ), дома —
только лёгкое и управление по ssh. С УС-2 (27.10.2026) на сервере идут и браузерные отчёты — Chromium без видеокарты, WebGL
программный, своя база машины; дома их не гонять (видеокарта гасит ПК). Ночная проверка и как её читать — раздел «Ночная
приёмка на сервере (УС-2)» ниже.*

- **Папка `/opt/tribe-ci`** (не боевая, хозяин `tribe`; не удалять между заходами): `repo/` — клон с GitHub ключом deploy
  хоста (в контейнер ключ не идёт, `.env` игры — тоже), `logs/` — лог шага `NN-имя.log`, итог `summary.tsv` (шаг, код,
  секунды, коммит, конец), `status` — текущий шаг; `home/` — HOME контейнера (кэш npm и замок машины `home/.heavy-job.lock`);
  `run.sh`, `run2.sh` — драйверы шагов (шаги по одному, коммит после шага, правившего файлы, явными путями), `watch.sh` — где
  идёт работа, нагрузка и отклик боевого адреса, `switch.sh` — одноразовый переход с `run.sh` на `run2.sh`.
- **Контейнер** — на образе Node из `.nvmrc`, четыре ядра, низкий приоритет, в фоне; работа не зависит от домашнего ПК:

  ```bash
  docker run -d --name tribe-ci --init --cpus=4 --memory=8g --memory-swap=8g --cpu-shares=256 --user 1001:1001 -e HOME=/ci/home -v /opt/tribe-ci:/ci -w /ci/repo node:22-bookworm sleep infinity
  docker exec -d tribe-ci nice -n 19 bash -c "bash /ci/run2.sh <шаг> >> /ci/logs/run.out 2>&1"
  bash /opt/tribe-ci/watch.sh
  ```

- **Бюджет — квота `--cpus`** (`budget.cpuQuota`, `CLAUDE.md`, ⛔): в контейнере `availableParallelism()` уже 4, и без правила
  треть дала бы одно ядро. `ionice` в контейнере не применяется — только `nice 19` и вес 256. `--cpus` снижается на ходу:
  `docker update --cpus=2 tribe-ci`. **С 26.10.2026 (решение владельца) — 6 ядер, пока отклик боевого в норме**: замер с
  сервера `curl -w '%{time_total}' https://game.kingsvassals.com/api/time` до запуска и через пару минут под нагрузкой (первый
  раз: 0.042–0.088 с пустым, 0.042–0.074 с на 6 ядрах); вырос — `docker update --cpus=4 tribe-ci`. Паузы между шагами вывода
  (`derive --pause`, 3 мин) были для домашнего ПК — на сервере `--pause 0`.
- **Работающий драйвер на месте не правят:** bash читает скрипт по ходу, и правка посреди шага ломает чтение. Новый план —
  новым файлом и запуском с номера шага (`run2.sh 14`).
- **Цена на сервере, 4 ядра** (журналы 22.10.2026): `npm ci` 8 с; `npm test` целиком 465 с (411 файлов; дома на 4 ядрах — больше
  15 мин); `typecheck` 54 с; `build` 74 с; шаг W ~11–12 мин (`derive -- w`, четыре шага с паузами — 55 мин); шаг таблицы у ворот
  ~6–7 мин (три шага — 21 мин); `stability:report -- --derive` ~3 мин; `ESTATES_DERIVE=1` ~3 мин; `COUNCIL_DERIVE=1 npm run
  pop:report` 13–21 мин; 18 счётных разом — 2302 с, база к ним по одному — 5823 с (23.10.2026, «Первый заход» ниже).
- **Боевой адрес не заметил**: за 3 ч на 400 % процессора контейнера отклик `/api/time` с сервера 0.035–0.087 с (до запуска
  0.05–0.08), игра — 0 % процессора; из дома 0.24–0.4 с со всплесками до 3 с и при пустом контейнере — сеть, не сервер.
- **Домой** — пакетом: на сервере `git -C /opt/tribe-ci/repo bundle create /opt/tribe-ci/<имя>.bundle <последний запушенный>..HEAD`,
  `scp` домой (бинарное — не конвейером PowerShell), дома `git fetch <пакет> HEAD:refs/tmp/<имя>`, дифф целиком (правило 10),
  `merge --ff-only`, push.

## Прибор пути `roam:report` (ПН-0ч)

*Пачка ПН-0 ГДД «Путь меча» (docs/gdd/path_of_sword.md, 6.5, 7.1; разбор — раздел 11 ГДД).* Отчёт лёгкий и один процесс: веера

зовёт (жалованье, бой мира, путь, расселение, рынок, автопилот посёлка), и `scripts/roam/`.

**Что делает ночь.** Раз в сутки по расписанию (`30 1 * * *` по часам сервера — Europe/Berlin, это 00:30 UTC зимой, 03:30 по
Москве: игроков меньше всего, копия базы игры — в 03:30 по часам её контейнера) `night.sh` берёт свежий `master` из origin —
**только если он изменился** с прошлой ночи и с прошлой прошло не меньше 20 часов. Дальше:

1. Рабочее дерево `/opt/tribe-ci/night/wt` на этом коммите. Пока в `master` стояли временные множители теста (×3 пути, войско не ест —

   множители не 1 — ночь не идёт, весть говорит об этом. Коммитом, а не правкой дерева — потому что ключ вывода отчёта
   (`runs.closureKey`) считается по блобам: база и ночь должны быть одним видом дерева.
2. Контейнер `tribe-ci` (образ `deploy/ci/Dockerfile` — Node из `.nvmrc` и Chromium; 6 ядер, если отклик боевого до старта в норме,

базы» (новый отчёт); тесты — зелёные или красные файлы; пол — пакеты, типы, сборка; время ночи (пол и отчёты); отклик боевого —
худший и медиана, ядра (стрелка — снижались на ходу); итог — принят или база прежняя; путь к логу. Сдвиг — открыть
`reports.log` ночи: строки «−/+» под каждым отчётом.

**Руками.**

```bash

ssh tribe@169.58.98.192 'setsid nohup sh /opt/tribe-ci/night/bin/night.sh --force > /dev/null 2>&1 < /dev/null &'
ssh tribe@169.58.98.192 'tail -5 /opt/tribe-ci/night/night.log; d=$(ls -d /opt/tribe-ci/logs/night/* | tail -1); cat $d/status $d/summary.tsv; cat $d/message.txt'
ssh tribe@169.58.98.192 'sh /opt/tribe-ci/night/bin/night.sh --accept <коммит>' # принять разобранный сдвиг базой машины
ssh tribe@169.58.98.192 'sh /opt/tribe-ci/night/bin/night.sh --seed <коммит>'   # заложить базу заново (сравнивать не с чем)
```

Занят контейнер `tribe-ci` (ручная работа сессии) — ночь пропускается и пойдёт следующей ночью; ручная работа в нём ночную
не ждёт, так что долгий заход сессии на сервере ночь просто сдвигает. Брошенный замок машины в HOME контейнера
(`/opt/tribe-ci/home/.heavy-job.lock`) ночь снимает сама: раз контейнера нет, держать его некому.
