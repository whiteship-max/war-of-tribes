# Справочник: консоль боёв и сценариев (УС-1)

Команды для владельца и сессий: посчитать бой, набег, осаду, удар по лагерю, перехват, перебор таблицей, посмотреть
ролик того же боя глазами, вывести W и таблицу у ворот, замерить скорость. Своих правил боя и мира у консоли нет — она
зовёт те же двери, что игра и отчёты (`world/fights.wallFight`, `LocalWorld.wallField`, `gateField`, приказы мира), и
печатает, что они сделали. Справочник — продолжение `CLAUDE.md` (указатель справочника), правится здесь. Код —
`scripts/console/`; у каждой команды полный список ключей — `--help`.

## Как запускать

```bash
npm run <команда> -- <ключи>
```

- Двойной дефис после имени команды обязателен — так npm отдаёт ключи команде. Работает одинаково в PowerShell, Git Bash
  и Linux.
- Сторону с пробелами или точкой с запятой — в кавычки: `--a "spearman:100,archer:40"`. Без пробелов кавычки не нужны.
- Имена видов — латиницей (`spearman`) или по-русски (`копейщики`). Если в PowerShell русские буквы в выводе — кракозябры,
  один раз в окне: `[Console]::OutputEncoding = [Text.Encoding]::UTF8`.
- Ошибка в доводе — строка «ошибка: …» и подсказка, код выхода 2; неизвестный ключ (опечатка) — тоже ошибка, а не молча
  другой бой.
- `npm run console` — оглавление команд.

**Бюджет железа (CLAUDE.md, ⛔).** Команды мира (`raid`, `siege`, `camp`, `intercept`, `sweep`, `derive`, `speed`) и бой
больше чем на 200 сидов берут замок машины `~/.heavy-job.lock` и ждут свободной машины, как приёмка; рядом с приёмкой и
тестами их не гонят. Многопроцессная работа (`derive`) идёт веером отчётов — в бюджете ядер. `replay` — стенд сцены: сессия
держит его не дольше двух минут и одним заходом; владелец смотрит сколько хочет.

## Стороны боя

Сторона — список `имя:число` через запятую:

| что | как писать | что значит |
| --- | --- | --- |
| виды племени | `spearman:100`, `копейщики:100` | головы; в строй — по цене вида (`price.kindsOf`), как у игры |
| рода ядра | `kind:spear:120`, `infantry:150` | бойцы строя напрямую; лучники ядра — только `kind:archer` (`archer` — лучники племени) |
| волки | `волки:300`, `wolves:300` | стая из 300 волков — лёгкая конница без вещей, как у события у ворот |
| разбойники | `raiders:900` | отряд набега мощью 900, уклад — по сиду, как у мира |
| логово | `lair:600` | гарнизон логова мощью 600 |

Мощь — мера мира: дубинщик весит 2; бойцов строя — мощь / 2 (`garrison.menOfPower`).

## Команды

### `npm run fight` — бой двух сторон

Ядро боя дверью боя у стены мира и сервера: стороны, место, стена, отметки, мораль между боями, ширина фронта, сид и
повторы. Один бой — исход, потери по родам, ход боя по фазам (тики, павшие, мораль), ключевые события (`--log` — журнал
целиком). Повторы (`--runs N`) — доля побед с границей Уилсона на 95 %, потери и длина боя 10-й…медиана…90-я, а первый
бой подробно.

```bash
npm run fight -- --a spearman:120,archer:60 --d legionary:80 --runs 40
npm run fight -- --a raiders:900 --town 5 --wall scaling --runs 100
npm run fight -- --a legionary:80 --d lair:600 --place forest --river --log
npm run fight -- --a knight:40 --d kind:spear:150 --pips-a shock:2,maneuver:3 --width 60 --watch
```

`--town L` вместо `--d` — гарнизон, ополчение и стрелки башни посёлка мерки уровня L. `--wall`: `none` (поле),
`scaling` (с ходу), `ladders`, `ram`, `tower`, `breach:N`, через «+».

Дух войска (ДР-1, docs/siege_v2.md, 24): `--spirit-a`, `--spirit-d` «мораль,дисциплина» 0…100 (70 — нейтраль; без ключа — без
духа, как логово). `--derive-spirit` — вывод точек `SPIRIT` (`src/battle/config.ts`) и сила по углам шкал: армия мерки (или
`--a`) с духом против той же без духа, растянутой в k раз, — k, где победы поровну; сидов на точку — `--runs` (200, больше
`LIGHT_BATTLES` — под замком машины, около четверти часа). `--check` — только сила по углам при записанных точках.

```bash
npm run fight -- --a spearman:120,archer:40 --d spearman:120,archer:40 --spirit-a 0,0 --runs 200
npm run fight -- --derive-spirit --runs 200
npm run fight -- --derive-spirit --check
```

### `npm run gate` — волки и разбойники у ворот

Бой события у ворот дверью мира (`LocalWorld.gateField`) на посёлке мерки: гарнизон, отряд полководца в городе,
ополчение, стрелки башни; строкой — дух дружины посёлка (ДР-1, `sim/spirit`): он идёт в бой у ворот. Без числа — сила таблицы игры для этого посёлка (`data/events.gatePower`). Сиды — `i·7919`, как
у раздела 4 `raid-mix:report`.

```bash
npm run gate -- --level 3 --wolves
npm run gate -- --level 5 --wolves 420 --runs 200
npm run gate -- --level 7 --raiders 1500 --army spearman:60,archer:40
```

### `npm run raid` — набег логова

Без ключей — бой у стены сухим прогоном по сидам той же дверью, что набег мира (`LocalWorld.wallField`, штурм с ходу).
`--live` — настоящий мир: логово выходит сейчас, идёт, бьётся у стены, грабит или садится лагерем, и осада идёт фазами до
конца (как у `siege`). Мощь по умолчанию — дозревшее логово медианной опоры при жителях посёлка (`lairs.lairRaid`);
слабый город логово не замечает — `--power P` или `--no-shield`.

```bash
npm run raid -- --level 8 --runs 100
npm run raid -- --level 7 --power 1600 --army spearman:60,archer:40,legionary:30
npm run raid -- --level 8 --power 3000 --live --watch
```

### `npm run siege` — осада своего города

Настоящий мир: набег выходит сейчас и, если мир так решит (штурм не удался бы, кость посадки выпала, лагерь удержит
вылазку — `LocalWorld.sitsDown`), садится лагерем. Дальше — фаза за фазой строкой мира: кость, поправки, исход, ушло из
лагеря, обстрел; и строкой консоли — хлеб до голода, машины лагеря, требушет на стене, кольцо Р-5. Приказы защитника —
те же двери, что кнопки окна осады: `--repair`, `--ration`, `--gun`, `--gun-aim camp|machines`. Конец — донесение
(голод, сдача, штурм, снятие) и запись осады для ролика ГФ-2.

```bash
npm run siege -- --level 8 --power 3000
npm run siege -- --level 8 --power 3000 --repair --ration --gun --gun-aim machines --watch
```

Лагерь не сел — команда скажет почему: прорвали — мощь поменьше; отбиты и ушли — побольше или другой `--world`.

Хлеб осады (ОС-1, docs/siege_v2.md, 23): строка фазы печатает склад племени, «хлеба хватит» и штраф к добыче с причиной — те же
слова, что окно защитника. `--ratio R` — мощь набега в R мощностей гарнизона (мерка кольца и штрафа) вместо `--power`;
`--sit` — лагерь садится при любом исходе сухого прогона, кроме прорыва (замер правила хлеба, а не частоты осад); `--calm` —
кость фаз «без перемен»: осаду кончают только голод и уход лагеря; `--derive` — вывод штрафа к добыче (`CUT_MIN`, `CUT_MID`)
по посёлкам мерки 1–10 одной таблицей, без мира. У мерки 5 защита слабого не пускает логово — `--no-shield`.

```bash
npm run siege -- --derive
npm run siege -- --level 5 --ratio 1 --sit --calm --no-shield
```

### `npm run camp` — удар по лагерю

`siege` с ударом: `--sortie "вид:N,…"` — вылазка из города этим отрядом; `--strike` — полководец из поля своей дружиной
(`--joint` — вместе с гарнизоном из ворот). Дружина — всё, что не оставлено `--garrison` (по умолчанию половина каждого
вида); до набега она выходит в поле рядом с городом. `--at-phase K` — в какую фазу бить (по умолчанию 2). Пишутся две
записи: бой у лагеря (ролик ГФ-1) и осада целиком (ГФ-2).

```bash
npm run camp -- --level 8 --power 3000 --sortie legionary:30,spearman:40 --at-phase 3
npm run camp -- --level 8 --power 3000 --army spearman:150,archer:100,legionary:80,rider:40 --strike --joint
```

### `npm run intercept` — перехват в поле

Набег выходит сейчас, полководец ведёт дружину навстречу приказом мира (тот же, что кнопка «Перехватить»: встреча,
энергия, отказ — правилами мира). Бой в поле — донесением; уцелевшие идут к стене, и набег решается там.

```bash
npm run intercept -- --level 8 --power 2000
npm run intercept -- --level 9 --army legionary:80,rider:60,archer:60 --garrison archer:60 --watch
```

### `npm run sweep` — перебор таблицей

Строка — значение перебора, доля верха пришедших с границей на 95 %, потери. «Ровный» — первая строка, где доля доходит до
половины.

```bash
npm run sweep -- wolves --level 5                      # стая от ¼ до 3 таблиц игры
npm run sweep -- raiders --level 7 --from 500 --to 2500 --step 250
npm run sweep -- garrison --level 5 --wolves 450        # какой гарнизон держит стаю
npm run sweep -- garrison --level 8 --power 2500        # … или набег у стены
npm run sweep -- power --level 8 --from 500 --to 4000 --step 500 --runs 80
npm run sweep -- width --a spearman:200,archer:100 --d legionary:120 --from 60 --to 130 --step 10
```

`garrison` множит войско посёлка (или `--army`) на k тем же составом; строка «Держит с …» — первый гарнизон, у которого
пришедшие берут верх реже половины боёв.

### `npm run replay` — посмотреть глазами

Каждая команда, у которой был бой или осада, кладёт запись в `snaps/console/<команда>-<время>.json` и копию в
`snaps/console/last.json` (`snaps/` не в git) и печатает строку `ролик: npm run replay -- <файл>`. `replay` поднимает
dev-сервер vite этого репозитория на `127.0.0.1:5199` и открывает браузер на стенде `?replay=file` — тот же ролик, что в
игре: бой — `TwReplay` (ГФ-1), осада — `SiegeReplay` (ГФ-2). Ключ `--watch` у команд делает то же сразу. Выход — Ctrl+C.

```bash
npm run replay                                   # последняя запись
npm run replay -- snaps/console/siege-20261020-191943.json
npm run replay -- --no-open                      # только адрес
```

### `npm run derive` — вывод W и таблицы у ворот

Числа, которые сами входят в свою выборку (правило 16): W с шагом кости и таблица сил у ворот. Шаг вывода считает только
то, из чего число выводится, теми же функциями, что разделы отчётов: W — прогоны «Найма» (`raid-width.widthOfHired`, без
«Лазарета», «Сожжённых» и «Морали»), таблица — партии мерки и ровный бой (`raid-defense-mix.gateEvens`, `gateValue`, без
кривых медианного, окрестности и боя без кости). Без `--write` — один шаг и печать. С `--write` драйвер гоняет шаги
дочерними процессами, сам правит записанное между ними (`src/battle/config.ts` — `FRONT_WIDTH`, `DICE.step`;
`src/game/data/events.ts` — `GATE_POWER`) и останавливается по правилам:

- **W** — выведенное = записанному: точка неподвижна (шаг кости правится на выведенный на этом W). Качание a → b → a —
  полусумма, округлённая до целого, с шагом кости на ней, и шаг проверки. Шаги кончились (по умолчанию 4) — «не сошлось»,
  решение по правилу 19.
- **Таблица** — строка села, если выведенное в 1 % от записанного; не севшие за все шаги (по умолчанию 3) — полусумма
  записанного и выведенного последним шагом (как в выводах 19.4, 20.2, 22.2).

Между шагами дольше десяти минут — пауза `--pause` минут (3). Замок машины держит драйвер на весь вывод. Правка ядра —
`--write` правит `config.ts` и `events.ts`; дифф читает и коммитит сессия (правило 10), числа в документ — из вывода
приёмки (правило 12).

```bash
npm run derive -- w                       # один шаг на записанном
npm run derive -- w --write               # до неподвижной точки
npm run derive -- gate --write --steps 3
```

### `npm run speed` — замер скорости

Постоянный набор прогонов, из которых состоят тяжёлые отчёты и вывод: лестница «Найма» (`ladder`), партия мерки у ворот
(`towns`), ровный бой у ворот (`gate`), решётка ядра боя на 1318 боёв (`lattice`), осада в мире (`siege`). Время — лучшее из
`--repeat N`; отпечаток — sha256 итогов: одинаков на двух деревьях — прогоны дали то же. `--only ИМЯ` — один прогон,
`--profile ИМЯ` — профиль одного прогона (node --cpu-prof): собственное время функций и с вызванными.

```bash
npm run speed -- --repeat 2
npm run speed -- --profile ladder
```

Модуль берёт только то, что было в отчётах до УС-1, — «до» меряется его копией на старом дереве той же машины:
`cp scripts/console/speed.ts <старое дерево>/scripts/console/` и `npx vite-node scripts/console/speed.ts -- --repeat 2`.

## Рецепты

**Держит ли город набег.** `npm run raid -- --level 8 --runs 100` — доля прорывов у стены; своё войско — `--army`; чем
кончится в мире — `--live`.

**Какой гарнизон держит стаю N волков.** `npm run sweep -- garrison --level 5 --wolves 450`; размер стаи, при которой
город ещё держит, — `npm run sweep -- wolves --level 5`.

**Сравнить две армии.** `npm run fight -- --a spearman:200,archer:80 --d legionary:120 --runs 200` и наоборот
(`--a` ↔ `--d`): нападающий и обороняющийся в бою неравны (место, переправа — штраф нападающему). На стене — `--wall`.

**При какой ширине фронта армия начинает выигрывать.** `npm run sweep -- width --a … --d … --from 40 --to 160 --step 5`.

**Что делает осада фазами.** `npm run siege -- --level 8 --power 3000`; паёк, починка, требушет — `--ration --repair --gun`;
посмотреть — `--watch`.

**Снимет ли вылазка лагерь.** `npm run camp -- --level 8 --power 3000 --sortie legionary:40,spearman:60 --at-phase 2`; удар
из поля — `--strike --joint`.

**Посмотреть бой глазами.** Любая команда с `--watch`, или `npm run replay` после неё.

**Вывести W и таблицу после правки боя.** `npm run derive -- w --write`, потом `npm run derive -- gate --write`, потом пол и
полная приёмка (правило 9).

**Понять, где время.** `npm run speed -- --profile ladder` (или `gate`, `lattice`, `towns`, `siege`).

## Решения (правило 19)

1. **Ветка `game/us-1` от `master` `59ac050`, worktree `tribe-us1`** (облако); те же коммиты лежат и в ветке сессии облака.
2. **Вывод отчётов не меняется ни на букву.** Каждая правка скорости — та же арифметика в том же порядке или пропуск счёта,
   чей итог не читается; сверено отпечатками `npm run speed` (пять прогонов), хэшем 1318 боёв ядра, щупами старое против
   нового (ровный штурм осады — 24 случая, дуэли и стена конюшни, ровный бой у ворот) и тестами затронутых мест.
3. **Мир автопилота без хранилища.** Мир читает хранилище только при рождении, а `memory()` рождался пустым — запись после
   каждого шага не читал никто. `storage?.write(…)` без хранилища не собирает и строку; побочные дела записи (маска тумана в
   сохранение, забытые визиты) остались — они вне необязательной цепочки.
4. **Туман помнит открытые круги и в игре.** Это только запоминание счёта: что открыто, решают биты, а туман не
   затягивается; переполнение (65 536 кругов) — память сбрасывается целиком.
5. **Цена вида по-прежнему без запоминания** (её комментарий: правка жалованья доходит сразу) — мощь состава лишь не считает
   видов с нулём и делитель — раз на вызов.
6. **Ранний останов — точный, не статистический.** «Выборка до нужной точности с границей доверия» меняла бы печатаемые
   доли и полпути, а число боёв на точку — правило вывода владельца; нового правила не заводил. Там, где решение — только
   «≥ половины боёв», бои после решённого ответа не гоняются: ответ тот же при любом их исходе.
7. **Секущей для W нет.** f(W) шумит на ±2 при малом наклоне: секущая по двум шумным точкам прыгает, а простая итерация
   сходится за 2–3 шага (19.4, 20.2, 22.2). Ускорение вывода — шаг дешевле (только нужные прогоны) и без простоя между
   шагами (драйвер `derive --write`), а полусумма при качании — правило 16.
8. **Кэша между шагами таблицы у ворот нет.** Партии мерки бьются у ворот с таблицей игры, и правка любой строки меняет
   траекторию партии с первого боя у ворот — общих двум шагам снимков почти нет, а ровный бой — функция снимка.
9. **Консоль — на дверях мира и посёлке мерки отчётов.** Посёлок — `autopilot.townAt`, стоит (уровни, склад, войско — как
   поставили), мир и пульс идут — как у осады в отчётах; мир по умолчанию — 7 (первый сид отчётов). Своих правил нет.
10. **«Уровень стены» — способ штурма и посёлок.** В бою стена — проход с постоянными гранями (`world/wall`): уровня у неё
    нет; частокол и башня приходят ополчением и стрелками посёлка (`--town`, `--level`).
11. **Замок машины** — у команд мира и у боя больше чем на 200 сидов (`LIGHT_BATTLES`): короткий бой — доли секунды.
12. **Ролик — стенд `?replay=file`** отдельным куском (`src/render/console-stand.ts`), в первую загрузку игры не едет; запись —
    в `snaps/console/` (не в git), сервер — vite на своём порту 5199, чтобы не спорить с `npm run dev`.
13. **Имена команд — латиницей** (`fight`, `siege`): кириллица в имени скрипта npm ломается в cmd.exe; русские — значения.
14. **`derive --write` правит ядро** (`battle/config.ts`, `data/events.ts`) — так же, как правила вывода велят сессии руками;
    коммит — сессией после чтения диффа.
