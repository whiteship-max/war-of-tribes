# Справочник: выкладка

справочника про что — `CLAUDE.md`, «Указатель справочника». Правила здесь действуют так же, как в

## Выкладка (продолжение)

*Начало раздела — боевой адрес, ручная выкладка, `npm run build` — в `CLAUDE.md`, «Выкладка».*

**Боевой сайт один, и это `celebrated-yeot-73e410`.** Прежний сайт
`gleeful-sunflower-a2f83c` к игре отношения не имеет. Записано это не для порядка, а потому
что его трижды принимали за боевой и делали из этого неверные выводы о том, что собрано:
адрес отвечал кодом 200 и отдавал игру — только вчерашнюю. **Отвечающий адрес сам по себе не
доказывает ничего.** Что на сайте лежит, проверяется одним способом — сверкой имён чанков из
описи `npm run build` с исходником страницы на живом адресе (см. ниже, пункт про опись).

Игра — статика: `vite build` кладёт всё в `dist/`, `base: '/'` (абсолютные пути к чанкам, иначе
на подпути ломается). Состояние живёт в localStorage и на нашем сервере хранения,
переменных окружения у сборки нет — токен бота живёт только в @BotFather.

- Приложение одностраничное: любой путь должен отдавать `index.html`. Это записано сразу для двух
  хостингов, чтобы не переписывать при переезде: `netlify.toml` (+ `public/_redirects`) и
  `vercel.json`. Node — 22 (`.nvmrc`, `NODE_VERSION` в `netlify.toml`).
- **Релиз собирается одной командой — `npm run build`** (правило — `CLAUDE.md`, «Выкладка»).
  Почему скриптом, а не строкой `icons:build && tsc && vite build` в `package.json`, как было:
  1. **Половинчатая сборка не должна быть возможна по невнимательности.** Прежняя строка на
     Windows изредка падала ассертом libuv сразу после отчёта о значках — уже записав лист, но
     не дойдя до `vite build`. По половинам всё проходило, и рука сама тянулась досбирать
     руками; а пропущенный `icons:build` не виден по `dist` никак — на сайт уезжает вчерашний
     лист значков при сегодняшнем коде. Причин у падения было две, и обе убраны: ступени
     запускаются напрямую (`node <бинарь>`), без вложенного `npm run` с его cmd-шимами, а сам
     `scripts/build-icons.ts` выходит явно, не досиживая до разборки libuv поверх потоков
     `sharp` (объяснение — в хвосте того файла).
  2. **Собранное принимается, а не предполагается.** Каждая ссылка из `index.html` обязана
     указывать на существующий файл; лист значков в `dist` обязан совпасть с только что
     собранным; заставка, музыка и лица — быть на месте и по счёту; встроенный экран загрузки —
     пережить минификацию. Не сошлось — сборка падает, и папка `dist` сборкой не считается.
     `dist` перед началом стирается: `vite` перезаписывает, но не удаляет, и чанк с прежним
     хешем остался бы лежать рядом с новым.
  3. **Опись сборки в конце — подпись выкладки.** Она печатает коммит и имена чанков с их
     хешами. Хеш в имени чанка выводится из содержимого, и он же стоит в `index.html`, который
     отдаёт сайт: сверив имена из описи с исходником страницы на живом адресе, видно, тот ли
     билд там лежит. Один раз задеплоенное отстало на 56 коммитов, и выяснилось это только
     этим сравнением — поэтому опись печатается всегда, а не по флагу.
- **Выкладка идёт из GitHub, и перетаскивать папку больше нельзя.** Netlify Drop кладёт готовую
  статику и ничего не собирает, а функции надо собрать и зарегистрировать — сайт, выложенный
  перетаскиванием, остаётся без `/api/*`. На боевом проекте это закрыто подключённым
  репозиторием: Trigger deploy → сборка `npm run build` на стороне Netlify → Publish deploy,
  вместе с функциями. Обе кнопки нажимает владелец: автосборки и автопубликации нет (см. выше).
  Проверяется одним запросом: `https://celebrated-yeot-73e410.netlify.app/api/time` обязан
  вернуть `{"now":…}` с типом `application/json`. Вернулась страница игры (код 200, `text/html`) —
  функции не подхватились, и `res.ok` об этом не скажет. Шаги подключения и второй способ
  (`netlify deploy --prod`) — [docs/sync.md](../sync.md), раздел 1. Туда же вписывается
  `TELEGRAM_BOT_TOKEN` (Site configuration → Environment variables).
- **Свой сервер** вместо Netlify — те же адреса и обработчики, SQLite, Docker и Caddy: пошагово —
  [docs/SERVER.md](../SERVER.md), разбор — [docs/server-move.md](../server-move.md). Пока бот смотрит
  на Netlify, всё в этом разделе действует как есть.
- **Сайт обязан быть публичным.** Netlify новым сайтам включает Team protection, и тогда любой
  заход редиректит на форму входа Netlify — в браузере разработчика этого не видно, он залогинен,
  а с телефона и из Telegram игра просто не откроется. Настройка: Site configuration →
  Access & security → Visitor access. Проверять — приватным окном, не своим браузером.

### Стенд в проде

Стенд открывается по тому же адресу — он собирается в продакшен нарочно (см. «Графика»).
Замер частоты кадров на телефоне теперь делается без туннеля:

```
https://celebrated-yeot-73e410.netlify.app/?showcase=village&levels=10&perf=8
```

Экран не гасить и вкладку не сворачивать: в фоне `requestAnimationFrame` стоит, и замер выйдет
нулевым. Прогрев полторы секунды, потом камера крутится восемь секунд. Итог остаётся в подписи,
а тап по ней кладёт отчёт целиком (устройство, dpr, вызовы, треугольники) в буфер обмена —
класть его в `snaps/perf.jsonl` некому, `/__perf` есть только у dev-сервера. Снимки (`?snap=имя`)
в проде тоже не сохраняются: за ними — на `npm run dev`.

**Абзац выше — про настоящий телефон, следующий — про наш инструмент, и выводы у них разные.**
«Экран не гасить» сказано игроку и нам с телефоном в руках: там страница действительно уходит в
фон, кадры действительно останавливаются, и лечится это тем, что экран не гасят. Ниже речь о
другом — о **панели предпросмотра инструмента разработки** (браузер внутри рабочей среды сессии,
тот, в котором игру открываем мы сами). Ни к вкладке Chrome у игрока, ни к вебвью Telegram, ни к
чему-либо в самой игре это не относится: в игру панель не входит, у игрока её нет, и судить по
ней о поведении настоящего браузера нельзя — как и наоборот.

**Видимость панели предпросмотра не равна кадрам, и «кадров нет» в ней ничего не доказывает.**
`document.hidden === false` и `visibilityState === 'visible'` **не** означают, что кадры идут:
панель отвечает «видима», а `requestAnimationFrame` при этом не срабатывает ни разу за полсекунды —
кадры идут только те доли секунды, пока панель действительно рисуют. Проверено замером. Поэтому
«кадров нет» никогда не доказывает, что сцена сломана, а проверка видимости не доказывает, что
измерение состоялось. Мерить кадры можно только в окне, где панель заведомо рисуется, — например
сбросив счётчики, сняв снимок и прочитав их сразу после. Написано это потому, что на прежней
формулировке мы уже трижды принимали здоровую игру за сломанную.
