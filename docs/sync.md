# Личность игрока и хранение прогресса

Сервер решает пять вещей и ровно пять:

- прогресс не теряется при чистке данных браузера;
- игра открывается с любого устройства под тем же аккаунтом Telegram;
- две вкладки не перетирают друг друга молча;
- текущее время берётся серверное, а не с телефона;
- игроки видят замки друг друга на общей карте (раздел 4).

**Чего он не делает — и не должен начать делать по дороге.** Сервер не
авторитетный: он хранит и раздаёт, а не судит. Он не разбирает сохранение, не
проверяет ресурсы, не ловит читерство и ничего не начисляет — алмазов у него нет
ни в каком виде, и это держит тест, читающий его исходники. Платежей здесь тоже
нет. Каждая из этих вещей делается целиком и отдельно; сделанная «пока временно,
по дороге», она будет выглядеть работающей и не быть ею.

**Чужие игроки появились ровно в одном смысле: их замки видно.** Между ними не
происходит ничего — ни походов, ни осад, ни дипломатии, ни писем, — и общей
карты как общего состояния по-прежнему нет: землю каждый клиент считает сам из
одного и того же атласа, а сервер держит только список замков.

## 1. Где живёт

Netlify Functions плюс Netlify Blobs — новых сервисов и учётных записей не
заводится. Функций пять, все в `netlify/functions/`:

| Путь           | Что делает                                                        |
|----------------|-------------------------------------------------------------------|
| `/api/save`    | `GET` — прочитать своё сохранение, `PUT` — записать своё           |
| `/api/time`    | `GET` — серверное «сейчас», без подписи                            |
| `/api/castles` | `GET` — соседи, `PUT` — обновить свою строку и, если её нет, поставить замок |
| `/api/notify`  | приём черновиков уведомлений и присутствия ([NOTIFY.md](NOTIFY.md)) |
| `deliver`      | проход доставки по расписанию; по адресу не вызывается ([NOTIFY.md](NOTIFY.md)) |

Путь объявляет сама функция (`export const config = { path }`), а не
переписывание в `netlify.toml`. Причина: у сайта стоит общее правило «любой путь
отдаёт `index.html`», записанное сразу в двух местах (`public/_redirects` и
`netlify.toml`), и правило функции обязано разбираться раньше него. Объявленный
путь платформа разбирает до переписываний — и порядок правил в двух файлах
перестаёт иметь значение вовсе.

**Функция — обёртка, логика — общая** (переезд на свой сервер, этап 1, 05.10.2026;
[server-move.md](server-move.md)). Правила каждого адреса лежат в общем обработчике
`netlify/lib/routes/<имя>.ts`; функция Netlify передаёт ему запрос вместе с Blobs
платформы, свой сервер (`netlify/vps/`) — вместе с SQLite. Хранилище для обработчика —
узкая дверь `netlify/lib/kv.ts` с условной записью по ETag, и что оба дома держат её
одинаково, проверяет один набор тестов на обоих. Доставка (`deliver`) заморожена и не
выкладывается ([NOTIFY.md](NOTIFY.md)); на своём сервере она так же выключена.

### Что должен нажать владелец

**Это уже сделано.** Боевой проект `celebrated-yeot-73e410` подключён к GitHub, и
функции едут вместе со статикой:
`https://celebrated-yeot-73e410.netlify.app/api/time` отвечает `{"now":…}`.
Шаги ниже оставлены записью того, что было нажато, — они же понадобятся при
переезде на новый проект.

**Но сам по себе push ничего не выкладывает: автосборка и автопубликация
выключены нарочно.** Сайт обновляется двумя нажатиями владельца — Deploys →
Trigger deploy, дождаться сборки, потом Publish deploy. Поэтому боевой адрес
законно отстаёт от `master`, и ждать, пока он обновится сам, бессмысленно
(CLAUDE.md, «Выкладка»).

Начиналось всё с перетаскивания папки `dist` в Netlify Drop. **Так функции не
живут:** перетаскивание кладёт готовую статику и ничего не собирает, а функции
надо собрать и зарегистрировать. Пока сайт выкладывался так, серверной части на
нём просто не было — игра при этом работала как раньше, и в профиле честно
написано, что прогресс лежит только на устройстве.

Способов исправить два, и оба делаются руками владельца — доступа к его учётной
записи ни у кого больше нет.

**Способ первый, рекомендуемый: подключить репозиторий.** Заодно уходит старая
беда — выложенное однажды отстало на 56 коммитов, и заметили это только по
описи сборки.

1. Netlify → нужный сайт (`celebrated-yeot-73e410`) → **Site configuration →
   Build & deploy → Continuous deployment → Link repository**.
2. Выбрать **GitHub**, разрешить Netlify доступ (репозиторий приватный — Netlify
   попросит установить своё приложение в аккаунт и отметить `war-of-tribes`).
3. Ветка — `master`. Build command — `npm run build`. Publish directory — `dist`.
   Всё это уже записано в `netlify.toml`, и Netlify подставит их сам.
4. **Site configuration → Environment variables → Add a variable**: имя
   `TELEGRAM_BOT_TOKEN`, значение — токен бота из @BotFather. Больше его никуда
   вписывать не надо и никому показывать не надо: в репозитории его нет, в
   логах его нет, в этом файле его нет.
5. Deploy. После сборки открыть `https://<адрес>/api/time` — должно вернуться
   `{"now":…}`. Вернулась страница игры — функции не подхватились.
6. **Site configuration → Access & security → Visitor access** — убедиться, что
   сайт публичный (проверять приватным окном, не своим браузером).

**Способ второй: выкладывать из командной строки.** `npm i -g netlify-cli`,
`netlify login`, `netlify link`, дальше вместо перетаскивания —
`netlify deploy --prod`. CLI выкладывает и статику, и функции. Переменную
окружения всё равно надо вписать в настройках сайта (шаг 4).

Vercel (`vercel.json` лежит рядом как запасной хостинг) серверной части не
получает: функций под него здесь не написано, и `/api/*` там попадёт под общее
переписывание на `index.html`. Игра это переживает — см. раздел 7.

### Почему Blobs

Хранилище нужно на одну запись на игрока, размером в единицы килобайт, с
чтением по ключу и записью «поверх ровно этой версии». Blobs это умеют прямо:
`onlyIfMatch` с ETag — настоящее сравнение-и-запись, а не самодельный замок.
`siteID` и токен в функциях подставляются сами, заводить ничего не надо. Чтение
идёт с `consistency: 'strong'` — иначе сразу после записи можно прочитать
предыдущую версию и решить, что копии разошлись.

## 2. Личность: только подпись

`netlify/lib/initdata.ts` — единственная дверь. На вход строка `initData` и
токен бота, на выход либо личность, либо причина отказа.

- Секрет — `HMAC-SHA256("WebAppData", токен)`, подпись — `HMAC-SHA256(секрет,
  строка проверки)`, строка проверки — все пары `ключ=значение`, кроме `hash`,
  отсортированные и склеенные переводом строки. Сравнение подписей — постоянным
  временем.
- Поле `signature` (подпись Ed25519 для тех, у кого токена нет) у части клиентов
  приходит рядом с `hash`, и входит ли оно в строку проверки — у разных версий
  вышло по-разному. Принимаются оба разбора: **обе проверки — полный HMAC тем же
  секретом**, подделать любую из них нельзя, а игра работает на всех клиентах.
- Свежесть: `auth_date` не старше суток и не в будущем дальше пяти минут.
  Сутки — не небрежность: Telegram выдаёт строку один раз, при запуске
  мини-аппки, и больше не обновляет. Короткий срок означал бы не «безопаснее», а
  «к обеду синхронизация отвалилась». Цена длинного срока невелика: перехваченная
  строка открывает сохранение того же игрока — не деньги, не чужой прогресс, не
  начисление. Появится серверная валюта — срок придётся сокращать вместе с
  заведением сессий, и это отдельная работа.
- Пустой токен в окружении читается как «проверять нечем», а не как «проверка
  выключена»: не пускают никого. Забытая переменная на хостинге иначе открывала
  бы чужие сохранения всем.

**Идентификатор из тела запроса не принимается никогда и ни в каком виде.** Это
не проверка, а устройство: ключ хранилища собирается из числа, прошедшего
подпись (`saveKeyOf`), и чужого ключа не из чего собрать. Держат это два теста —
`initdata.test.ts` (подделка любого поля ломает подпись) и `server.test.ts`
(ключ в функции присваивается ровно один раз и ровно из `saveKeyOf(auth.user)`, а
в хранилище ходят только по нему).

Что ещё закрыто: тело не больше 512 КБ (сохранение втрое меньше — 6.4 КБ после
восьми часов игры, мир ещё 4 КБ), неразобранный JSON — отказ, а не пятисотка;
ограничитель частоты в два слоя (ведро в памяти экземпляра плюс настоящий
предел «не чаще раза в четыре секунды», выведенный из времени в самой записи и
переживающий смерть экземпляра); наружу из отказа уходит одно слово — какой
именно замок не сошёлся, полезно знать только тому, кто их подбирает; журналов
в функциях нет вовсе, чтобы в них однажды не попал ни токен, ни подписанная
строка.

## 3. Что хранится

Одна запись на игрока, ключ `tg-<id>`, и **сервер не понимает, что в ней лежит**:

```
{ v, rev, updatedAt, device, game, world, card }
```

`game` и `world` — те же строки, что лежат в localStorage: сохранение племени и
сохранение мира. Непрозрачные, сервер их не разбирает.

Мир едет вместе с племенем нарочно, и это отличается от прежней записи в
CLAUDE.md («мира на сервере не будет»). Причина: обещание «игра открывается с
любого устройства» с половиной партии не выполняется — деревня приехала бы, а
карта, туман, походы и фигуры остались бы дома. Хранятся они **одной записью**,
и это важнее самого факта хранения: выбирая при расхождении, игрок выбирает
целую партию, а не деревню отдельно от её карты. Авторитетным сервер от этого не
становится — он по-прежнему хранит строку, которую не читает.

**Одна запись — верно, пока мир у каждого свой. Своим он быть перестал.**
Земля стала общей: настоящая Европа, Магриб и Анатолия, одинаковые у всех
(см. [atlas.md](atlas.md)). Но живёт она по-прежнему у клиента — не на
сервере, а в запечённом атласе, — и на сервер по-прежнему уезжает одна
строка, которую он не разбирает.

**Разделение записи на «общий мир» и «моё знание о нём» началось, и началось
оно с замков.** Из четырёх вещей, которые должны были стать общими — чужие
замки, чужие армии, осады, дипломатия, — общей стала первая, и она уехала не
в эту запись, а в свою (раздел 4). Остальные три по-прежнему не существуют.

Граница проведена так и переносить её нельзя:

| Общее (сервер знает и раздаёт) | Личное (одна непрозрачная строка) |
|--------------------------------|-----------------------------------|
| где стоит замок игрока          | что разведано (туман) |
| как зовут вождя, мощь, население | что помнит про соседей (снимки и их даты) |
| когда владелец был в игре        | где стоят агенты и какие приказы отданы |
|                                 | свои походы, отчёты, письма, осады, логова |

Своё знание о чужом замке — личное: снимок, который игрок снял глазами, лежит
в его сохранении мира и никуда не уезжает. Общее — сам факт замка и то, что
владелец о себе написал.

Что сделано в ту же сторону раньше: сид перестал рождать землю и не выбирает
переправы — мост на одной и той же реке стоит в одном и том же месте у всех.
Расчёт пути сервер повторит по тому же атласу.

`card` — короткая опись (имя, день, племя, мощь, дружина). Складывает её клиент
(`src/net/snapshot.ts`) теми же функциями, что и весь интерфейс: своей формулы
мощи или населения там нет ни одной. Нужна она одному — строке «Отклонённая
партия» в «Служебном»: «день 41, 320 человек, мощь 5 900» читается, «две записи с
разными хешами» — нет.

**Третья запись — исходящие уведомления** (`tribe-notify`, ключ `tg-<id>`, и индекс по минутам
`tribe-notify-due`). Это второе и последнее место, где сервер читает то, что хранит: не партию, а
поручение «в такую-то минуту скажи вот это, если игрока нет». Устройство, правила и то, почему
расширение разрешено, — [NOTIFY.md](NOTIFY.md); разбирающих записей ровно две, реестр и
исходящие, и это тест (`netlify/lib/server.test.ts`).

## 4. Реестр замков: что стало общим

Вторая вещь, которую держит сервер, — список замков живых игроков:
кто, где стоит, как называется, какова мощь и когда последний раз был в игре.
Одна строка на игрока, ключ тот же — проверенный подписью идентификатор.

**Устроен он не так, как сохранение, и это единственное исключение во всём
документе.** Сохранение партии — непрозрачная строка: сервер её не читает.
Реестр прочитан насквозь. Это осознанное сужение правила «хранит и не судит», и
оно ровно одно; заводить второе нельзя.

Судьёй сервер от этого не стал. Имя, мощь и население он принимает как есть —
проверить их нечем, ни построек, ни припасов он не видит. Он делает одну вещь,
которую клиенту доверить нельзя: **выбирает клетку**.

### Место выбирает сервер

Клиент, выбирающий себе место, — это клиент, выбирающий себе соседей: сесть
вплотную к слабому, подальше от сильного, за морем от всех сразу. Поэтому поля с
координатами в теле запроса нет вовсе: `readClaim` собирает новый объект из трёх
полей (имя, мощь, население), а координаты `upsert` берёт у уже стоящей строки —
или у правила расселения, если строки нет. Стоящий замок не двигается никогда.

Правило расселения одно на обе стороны — `src/world/settle.ts`, и его же зовёт
игра, когда сервера нет вовсе. Ступени:

1. клетка пригодна под двор: не вода, не русло, не хребет (`land.settleable`);
2. не пустыня;
3. доля суши в круге радиусом 10 не ниже 0.6 — замок не на кончике мыса;
4. кусок суши под ней не меньше `MAINLAND_MIN` (20 000 клеток): материк, а не
   остров, с которого не дойти никуда;
5. **не ближе `SETTLE_GAP` (24 клетки, 147 км) ни к одному замку.** Больше круга
   живого обзора деревни (17) нарочно: сосед, попавший в чужой круг прямо при
   рождении, отдал бы даром всё, ради чего в игре есть лазутчик;
6. **не дальше `SETTLE_REACH` (60 клеток, 368 км) от ближайшего** — иначе на
   карте в четыре тысячи девятьсот километров двадцать игроков расселились бы
   так, что не встретился бы ни один;
7. **тот же кусок суши, что у соседей**, и не больше `SETTLE_WATER_MAX` (8%)
   воды на прямой до каждого из них. Первое обещает, что дорога посуху есть;
   второе — что она прямая: два берега залива лежат на одном материке, а идти
   между ними вокруг.

Числа меряные, а не выбранные: `npm run settle:report` сажает игроков по этому
правилу в настоящий мир и печатает, сколько между ними идти.

| Игроков | До ближайшего соседа | Войско идёт | Разведчик | 9 из 10 короче |
|---------|----------------------|-------------|-----------|----------------|
| 2       | 47 клеток (289 км)   | 15 м        | 7 м       | 26 м           |
| 5       | 29 клеток (178 км)   | 13 м        | 6 м       | 21 м           |
| 20      | 28 клеток (172 км)   | 11 м        | 6 м       | 18 м           |
| 50      | 27 клеток (165 км)   | 10 м        | 5 м       | 17 м           |

Медианы по шести мирам на каждое число игроков. Самый неудачливый из трёхсот
идёт к соседу 44 минуты через холмы, и это не сбой расселения, а география:
правило обещает землю и расстояние, а не ровную дорогу. Все триста замков — на
материке, и во всех мирах все они оказались на одном куске суши.

Порядок строк в реестре на ответ не влияет — список сортируется по клеткам, — а
повторная регистрация того же игрока при том же реестре даёт ту же клетку: место
ищется генератором, выведенным из проверенного идентификатора. Ищется оно
**внутри** цикла перезаписи; иначе двое, зашедших в одну секунду, посчитали бы
клетку каждый по своему списку, и сервер сам поставил бы два замка вплотную.

### Имя города

Строка реестра несёт и имя города (`CastleClaim.city`, `CastleRow.city`) — то, которым игрок
назвал свой город в профиле. Соседи видят его подписью под замком на карте, когда замок в
живом обзоре; вне обзора — имя из последнего снимка (`Sighting.name`).

- **Очистка одна на обе стороны** — `contract.cityName`: до сорока знаков (длиной строки —
  так же, как её меряет разбор уведомлений), без разметки, без управляющих и невидимых знаков
  (нулевой ширины, направления письма, мягкого переноса), пробелы сведены. Пустое, из одних
  пробелов или из одних невидимок — не имя. Зовут её клиент при вводе, мир при чтении слепка,
  сервер в `readClaim` и при чтении реестра, клиент при приёме чужих строк: сырым имя не
  проходит ни одну дверь, и держит это тест по исходникам (`ui/cityname.test.ts`).
- **По умолчанию — «Безымянный город»** (`DEFAULT_CITY`): и у себя, и у соседа, чей клиент
  имени ещё не присылал.
- **Ругательства не ловятся.** Фильтра слов у игры нет, и решать это надо отдельно, а не
  строкой регулярного выражения; сервер по-прежнему не судит, что игрок о себе написал.
- Судьёй сервер от этого не стал: имя он чистит тем же правилом, что клиент, и больше ничего
  с ним не делает. Третьего читателя хранимого не появилось — это поле той же записи.

### Чужие замки видны по правилам разведки, а не списком

Реестр — это список, но игрок его списком не видит нигде. Замки проходят через
тот же туман, что и всё остальное на карте, и слоёв у него два:

- **местность.** Клетка не разведана — замка нет ни на карте, ни в карточке,
  ровно как поселения. Разведана — замок виден, и виден навсегда: открытое не
  закрывается;
- **живые данные.** Кто там живёт, как велик и как называется — только из живого
  обзора, а его дают двое: круг у своей деревни (17 клеток) и стоящий
  наблюдателем лазутчик. Вышел из обзора — остаётся снимок с датой, и он
  стареет теми же ступенями, что и всякая разведка: точно, примерно, порядок
  величины, ничего.

Поблажки «первый снимок бесплатно», которая есть у сгенерированных поселений, у
замка нет, и это не мелочь. У поселения она честная: клетку открыл разведчик,
который мимо неё прошёл, — он и посмотрел. Здесь открывать нечего: строка
приезжает из реестра сама, в давно разведанную округу, и бесплатный снимок
означал бы, что мощь и население соседа достаются игроку за то, что тот просто
зашёл в игру.

**Мощь чужого замка идёт по правилу чужого отряда, а не чужого двора.** У двора
её даёт разведка (`Intel`); замок разведать нечем — походов между игроками нет.
Значит либо игрок видел его своими глазами, либо не знает о нём ничего, и
показывается ровно столько, сколько он вправе знать.

Соседям не раздаётся телеграмный номер: наружу уходит признак, выведенный из
ключа хешем. Кто именно играет за этот замок, соседям знать незачем — имя вождь
называет сам.

### Между игроками не происходит ничего

Ни походов, ни осад, ни дипломатии, ни писем. Держится это не проверками в
карточке, а устройством: замки живых игроков лежат отдельным списком и в
`gen.settlements` не попадают. По сгенерированным поселениям ходит вся фоновая
жизнь мира — набеги соседей, войны дворов между собой, выручка осаждённым,
письма, приказы лазутчика и дипломата, — и всё это выдумывает клиент. Приписать
выдуманное живому человеку нельзя: игрок прочёл бы «такой-то требует дань» о
человеке, который ничего не требовал, и потерял бы двор за стеной в набеге,
которого не было.

### Частота обращений

| Что | Как часто | Когда |
|-----|-----------|-------|
| `PUT` — своя строка | раз в 5 минут | пока идёт игра, и один раз на запуске |
| `GET` — соседи | раз в минуту | **только пока открыта карта** |

Пульс мира идёт раз в две секунды и реестра не касается вовсе: замки он читает
из памяти. Своя строка переписывается только когда есть за чем — сменилось имя,
мощь или население, либо прошло четыре минуты с прошлой отметки; чаще раза в
десять секунд не переписывается никогда. Реестр общий, и каждая лишняя запись —
это ещё одна гонка за право его переписать.

Ответ ограничен кругом в 200 клеток вокруг своего замка. Это не тайна — дальше
игрок не дотянется ни камерой, ни разведкой, — а потолок размера ответа: замки
не ближе 24 клеток друг к другу, значит в такой круг их помещается пара сотен,
сколько бы их ни было на всей карте.

Пишет только ведущая вкладка — то же правило, что и у отправки партии. Читать
может любая: чтение ни у кого ничего не меняет.

### Сервера может не быть

Реестр — не условие запуска. Список не приехал — на карте остаются замки,
которые помнит сохранение мира, и карта говорит словами, что данные старые
(старше трёх минут, то есть трёх пропущенных чтений подряд). Вне Telegram
реестра нет вовсе, и об этом сказано прямо, как и про синхронизацию партии.

Клетка своего замка лежит на устройстве и читается синхронно: мир строится
синхронно и ждать сеть в конструкторе не может. Ожидание перед постройкой мира
кончается **всегда** — разговором, отказом или сроком в девять секунд.

**Замок с карты не пропадает никогда.** Ушёл игрок, прополол реестр давние
строки, не ответила сеть — клетка, в которой замок видели своими глазами, не
имеет права снова стать пустой землёй: последнее увиденное лежит в сохранении
мира (`WorldSave.castles`).

### Реестр не растёт без предела

Строка живёт три месяца с последнего входа, всего строк не больше пяти тысяч.
Предел не от жадности: реестр едет целиком и переписывается целиком, а вечная
строка означала бы карту, заросшую замками, к которым никто не вернётся, и
каждый занимал бы свои двадцать четыре клетки.

**Сказать это надо прямо: вернувшийся через три месяца получает новую клетку, а
вместе с ней новую карту.** Деревня при этом цела — теряется разведанное.

### Чего сервер НЕ защищает

- **Мощь, население и имя — то, что игрок о себе написал.** Сервер их не
  проверяет и проверить не может. Разведка их только показывает: путь через
  снимок и его старение честен, но показывает он неподтверждённое самоописание.
  Игрок, написавший себе единицу мощи, выглядит безобидным для всякого, кто на
  него посмотрит.
- **Туман рисует клиент.** Реестр отдаётся клиенту одним куском, в пределах
  круга; правило «живьём только в обзоре» применяет игра. Переписанный клиент
  увидит весь присланный список сразу. Пока между игроками не происходит
  ничего, цена этому — знание, а не преимущество; появятся действия — правило
  придётся переносить на сервер целиком, вместе с расчётом обзора.
- **Того, что игрок был в игре**, сервер тоже не проверяет: отметку он ставит
  своими часами в момент запроса, а запрос можно послать и не играя.

### Что от этого стало связано с выкладкой

Функция теперь везёт с собой правила игры: атлас (`src/world/atlas/`), землю
(`src/world/land.ts`), расселение (`src/world/settle.ts`) и числа `SETTLE_*`.
Значит они стали такими же связанными с выкладкой, как `netlify/lib/contract.ts`:
поправил число — до перевыкладки клиент и сервер расселяют по-разному.

Отсюда же отметка земли в самом реестре (`epoch` — отпечаток атласа). Пересобрали
атлас — реестр начинается заново: координаты старой земли на новой означают не
сбой, а другое место, и замок, стоявший на 541|822, оказался бы посреди залива.

Держит эту границу тест по исходникам (`src/world/land.test.ts`): из `land.ts` и
`settle.ts` нельзя дойти до `@/`, а замыкание их импортов зафиксировано
поимённо. Нарушение проходит и тесты, и сборку игры — падает только вторая
ступень `npm run typecheck`, а на хостинге выглядит как функция, которая не
собралась.

## 5. Расхождение: сервер главнее, но копия не пропадает

Кто пишет, говорит, поверх какой записи он пишет (`baseEtag`). Легло что-то
другое — ответ 409 вместе с чужой записью целиком.

Всё правило встречи двух копий при запуске собрано в одной чистой функции —
`decide` в `src/net/sync.ts`, четыре ветки:

| Что нашли                                    | Что делаем |
|----------------------------------------------|------------|
| на сервере пусто                             | `first` — кладём свою |
| своей копии нет (чистили данные, новый телефон) | `adopt` — берём серверную молча: спорить не с чем |
| серверная — наша же предыдущая                | `continue` — играем дальше, кладём поверх |
| серверная не продолжает нашу                  | `yield` — берём серверную, свою откладываем |

Разница между двумя последними и есть всё правило. **Игра без сети расхождением
не считается**: копия выросла из той же записи и просто ушла дальше, и вечер
офлайна уезжает на сервер сам и молча. Расхождение — это когда обе копии выросли
из одной базы врозь (играли с двух устройств), и решается оно в пользу
серверной, тоже молча.

**Окна выбора нет ни в каком виде, и заводить его заново нельзя.** Вопрос при
входе — плохая первая минута, а сравнивать две партии по описи игрок всё равно
не умеет.

«Не знаю, чему наследую» — это **не** «наследую этому»: устройство, ни разу не
синхронизировавшееся, чужую партию молча не затирает. На этом стоит тест.

Уступка не теряет вторую копию: отвергнутая ложится рядом на устройство
(`tribe.sync.spare.v1`), и вернуть её можно в «Заданиях» → «Служебное» →
«Отклонённая партия». Возврат оставляет отметку наследования на месте — иначе
правило «сервер главнее» тут же отправило бы возвращённую партию обратно в
отвергнутые.

Взятая с сервера партия применяется перезапуском игры, а не подменой состояния
на ходу: партию держат стор игры, стор карты, сцена и таймеры, и заменить их
всех разом посреди кадра нечем.

## 6. Две вкладки

Сохранение одно на всё localStorage, и вкладка, не знающая о чужом ходе,
затирает его своим автосохранением. Лечится здесь именно **молча**.

Вкладки договариваются об одном: кто ведёт партию (`src/net/session.ts`).
Ведущая подновляет отметку раз в три секунды; отметка старше двенадцати секунд
считается брошенной — вкладку закрыли. Вторая вкладка **не перехватывает ведение
сама**: она показывает окно «Игра открыта дважды» и до решения игрока не пишет
ничего — ни на диск, ни на сервер, ни на выходе из игры.

Настоящей блокировки тут нет и быть не может: localStorage не умеет атомарной
проверки-и-записи. Договорённость держится на отметке времени, и этого хватает
ровно на то, ради чего заведено, — заметить вторую вкладку и спросить. На
злоумышленника это не рассчитано, и рассчитывать не надо.

Проверено не на слово: вторая вкладка через полный цикл автосохранения не
тронула ни сохранение, ни отметку ведения.

## 7. Устойчивость: сервера может не быть

**Локальное сохранение остаётся рабочей копией, сервер — местом синхронизации, а
не условием запуска.** Игра поднимается с диска и играется целиком без сети;
синхронизация начинается после того, как игра уже пошла, и ничего не ждёт.

- у каждого запроса свой срок (8 с), после которого он бросается;
- неудача возвращается значением, а не исключением: ни один забытый `catch` не
  может уронить игру;
- «функций тут нет» отличается от «сервер ответил ошибкой» по типу содержимого:
  на dev-сервере и на хостинге без функций `/api/*` отдаёт страницу игры **с
  кодом 200**, и обычная проверка `res.ok` сказала бы «всё хорошо». Ответом
  сервера считается только то, что назвалось JSON;
- игрок видит, что синхронизация не прошла: строка в профиле, словами и без
  подробностей («Нет связи с сервером. Играй дальше — сохраним, когда связь
  вернётся»). Ни модалки, ни блокировки, ни бесконечного колёсика;
- вне Telegram синхронизации нет вовсе, и об этом сказано прямо. Это не поломка:
  личности там нет, выдумывать её нельзя.

## 8. Время: одна дверь

`src/net/clock.ts` — единственное место, где игра спрашивает часы. `Date.now()`
и `new Date()` без доводов запрещены в `src/game`, `src/world`, `src/ui`,
`src/profile` и `src/battle`; держит это `clock.test.ts` чтением исходников.

Серверное «сейчас» приезжает **с любым ответом**, включая отказ, и становится
поправкой, а не разовым значением, — отдельного похода за временем игре не нужно
ни разу за партию. Не сверялись — работают часы устройства, и об этом можно
спросить (`clockSynced`).

Поправок в игре две, и складывать их в одну нельзя: `serverNow` правит часы
устройства по серверу хранения, `clockOffset` в `world/store.ts` правит часы
мира по часам мира. Обновляются они врозь, и общая начала бы дёргаться от
каждого пульса.

Сторожем это не делает никого. Игрок с переведёнными часами и без сети получит
своё устройство и ничего больше — потому что больше взять неоткуда. Ловля
читерства — отдельная работа, и делать её надо целиком.

## 9. Что лежит на устройстве

| Ключ                     | Кто пишет            | Что это |
|--------------------------|----------------------|---------|
| `tribe.save.v1`          | `game/save.ts`       | партия |
| `tribe.world.v1`         | `world/local/state.ts` | мир |
| `tribe.sync.v1`          | `net/sync.ts`        | какой серверной записи наследует эта копия |
| `tribe.sync.spare.v1`    | `net/sync.ts`        | отвергнутая при выборе партия |
| `tribe.device.v1`        | `net/session.ts`     | признак этого браузера |
| `tribe.tab.v1`           | `net/session.ts`     | кто из вкладок ведёт партию |
| `tribe.castles.v1`       | `net/roster.ts`      | **кэш** реестра: своя клетка и соседи |
| `tribe.prologue.v1`      | `prologue/save.ts`   | предыстория; к синхронизации не относится, на сервер не едет |
| `tribe.sound`            | `sound/settings.ts`  | настройка звука; к синхронизации не относится, на сервер не едет |

**Мест хранения два, и роли у них разные.** Устройство — рабочая копия: игра
запускается с неё и играется целиком без сети. Сервер — правда: он переживает
телефон, чистку данных браузера и переустановку клиента. Третьего места нет.

Строка `tribe.castles.v1` — не третье место, а именно кэш, и разница тут не в
словах. Правда о том, где стоят замки, лежит на сервере; на устройстве лежит
то, что игра успела оттуда узнать, вместе с отметкой, когда узнала. Стёрли его —
пропадёт список соседей до следующего ответа сервера, и не пропадёт ничего
больше; своё же знание о соседях (снимки и их даты) живёт в сохранении мира и к
кэшу отношения не имеет.

**Облако Telegram (CloudStorage) убрано.** Оно решало ровно одну задачу — «не
потерять прогресс при чистке браузера», — и наш сервер решает её лучше: без
предела в 4096 символов на значение, с личностью из проверенной подписи, и он
наш. Пока они стояли рядом, это была не тройная надёжность, а третий шанс
разойтись: у каждого места своя отметка времени, свои условия записи и свои
отказы. Писать в облако игра перестала совсем.

Чтение осталось — **разовым подъёмом, а не хранилищем**
(`src/telegram/cloud-rescue.ts`). Причина одна и она достаточная: у кого-то
партия может лежать только там — играли до появления сервера, потом потеряли
локальную копию (переустановка клиента, чистка данных, вытеснение хранилища
вебвью на iOS). Сделать такую партию недостижимой молча нельзя ни при каких
условиях. Устройство подъёма:

- облако спрашивают ровно тогда, когда своей копии на устройстве нет вовсе, —
  тем же условием, что стояло здесь и раньше;
- поднятое **сразу ложится на диск**, до всякого догона: второго подъёма не
  будет, потому что устройство перестало быть пустым;
- игрок узнаёт строкой в летописи — партия приехала из места, о котором он не
  просил, и молчать об этом нельзя;
- если серверная партия тоже есть, живых копий становится две, и разбирает их
  обычное правило расхождения (`decide`) — молча, а отвергнутая копия ложится в
  `spare`;
- записи нет и **быть не может**: `setItem` убран из типа облака в
  `telegram/webapp.ts`, так что `cloudSet` не возвращается правкой одной
  строки — это ошибка компиляции.

Удалять подъём — когда он перестанет что-либо возвращать. Со стороны кода это
не проверить: данные лежат у игроков. Значит сносить его надо решением
владельца, а не по календарю.

Держит всё это `src/telegram/cloud.test.ts`, и держит **с двух сторон**: со
стороны кода — во всём дереве не осталось ни вызова, ни спящей ветки к облаку,
кроме одной двери; со стороны двери — она не мёртвый код: её зовут, зовут ровно
из `loadGame`, и она делает то, ради чего оставлена. Одной половины мало: замок,
который никто не открывает, от замка, который никто не проверял, по исходнику
не отличить.

Этот шаг формата сохранения племени не менял: миграции под сервер не
понадобилось. **Сохранение мира — менялось:** `WORLD_SAVE_VERSION` поднялся до восьмёрки,
и нижняя граница равна ей. Причина ровно та же, по какой было нечего приводить у
семёрки, только про другое: дом ставит теперь реестр, а у старого сохранения он
найден поиском по сиду. Принять его клетку значило бы дать клиенту выбирать себе
место, то есть выбирать себе соседей; оставить её — оставить карту, весь туман
которой относится к чужой округе. Мир поэтому собирается заново, а версия и есть
объявление об этом.

Есть один случай, когда карта пропадает не от версии: партия шла без сервера
(вне Telegram, без сети, на хостинге без функций) и встала там, куда её поставило
правило расселения само, — а потом реестр назвал другую клетку. Молча это не
делается: игрок узнаёт строкой в летописи.

## 10. Как проверить

- `npm test` — тесты слоя: подпись и её подделка, свежесть, разбор тела, правило
  встречи двух копий, ведение между вкладками, замки серверной части, подъём
  партии из облака Telegram и двусторонняя проверка того, что от облака как от
  хранилища не осталось ничего. Про реестр отдельно: `netlify/lib/roster.test.ts`
  (чужую строку не тронуть, стоящий замок не двигается, координат из тела не
  принимают), `src/net/roster.test.ts` (сервера нет — игра идёт),
  `src/world/castles.test.ts` (чужой замок вне обзора не выдаёт ни имени, ни
  мощи) и `src/world/settle.test.ts` (проходимая земля и досягаемый сосед);
- `npm run settle:report` — расселение в настоящем мире: сколько идти до соседа
  при 2, 5, 20 и 50 игроках;
- `npm run typecheck` — включает и функции: они лежат вне `src`, своим проектом
  (`netlify/tsconfig.json`), и без этой ступени уезжали бы на хостинг
  непроверенными — их собирает esbuild, а он типов не смотрит;
- `npm run build` — та же ступень стоит и в релизной сборке;
- после выкладки: `https://<адрес>/api/time` отдаёт `{"now":…}`; в игре
  «Профиль» → строка состояния говорит, что прогресс сохранён на сервере;
- проверка «с другого устройства»: открыть игру, дождаться этой строки, потом
  открыть под тем же Telegram на другом телефоне — партия должна приехать;
- после выкладки: `https://<адрес>/api/castles` без подписи обязан отдать
  `{"error":"unauthorized"}` с кодом 401 и типом `application/json`. Вернулась
  страница игры с кодом 200 — функции не подхватились;
- проверка «двое видят друг друга»: открыть игру под двумя разными аккаунтами
  Telegram, дождаться в обоих строки о сохранении, потом открыть карту и отвести
  разведчика в сторону соседа. Замок обязан появиться на карте, а мощь — **не**
  появиться, пока в клетке никто не стоит живым обзором.
