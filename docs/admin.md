# Инструменты для теста с игроками: админка в боте, «Сообщить об ошибке», статистика

Рабочий документ ветки `game/admin` (06.10.2026). Задание владельца: админ-команды в боте только для
`ADMIN_IDS`, указ «прибавить/убавить ресурс и войско» записью в журнале игрока, заморозка аккаунта, журнал
админа; кнопка «Сообщить об ошибке» с автоматическим контекстом; статистика по игрокам, журнал действий
города, флаги подозрительного, `/stats` файлом CSV, `/player`, `/flags`.

**Ядро.** Ветка правит ядро: `netlify/lib/contract.ts` (договор), `netlify/lib/kv.ts` (имена хранилищ),
`netlify/lib/routes/*` (сохранение, война, бот, новый адрес отчёта), `netlify/lib/initdata.ts` (имя
пользователя из подписи), `netlify/lib/deliver.ts` (заморозка в ходе войны), `src/net/` (синхронизация, указы,
опись), `src/game/types.ts` и `state.ts` (необязательное поле партии и два счётчика), новая дверь
`src/game/sim/admin.ts`, счёт промыслов в `src/game/sim/minigames.ts`. Сохранение версию не поднимает: новые поля
необязательные или мержатся поверх умолчаний.

## Что владельцу вписать

1. **`ADMIN_IDS`** — ваш идентификатор Telegram (число). Узнать свой: написать любое сообщение боту
   [@userinfobot](https://t.me/userinfobot) — он ответит `Id: 123456789`. Несколько админов — через запятую:
   `ADMIN_IDS=123456789,987654321`.
   - **Netlify:** Site configuration → Environment variables → Add variable → `ADMIN_IDS`, затем новый деплой
     (переменные доходят до функций только со сборкой).
   - **Свой сервер:** строка `ADMIN_IDS=…` в `.env` рядом с `docker-compose.yml` (образец — `.env.example`), затем
     `docker compose up -d`.
2. **Вебхук бота уже должен стоять** — он же принимает кнопки уведомлений (docs/NOTIFY.md, раздел 12;
   `TELEGRAM_WEBHOOK_SECRET`). Команды админа приходят тем же вебхуком; новых настроек в @BotFather не нужно.
   Если бот не отвечает на `/help` — проверить, что `setWebhook` указывает на `…/api/bot` и что Telegram шлёт
   ему `message` (по умолчанию шлёт все виды обновлений; если при `setWebhook` задавали `allowed_updates`, в нём
   должен быть `message`).
3. Необязательно: в @BotFather → Edit Bot → Edit Commands можно вписать список ниже — тогда команды подсказываются
   при наборе `/`. Игроки их тоже увидят, но бот ответит только админу.

## Команды бота (только `ADMIN_IDS`, в личном чате с ботом)

`<кто>` — номер Telegram (`123456789`), имя пользователя (`@ivan_99`) или имя города (целиком или частью).
Город с пробелом в имени в `/give` и `/freeze` называйте номером.

| Команда | Что делает | Пример |
| --- | --- | --- |
| `/help` | список команд (и ответ на любой другой текст) | `/help` |
| `/find <кто>` | найти игроков: город, номер, имя, ратуша, жители, когда был | `/find Новг` |
| `/player <кто>` | всё об игроке: вождь, заходы, время в игре, склад, войско, бои, промыслы, версия, заморозка, указы, флаги, журнал города | `/player @ivan_99` |
| `/give <кто> <что> <число> …` | указ: прибавить ресурс или бойцов, с минусом — убавить; пар сколько угодно | `/give 123456789 дерево 500 копейщики -10 золото 200` |
| `/freeze <кто> [причина]` | заморозить | `/freeze 123456789 золото из ниоткуда` |
| `/unfreeze <кто>` | разморозить | `/unfreeze 123456789` |
| `/frozen` | кто заморожен | `/frozen` |
| `/payments` | последние 20 заказов алмазов за USDT: минута, игрок, номер, набор, статус (создан, ждёт перевода, оплачен, начислено, истёк), начало хеша перевода, причина отказа. Первая строка — сеть и кошелёк оплаты или почему оплата выключена. Только чтение — ни начислить, ни поменять статус нельзя (docs/payments.md) | `/payments` |
| `/gems <кто>` | алмазы игрока: баланс, лавка за сегодня, ускорено по постройкам, последние 25 операций журнала. Только чтение — начислить нельзя (docs/gems.md) | `/gems 123456789` |
| `/log [сколько]` | журнал админа: кто, когда, кому, что (по умолчанию 20, не больше 50) | `/log 50` |
| `/stats` | файл CSV по всем игрокам — строка на игрока | `/stats` |
| `/flags` | подозрительные игроки, свежие сверху | `/flags` |
| `/reports` | десять последних отчётов об ошибках | `/reports` |
| `/report <номер>` | отчёт целиком: текст, версия, устройство, экран, сцена, события | `/report mg1abc2d-4567` |
| `/spawns` | тест с игроками: двенадцать мест на Сицилии — кто какое занял, кто встал вне мест; режим и эпоха мира (docs/test_world.md) | `/spawns` |
| `/wipeworld ДА` | чистый старт: стереть все партии, реестр замков, войну, уведомления, журналы городов, отчёты, статистику и указы; эпоха мира +1. Без «ДА» — объяснение. Остаются заморозка и журнал админа (docs/test_world.md) | `/wipeworld ДА` |

Что можно в `/give`: древесина (дерево), камень, еда, шкуры, кости, медь, железо, золото; бойцы — дубинщики,
копейщики, лучники, топорники, мечники, щитоносцы, всадники, латные (латные всадники), латники. Падежи понимаются
(«копейщиков», «камня»), латинские ключи тоже (`wood`, `spearman`). **Алмазы указом не меняются.**

Время в ответах бота — московское.

## Как проверить

1. Вписать `ADMIN_IDS`, выложить сборку. Написать боту `/help` со своего аккаунта — пришёл список; с чужого — тишина.
2. Открыть игру из Telegram, поиграть минуту (игра пишет на сервер раз в минуту). `/find` своего города, `/player` —
   видны числа, «Записи партии: последняя №…».
3. `/give <свой номер> дерево 100 копейщики 2`. Через минуту в игре: склад +100 (не сверх вместимости), +2 копейщика,
   в летописи «Указ админа №1: …». Перезапуск игры указ второй раз не применяет.
4. `/freeze <свой номер>` — через минуту поверх игры плашка «Аккаунт заморожен», касания не проходят; поход на этот
   город со второго аккаунта отказывает «Этот город сейчас закрыт для войны». `/unfreeze` — плашка уходит со
   следующей записью (до минуты).
5. В игре: меню державы → значок 🐞 в шапке (или Профиль → «Сообщить об ошибке»), написать текст, «Отправить». Админу
   приходит короткое сообщение с `/report <номер>`; `/report` показывает всё. Шестой отчёт за час — отказ «слишком
   много отчётов».
6. `/stats` — бот присылает `tribe-stats-….csv`; открывается двойным щелчком в Excel (русском) и импортом в Google
   Таблицы (разделитель — точка с запятой, распознаётся сам).
7. `/log` — все действия выше строками.

Тесты: `netlify/lib/admin.test.ts` (чужой id не проходит и ничего не трогает; указ номером, без алмазов; заморозка
закрывает запись и войну; отчёт ложится, доходит, поток режется; флаги из правил; CSV), `src/net/admin.test.ts`
(указ ложится ровно один раз, по правилам склада; виды указа те же, что у игры), замки `netlify/lib/server.test.ts`
(админ проверяется до хранилища; команды партий не пишут; кто пишет хранилище админки; читатели записей).

## Устройство (решения строкой, правило 19)

- **Сервер по-прежнему не разбирает сохранение.** Числа для статистики и флагов клиент кладёт рядом с партией
  описью наблюдения (`SaveRecord.watch`, тип `WatchCard`) — так же, как `SaveCard`, теми же функциями игры, что
  интерфейс (`src/net/snapshot.watchOf`). Сервер читает только опись. Обоснование: правило 1 проекта и замок
  `server.test.ts` «сервер разбирает ровно названные записи» — расширен вслух в третий раз.
- **Указ админа — запись в журнале игрока на сервере, а не правка сохранения.** Хранилище `tribe-admin`, ключ
  `grants/tg-<id>`: номер по порядку, минута, кто, что (`AdminGrant`). Клиент получает указы в ответе на чтение и
  запись партии (`admin` в ответах `/api/save`) и применяет дверью `sim/admin.applyGrants` ровно один раз: партия
  помнит номер последнего применённого (`GameState.adminSeen`), применяются только старшие номера по порядку.
  Обоснование: сервер, переписавший запись партии, сменил бы ETag, и следующая запись клиента ушла бы в 409 и в
  «партию продолжили на другом устройстве»; номер вместо списка — потому что список можно обрезать
  (`GRANTS_KEEP` = 50), а номер не теряет ничего.
- **Алмазов в указе нет и быть не может.** Указ знает только виды `STOCK_KEYS` (семь припасов и золото) и
  `TROOP_KEYS` (бойцы); разбор (`readDeltas`) отбрасывает всё прочее, а клиентский тест сверяет списки с игрой. Алмазы
  с 09.10.2026 живут на сервере своей книгой (docs/gems.md); начисление у них одно — `netlify/lib/gems.creditGems`
  (стартовые эпохи, потом покупка), и команда `/gems` его не зовёт — только читает (`server.test.ts`).
- **Прибавка на склад — по правилу склада:** сверх вместимости не ложится (как возврат цены `sim/pay`), убавка — не
  ниже нуля; бойцов не меньше, чем их в походе (`s.away`); золото — в казну без потолка. Летопись говорит, что легло.
- **Заморозка — одна запись на всех** (`tribe-admin`, ключ `frozen`), читается строго. Замороженный: запись партии —
  423 `frozen` с запиской; приказ войны — отказ словами; на его город поход не уходит, а войско, пришедшее к нему
  (и в ходе войны у обработчика, и в проходе доставки), поворачивает, как к городу, ушедшему из игры (конец `gone`).
  Клиент на 423 и на `admin.frozen` показывает спокойную плашку поверх игры, которая забирает касания. Запись идёт
  раз в минуту и дальше — так приезжает и разморозка. Реестр замков (`/api/castles`) и уведомления не закрыты:
  это показ, а не ход.
- **Админ — только `ADMIN_IDS`.** Проверка (`commands.adminCommand`) — раньше любого похода в хранилище, только
  личный чат с ботом и только от того, кто пишет. Всем остальным — 200 и тишина, как на любое чужое обновление.
  Подлинность обновления — тот же секрет вебхука (`TELEGRAM_WEBHOOK_SECRET`), что у кнопок уведомлений.
- **Отчёт об ошибке** — `/api/report`, личность из подписи. Хранилище `tribe-reports`, ключ — номер
  (`<минута в 36-ричной>-<хвост номера игрока>`). Поток — не больше `REPORT_LIMITS.perHour` = 5 в час с игрока: счёт
  лежит в наблюдении игрока и переживает смерть экземпляра функции (5 — моё число: живой человек чаще не пишет).
  Админам приходит коротко (первые 300 знаков) с командой «подробнее». Место под снимок экрана — поле
  `ReportPut.shot` в договоре; сейчас сервер его не принимает.
- **Наблюдение** — `tribe-watch`, ключ `tg-<id>`: когда пришёл, последний запрос, заходы (перерыв дольше трёх
  записей подряд, `3 × SAVE_PUSH_MS`, — новый заход), время в игре (сумма промежутков внутри захода), записи,
  последняя опись, походы на игроков, журнал города (150 строк: заходы, записи захода одной строкой, разовые дела,
  промыслы, походы, отчёты, указы, заморозка, флаги) и флаги (50). Пишется попутно (`watch.observe`): ошибка
  хранилища наблюдения не роняет запрос игрока.
- **Храним только нужное:** номер Telegram, имя пользователя (из подписи), имя города, имя вождя и числа партии.
  Ни имени и фамилии из Telegram, ни телефона, ни фото.
- **CSV:** разделитель — точка с запятой, в начале BOM (UTF-8) — русский Excel открывает файл двойным щелчком с
  кириллицей и колонками; Google Таблицы распознают разделитель сами. Числа целые — десятичной запятой не нужно.
- **`SAVE_PUSH_MS` и `SAVE_HURRY_MS`** переехали в договор: их читают обе стороны (игра пишет, сервер считает заходы
  и «чаще, чем пишет игра»). `sync.PUSH_MS`/`HURRY_MS` — те же числа.
- **Версия игры** — ступень сохранения и имя входного куска сборки (в нём хеш): `сохр. 21 · index-abc123.js`. Своей
  константы сборки не заводил — в `vite.config.ts` правка тронула бы замыкание всех отчётов.

## Флаги подозрительного

Флаг — подсказка админу с пояснением «что и насколько», а не приговор: партию он не трогает. Тот же вид флага за
час не дописывается, а считается в прежний (`×N`). Выведены из правил игры; где своё число — сказано.

| Флаг | Когда | Откуда предел |
| --- | --- | --- |
| коды проверки | партия помечена `cheated` | `GameState.cheated` |
| скорость проверки | часы партии впереди настоящих | `GameState.lead` |
| часы устройства | часы телефона расходятся с серверными больше 5 мин | `initdata.CLOCK_SKEW_SECONDS` |
| сверх склада | припаса больше вместимости склада | выработка, добыча, возврат, указ — все кладут не сверх `storageCap`; ложный — если склад потерял уровень событием |
| время партии | игровое время ушло дальше, чем позволяют настоящие часы с опережением и допуском | `pace.gameDaysOfMs` (×30) |
| рост склада | между двумя записями без разовых дел припас вырос больше выработки × время × 2 | `productionPerDay`, налог и вера для золота; запас ×2 — моё число: выработка меняется внутри промежутка |
| рост войска | без разовых дел войско с ранеными выросло больше, чем казармы и конюшня выучат × 2 | `recruitRate`, работа вида |
| частые промыслы | промыслов больше, чем позволяла энергия (полный запас + приток за время) | `ENERGY_MAX`, `ENERGY_REFILL`, `MINIGAME_COST` |
| добыча промыслов | добыча промыслов больше потолка × число игр | `minigameCap` |
| частые записи | три отказа «слишком часто» за час | игра пишет не чаще раза в `SAVE_HURRY_MS`; 3 — моё число (перезапуск сразу после записи даёт один честный отказ) |
| откат партии | счётчик разовых дел уменьшился | другое устройство, восстановленная копия или правка сохранения |
| войско сверх подтверждённого | опись заявила войско с ранеными больше книги войска сервера (сверх 2 тел), не считая павших в боях, о которых клиент ещё не знает; или приказ войны просил больше подтверждённого — приказ отклонён | книга войска: обучение казарм и конюшни подтверждённых уровней за серверное время, указы, потери войны (docs/pvp.md, раздел 6) |
| стройка сверх подтверждённой | уровни построек в описи выше, чем объясняет труд стройки: не хватает больше получаса потолка стройки (`town.BUILT_FLAG_MS`) | книга стройки: потолок скорости стройки подтверждённых жителей и уровней за серверное время ×2, даровые пять минут на уровень, вести, уровни, ускоренные за алмазы (docs/pvp.md, раздел 7) |
| жители сверх подтверждённых | жителей в описи больше книги жителей сверх 3 (или 2 %) | книга жителей: прирост не выше жилья, толпы вестей по почте, вернувшиеся из войска и из очереди, уведённые лазутчиком (docs/pvp.md, раздел 7) |

«Разовые дела» — счётчик описи `deeds`: события, бои, разведки, набеги, замки, логова, покупки, ежедневки, промыслы,
указы. Рост склада и войска сверяется только между описями, где дел не было, никто не ушёл и не вернулся из похода
(`away`) и не изменилось число караванов в пути (`caravans`): иначе рост объяснён. Известный источник ложного флага —
событие, которое кладёт добро, не проходя через почту (не нашёл таких, но не перебирал все).

## Чего нет

- Снимка экрана в отчёте — место оставлено (`ReportPut.shot`).
- Отдельного журнала действий в игре по каждому клику: сервер видит то, что до него доходит, — записи партии (раз в
  минуту), походы войны, промыслы и дела по разнице описей, отчёты, указы и заморозку.
- Боёв с игроками по отдельности: `/player` показывает победы и поражения партии (с логовами и с игроками вместе) и
  число походов на игроков; подробности войны — в записи войн, которую пока смотрит только `/api/war`.
- Поиск идёт перебором записей наблюдения: на десятках и сотнях игроков — секунды; на тысячах понадобится индекс.
